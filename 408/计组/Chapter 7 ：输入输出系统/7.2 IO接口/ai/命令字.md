### 结论

在 I/O 系统中，**命令字（Command Word）**是 CPU 为了控制外部设备执行特定动作（如“启动”、“停止”、“复位”等），而向 I/O 接口发送的一段包含具体控制逻辑的二进制编码。 它本质上是 CPU 向 I/O 控制逻辑下达的“高级宏观任务指令”。

---

### 关键点

1. **存放位置** 命令字被 CPU 发送并暂存于 I/O 接口内部的**控制寄存器**（即控制端口）中。由于它是 CPU 单向用于下达指令的，因此该端口对 CPU 而言**仅支持写操作**。
2. **传输通路（核心考点）** 虽然命令字起着“控制”的作用，但在系统总线上传输时，它和普通的打印数据一样，是依靠**数据总线**传送到 I/O 接口的。
3. **解析与执行机制** 外部设备的纯硬件（如机械马达、打印喷头）无法直接识别这串二进制命令字。命令字必须由 I/O 接口内部的**控制逻辑电路进行译码**，将其“翻译”并转换为能直接驱动外设动作的底层物理时序信号（如控制电平脉冲）。

---

### 易错点 / 易混点

⚠️ **这是 408 I/O 章节极易挖坑的概念辨析：**

- ❌ **常见陷阱：认为命令字是通过“控制总线”传输的。**
    
    - ✅ **408 纠正**：**大错特错！** 控制总线上只跑极其简单的电平脉冲（如单纯的 `Read` 或 `Write` 信号），它无法承载复杂的逻辑指令。CPU 发出的具有复杂含义的“命令字”，本质上是一种特殊的数据，**必须走数据总线**。
- **高频概念辨析：命令字 vs 状态字**
    

| 维度           | 命令字 (Command Word)           | 状态字 (Status Word)            |
| :----------- | :--------------------------- | :--------------------------- |
| **传输方向**     | **CPU $\rightarrow$ I/O 接口** | **I/O 接口 $\rightarrow$ CPU** |
| **存放位置**     | 控制寄存器（控制端口）                  | 状态寄存器（状态端口）                  |
| **CPU 访问权限** | **仅支持写操作** (Write-only)      | **仅支持读操作** (Read-only)       |
| **核心作用**     | CPU 用于“下达具体任务”（如启动寻道）        | 接口用于向 CPU“反馈工作进度或报错”（如就绪、缺纸） |

### 💡 记忆提示

**命令字 = “装在信封里的任务清单”**

- 老板（CPU）把写有具体任务的清单（**命令字**），顺着文件传送通道（**数据总线**），塞进收发室指定的“任务接收箱”（**控制寄存器/控制端口**）。
- 老板塞清单的这个动作本身，是一个简单的“推入”（**控制总线上的 Write 信号**）。
- 收发室大爷（**I/O 控制逻辑**）拿出清单阅读理解（**译码**），然后用大喇叭对外面的快递小哥大喊发车（**发出物理控制信号驱动外设**）。
