### 结论

在程序查询方式中，所有的操作（包括地址加 1、计数器减 1 等）必须完全靠 CPU 执行指令来实现，其根本原因在于：**该方式下缺乏能独立接管系统总线和内存管理的专门硬件（如 DMA 控制器）**。 因此，数据交换的控制完全只能由 CPU 通过执行一段预先编写好的 I/O 服务程序来实现。由于外设速度极慢，CPU 必须用极高的速度反复执行相同的“轮询”指令流，导致宝贵的 CPU 时间被白白消耗在无意义的空转上。

---

### 关键点（原因深度剖析）

1. **I/O 接口硬件功能的局限性** 普通的 I/O 接口仅包含数据缓冲寄存器和状态寄存器，用来解决主机与外设的速度匹配和格式转换问题。它内部**没有**用于记录“主存存放地址”的寄存器，也**没有**硬件加法器去自动计数。因此，这些寻址和计数的逻辑必须转移给 CPU 来处理。
2. **纯软件驱动的数据通路** 因为缺乏自动硬件，每一次数据的传送都必须经历极其繁琐的“软件指令流”： CPU 需要亲自执行读取指令（`IN`）获取状态，通过算术逻辑指令（如 `INC`、`DEC`）让 ALU 完成指针“地址加 1”和“计数器减 1”的操作，再通过条件转移指令判断是否循环。**外设每准备好一个字，CPU 都要重新走一遍完整的取指、译码、执行的指令周期**。
3. **速度鸿沟引发的“踏步”（浪费时间的根源）** CPU 执行一条机器指令通常只需要几个纳秒，而机械外设（如打印机、机械硬盘）准备一个数据往往需要几毫秒甚至更久。在独占查询方式下，CPU 发出启动命令后，就会陷入死循环（踏步等待）。 在这几毫秒内，CPU 并不是在“休息”，而是在高速地、成千上万次地反复执行“读取状态 $\rightarrow$ 测试判断 $\rightarrow$ 未就绪则跳转重试”的汇编指令。**这种用高速指令流去迁就低速外设的做法，导致 CPU 利用率极低**。

### 易错点 / 易混点

⚠️ **在 408 真题中，这里极易与 CPU 状态及 DMA 方式进行综合挖坑：**

- ❌ **常见陷阱 1：认为“踏步等待”时 CPU 处于暂停或休眠状态。**
    - ✅ **408 纠正**：**大错特错！** 程序查询的“死等”是指 CPU 在**满负荷运算**，它正在疯狂执行循环程序中的状态查询指令。这不仅 100% 占用了 CPU 的算力，还在疯狂占用系统数据总线去读取接口状态。
- ❌ **常见陷阱 2：认为无论什么 I/O 方式，地址修改都由 CPU 完成。**
    - ✅ **高频对比（程序查询 vs DMA）**：
        - **程序查询方式**：修改主存地址、修改计数值等步骤，是由 CPU 内部的 ALU 执行算术指令完成的，属于**软件行为**。
        - **DMA 方式**：DMA 控制器内部自带了主存地址寄存器和长度计数器。传送时，“地址加 1”和“计数减 1”完全是由 DMA 内部的**硬件电路**自动生成的，不需要 CPU 执行任何指令干预，因此传送速度极快。

### 💡 记忆提示

**把程序查询方式想象成“没有自动化设备的全手动记账”：**

- **没有传送带（无 DMA 硬件）**：老板（CPU）只能自己当搬运工，每从车间（外设）拿回一个零件（读取数据），都得亲自走回办公室的特定货架放好。
- **软件指令 = 手动修改账本**：放好零件后，老板必须亲自翻开账本，把下一次放置的货架号改写一下（**执行地址加 1 指令**），再把剩余总任务划掉一笔（**执行计数器减 1 指令**）。
- **浪费时间（踏步等待）**：工人做零件要 1 小时，老板这 1 小时什么也不干，就站在车间门口每秒钟问一次“好了没？”（**高速循环执行查询指令**）。时间全浪费在无效的询问上了。
