### 结论

在 408 考研的底层硬件逻辑中，CPU 会在**当前机器周期（即总线周期）结束时**响应 DMA 请求。

---

### 关键点

根据资料，DMA 请求的响应机制及其背后的设计原因可以归纳为以下几点：

**1. 响应时机**

- **机制**：CPU 并非在整条机器指令执行完才检查 DMA 请求，而是在每个**机器周期（通常等同于总线周期，如取指周期、间址周期、执行周期中的访存阶段等）的末尾**去检测总线请求信号（HRQ）。
- **动作**：一旦检测到 DMA 请求，只要 CPU 允许交出总线，它就会在当前总线周期结束后，输出总线响应信号（HLDA），让出总线控制权。

**2. 原因一：为什么“不需要”等到整条指令结束？**

- **DMA 的本质**：DMA 申请的仅仅是**系统总线的使用权**，用于在主存和 I/O 设备之间搬运数据，它**不改变 CPU 内部的寄存器状态（如 PC、PSW 等）**。
- **无须保存现场**：因为不打断 CPU 当前程序的执行流，所以根本不需要像“程序中断”那样去“保存现场和恢复现场”。因此，CPU 完全没必要非得把手头一整条复杂的指令做完才让出总线。

**3. 原因二：为什么“不能”随时立即响应？**

- **保证访存的原子性**：总线周期（机器周期）是 CPU 访问主存的最小时间单位（例如一次完整的内存读或写操作）。如果 CPU 正在通过总线读写数据，DMA 突然把总线抢走，会导致 CPU 读写了一半的数据直接损坏。因此，必须等当前这个“读/写内存的动作（总线周期）”完整做完，才能安全交接。

---

### 易错点 / 易混点（⚠️ 408 极高频对比陷阱）

出题人极爱在选择题中将 **DMA 请求** 与 **中断请求** 放在一起对比挖坑，这是必须形成条件反射的绝对考点：

|维度|DMA 请求|中断（外中断）请求|
|:--|:--|:--|
|**申请目标**|申请**总线控制权**。|申请 **CPU 的处理时间**（去执行中断服务程序）。|
|**响应时机**|每个**总线周期（机器周期）结束时**。|每条**指令周期结束时**。|
|**是否保存现场**|**不需要**（仅让出总线，CPU 内部状态不变）。|**必须**（打断了程序执行流，要用栈保存断点和寄存器）。|
|**优先级**|**最高**（因为 I/O 设备的高速数据稍纵即逝，必须立刻拿走）。|低于 DMA 请求。当两者同时发生时，**CPU 优先响应 DMA 请求**。|

- ❌ **常见陷阱**：认为 DMA 响应是在指令执行结束之后。
    - ✅ **408 纠正**：只有中断才等指令结束！DMA 响应速度远快于中断，只要当前的“微观小节拍（总线周期）”一结束，总线马上就被切走。

### 💡 场景具象化（记忆提示）

**把 CPU 想象成“公司总经理”，总线想象成“公共电梯”：**

- **指令周期** = 总经理处理完一个大项目。
- **总线周期（机器周期）** = 总经理坐一次电梯下楼拿个快递。
- **中断请求（下属来汇报工作）**：下属要占用总经理的脑子（CPU时间），所以总经理必须把手头的**大项目彻底处理完（指令周期结束）**，把进度存进保险柜（保存现场），才能听他汇报。
- **DMA 请求（搬家公司来搬货）**：搬家公司不占用总经理的脑子，只占用**公共电梯（系统总线）**。所以，只要总经理**坐完当前这一趟电梯（总线周期结束）**，就可以立刻把电梯让给搬家公司用，总经理自己回办公室继续看文件（并行执行），**根本不需要等大项目做完才让电梯**。
