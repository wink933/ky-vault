基于提供的 image_a78362.jpg，DMA（直接内存访问）的工作流程主要围绕总线控制权的获取、数据的直接传输以及传输完成后的状态汇报展开。以下是结合图中具体连线的详细工作流程分析：

  

**1. 传输请求与总线接管阶段**

  

- **设备 -> DMA请求触发器：** 当外围设备准备好发送或接收数据时，向 DMAC 内部的“DMA请求触发器”发出硬件请求信号。
    
      
    
- **DMA请求触发器 -> 控制/状态逻辑：** 触发器将请求传递给“控制/状态逻辑”单元，该单元决定是否响应此请求。
    
      
    
- **控制/状态逻辑 -> CPU (HRQ线)：** DMAC 通过 HRQ（Hold Request，总线保持请求）连线向 CPU 发出信号，请求接管系统总线的控制权。
    
      
    
- **CPU -> 控制/状态逻辑 (HLDA线)：** CPU 在完成当前总线周期后，通过 HLDA（Hold Acknowledge，总线保持应答）连线向 DMAC 发出确认信号，并让出系统总线（控制线、数据线、地址线）的控制权。
    
      
    

**2. 数据传输阶段**

  

- **控制/状态逻辑 -> 控制线（系统总线）：** 获得控制权后，控制/状态逻辑向系统总线的控制线发出相应的内存读/写及外设读/写控制信号。
    
      
    
- **主存地址计数器 -> 地址线（系统总线）：** DMAC 将内部“主存地址计数器”中存放的目标内存地址输出到系统总线的地址线上，以选中对应的主存单元。
    
      
    
- **设备 <-> 数据缓冲寄存器 <-> 数据线（系统总线）：** 此时，CPU 已被旁路。数据直接通过外设与 DMAC 内的“数据缓冲寄存器”交互，并经由系统总线的“数据线”直接在设备和主存之间双向传输，无需 CPU 参与。
    
      
    

**3. 地址更新与计数阶段**

  

- **+1 逻辑连线：** 每完成一个字或字节的数据传送，DMAC 内部的逻辑会触发一次“+1”操作。
    
      
    
- **更新主存地址计数器：** “+1”信号反馈给“主存地址计数器”，使其指向主存中的下一个连续数据地址。
    
      
    
- **更新传送长度计数器：** 同时，“+1”信号反馈给“传送长度计数器”（在此图中采用加法计数溢出模式），记录已传输的数据量。
    
      
    

**4. 传输完成与中断汇报阶段**

  

- **传送长度计数器 -> 溢出信号：** 当预设的数据块全部传输完毕时，“传送长度计数器”达到最大值并产生“溢出信号”。
    
      
    
- **溢出信号 -> 中断机构：** 溢出信号触发 DMAC 内部的“中断机构”。
    
      
    
- **中断机构 -> 中断请求（系统总线）：** 中断机构通过系统总线向 CPU 发出“中断请求”信号，通知 CPU 数据块传输已全部完成。同时，DMAC 撤销 HRQ 信号，将系统总线控制权交还给 CPU。
