作为你的 **“408 计算机组成原理复习助手”**，我为你梳理 Cache 一致性问题中与“写命中”策略紧密绑定的另一组核心考点：**写分配法（Write Allocate）与非写分配法（Not-Write-Allocate）**。

在 408 考纲中，这两个概念极少单独出现，它们几乎总是与“全写法”或“回写法”捆绑在一起考察。请务必将它们作为一套组合拳来记忆。

### 结论

写分配法和非写分配法是专门用来处理 **Cache 写不命中（Write Miss，即要写的数据不在 Cache 中）** 时的两种处理策略。

- **写分配法**主打“既然不在，就先把它请进来再改”，通常与**回写法**搭配。
- **非写分配法**主打“既然不在，就直接去主存改，不让它进 Cache”，通常与**全写法**搭配。

---

### 核心概念对比表

| 维度          | 写分配法 (Write Allocate)                       | 非写分配法 (Not-Write-Allocate)            |
| :---------- | :------------------------------------------ | :------------------------------------ |
| **定义与机制**   | 当发生写不命中时，**先将主存中的块调入 Cache**，然后在 Cache 中修改。 | 当发生写不命中时，**直接将数据写入主存**，不将主存块调入 Cache。 |
| **核心区别**    | 缺失的块**会**被加载到 Cache 中。                      | 缺失的块**不会**被加载到 Cache 中。               |
| **固定搭配策略**  | 通常与 **回写法 (Write-Back)** 合用。                | 通常与 **全写法 (Write-Through)** 合用。       |
| **空间局部性利用** | 认为既然现在写了它，马上还可能读/写它所在块的其他数据，调入 Cache 收益高。   | 认为写完就不管了，没必要费力气把它搬进 Cache 占用宝贵的空间。    |

---

### 关键点：为什么会有这种“固定搭配”？

408 极度喜欢考这种底层逻辑推导，请务必理解这两种搭配的必然性：

**1. 为什么“写分配法”必须搭“回写法”？**

- **推导逻辑**：回写法的精髓在于“修改只留在 Cache 里，用脏位标记”。如果写不命中时我们不把它调入 Cache，回写法就根本无法工作。因此，必须先把它从主存搬进 Cache（写分配），然后在 Cache 里把数据改掉，并将该行的“修改位（脏位）”置为 1，等以后它被替换时再写回主存。

**2. 为什么“非写分配法”最配“全写法”？**

- **推导逻辑**：全写法的精髓是“只要修改，就必须写主存”。既然发生写缺失时，反正无论如何都要去主存写一趟，那就直接写进主存完事了。如果非要把它再调入 Cache，不仅多了一次主存到 Cache 的块读取开销，而且由于全写法的特性，Cache 里的新数据也必须同步到主存，纯属多此一举。

### ⚠️ 易错点 / 易混点

在 408 选择题和综合大题中，命题人最喜欢利用这两个维度的交叉进行挖坑：

**1. 致命陷阱：混淆“写命中”与“写不命中”的处理策略**

- **写命中（Write Hit）** 时的策略是：全写法、回写法。
- **写不命中（Write Miss）** 时的策略是：写分配法、非写分配法。
- _做题口诀：看到题目问“写命中”，找全写/回写；看到问“写缺失”，找分配/非分配。_

**2. 耗时计算陷阱（大题极易错）**

- **考点**：计算“写分配法”在写缺失时的总耗时。
- **纠错**：采用写分配法发生写缺失时，硬件必须执行**两步操作**：第一步，先把这个块从主存**读**入 Cache；第二步，CPU 再向 Cache **写入**修改。千万不要漏掉第一步“读入 Cache”的时间开销！
