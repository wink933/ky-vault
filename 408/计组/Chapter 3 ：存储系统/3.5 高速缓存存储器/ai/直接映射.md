
作为你的 **“408 计算机组成原理复习助手”**，我为你梳理了 Cache 映射方式中最基础、也是计算题中必考的核心模型——**直接映射（Direct Mapping）**。

### 结论

直接映射是一种“**强制对号入座**”的映射方式。主存中的每一个数据块，只能被存放到 Cache 中**唯一、固定**的某一行中。如果有两个主存块映射到了同一个位置，新块只能无条件覆盖旧块。

---

### 关键点

理解直接映射，必须掌握它的地址切分逻辑和底层硬件流程：

**1. 核心映射公式（取模机制）**

- **公式**：`Cache行号 = 主存块号 mod Cache总行数`。
- **硬件实现极简**：由于 Cache 的行数通常被设计为 $2^c$（即 $2$ 的整数次幂），取模运算在硬件上等价于**直接截取二进制数的低位**。因此，主存块号的低 $c$ 位，就是它对应的 Cache 行号。

**2. 核心命题模型：主存地址结构（408必考！）** 在直接映射中，CPU 发出的主存地址被硬件强制严格划分为三段：

- **主存字块标记 (Tag)**：主存块号的高位部分，用于区分到底是谁占用了这个位置。
- **Cache 行号 (Index / c位)**：主存块号的低位部分，用于快速定位到唯一的 Cache 行。
- **块内地址 (Offset / b位)**：用于在一个数据块内寻址具体的字节。

**3. 硬件访存全流程**

1. **抽**：CPU 从地址中抽出中间的“Cache行号”。
2. **定**：直接走到那一行的位置。
3. **比**：把 Cache 该行里存的 `Tag` 拿出来，与 CPU 地址高位的 `Tag` 进行对比。
4. **判**：如果 `Tag` 完全相等，**并且**该行的有效位（Valid bit）为 1，则命中！否则缺失。

**4. 替换策略**

- **根本不需要替换算法（如 LRU/FIFO 等）**！因为每个主存块能去的 Cache 位置是焊死的，一旦发生缺失需要调入新块，直接把它映射到的那个位置上的旧块**无脑覆盖**即可。

---

### ⚠️ 易错点 / 易混点

在 408 的选择题与综合大题中，命题人极其喜欢在以下特性上挖坑：

**1. 硬件成本陷阱：比较器数量**

- **考点**：直接映射需要多少个比较器？
- **真相**：**只需 1 个！** 因为它直接用“Cache行号”定位到了唯一的候选位置，所以只要对那 1 个位置的 Tag 进行 1 次相等性比较即可，硬件速度极快。

**2. 性能陷阱：极高的“冲突缺失”**

- **致命缺陷**：由于位置固定，哪怕整个 Cache 中有 99% 的行都是空的，只要 CPU 交替访问的两个主存块恰好映射到了**同一个 Cache 行**，它们就会疯狂互相覆盖，导致 Cache 命中率跌至谷底（这种现象被称为“抖动”）。

**3. 空间计算陷阱：Cache 总容量**

- 在 408 大题中如果问你“Cache 的总容量”是多少，**不仅要算数据区的容量，还要加上标记阵列（Directory）的容量！**
- 每一行的附加信息至少包含：**1位有效位 + Tag标记位**。有时题目还会要求加上一致性维护的**脏位（修改位）**或替换算法位（直接映射不需要替换位，但全相联/组相联需要）。

### 💡 推导示例（408 黄金解题模板）

请将这套**三步拆地址法**记熟，通杀所有直接映射计算题（参考资料例 3.3）：

**【题目条件】** 主存大小 256MB，Cache 数据区 8KB，块大小 64B。求直接映射的主存地址结构。

**【解题步骤】**

1. **算块内地址（Offset）**： 块大小为 64B = $2^6$B $\rightarrow$ **块内地址占 6 位**。
2. **算 Cache 行号（Index）**： Cache 一共有多少行？ 8KB / 64B = 128 行 = $2^7$ $\rightarrow$ **Cache行号占 7 位**。
3. **算 Tag（标记）**： 主存大小 256MB = $2^{28}$B $\rightarrow$ 主存总地址长 28 位。 Tag 长度 = 28 - 7（行号） - 6（块内地址） = **15 位**。

**【最终结构】** `| Tag (15位) | Cache行号 (7位) | 块内地址 (6位) |`
