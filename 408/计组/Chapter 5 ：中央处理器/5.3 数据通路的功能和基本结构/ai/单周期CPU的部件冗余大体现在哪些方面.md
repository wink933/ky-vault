### 结论

在 408 计算机组成原理中，单周期 CPU 的部件冗余大，其根本原因在于其底层设计要求：**“一条指令的所有微操作（取指、译码、执行、访存等）必须在一个时钟周期内全部并发完成。”**

因为在同一个物理瞬间（单个时钟周期内），硬件部件**无法进行“分时复用”**，所以 CPU 只能被迫采用**“空间换时间”**的策略，为同一时刻发生的不同操作配置多套功能相同的独立物理硬件。

---

### 关键点：部件冗余的具体体现

根据教材对“完整单周期数据通路”的分析，这种硬件冗余大体现在以下三个核心方面：

#### 1. 运算单元（加法器/ALU）的物理冗余

- **机制**：在单周期内，CPU 可能同时需要做“数据运算”和“计算地址”。由于部件不能被复用，单周期 CPU 必须配置**多个独立的加法器实例**。
- **具体表现**：
    - 需要一个**主 ALU** 专门负责执行阶段（EX）的指令算术/逻辑运算。
    - 需要一个**独立的专用小加法器** 专门负责取指阶段（IF）的 `PC + 4` 计算。
    - 需要**另一个独立的专用加法器** 专门负责计算转移指令（如 `beq`）的目标地址。
- _(对比：在多周期 CPU 中，上述三个动作被切分到不同节拍，只需要一个核心 ALU 就能分时包揽所有工作。)_

#### 2. 存储器的分离冗余（强制哈佛结构）

- **机制**：单周期 CPU 在执行诸如 `Load`/`Store` 指令时，同一个时钟周期内既要“取出该指令（访存取指）”，又要“读取或写入操作数（访存读写数据）”。
- **具体表现**：为了避免结构冒险（端口冲突），单周期 CPU **必须将“指令存储器”和“数据存储器”在物理上完全独立分开**（即采用哈佛结构）。两套存储器各自配备独立的地址总线和数据总线。

#### 3. 专用连线与多路选择器（MUX）的冗余

- **机制**：单周期 CPU 绝对**不能采用单总线结构**（因为单总线在一拍内只能传输一次数据）。
- **具体表现**：为了让各个部件在一拍内畅通无阻地交互数据，必须铺设极其复杂的**专用数据通路**。这就导致各部件门口必须冗余设置大量的**多路选择器（MUX）**来协调多根专线的汇聚，大幅增加了芯片面积和硬件开销。

### 易错点 / 易混点（⚠️ 408 极高频陷阱）

出题人在考察“单周期 vs 多周期”的硬件组成时，极爱在以下细节挖坑：

- ❌ **常见陷阱 1：认为单周期 CPU 因为硬件冗余大，所以它的寄存器数量比多周期 CPU 多，甚至包含了指令寄存器（IR）。**
    - ✅ **408 纠正**：**恰恰相反，这是一个极易错的反直觉考点！** 虽然单周期 CPU 的运算器和存储器严重冗余，但它**没有指令寄存器（IR）**！ 因为指令从指令存储器读出后，其电平信号在整个时钟周期内都会持续有效地直接驱动控制器和数据通路，**根本不需要用 IR 来暂存**。而多周期 CPU 因为跨越了多个时钟节拍，必须用 IR 把指令锁存住。
- ❌ **常见陷阱 2：认为单周期 CPU 硬件投入多，性能一定比多周期 CPU 好。**
    - ✅ **408 纠正**：由于必须在 1 拍内跑完最慢的指令（如 `lw`），单周期 CPU 的**时钟周期被拉得极其漫长（主频极低）**。导致其虽然单拍能干很多事，但综合运行速度、硬件利用率都远不如通过部件复用来提高主频的“多周期 CPU”。
