### 结论

**单周期 CPU** 要求所有指令都在一个时钟周期内完成（CPI恒定为1），其时钟周期长度被迫由最慢的指令决定，硬件利用率低； **多周期 CPU** 将指令执行拆分为多个节拍，不同指令耗费的时钟周期数不同（平均CPI > 1），可提高时钟频率并复用硬件资源。 **注意：** 两者在指令层面上**均属于严格的串行执行**，不支持指令级重叠（无流水线特性）。[[为什么多周期CPU可提高时钟频率并复用硬件资源]]

### 单周期 CPU vs 多周期 CPU 核心对比

| 维度               | 单周期 CPU                                                          | 多周期 CPU                                    |
| :--------------- | :--------------------------------------------------------------- | :----------------------------------------- |
| **定义**           | 为所有指令分配相同的执行时间，每条指令在1个时钟周期内完成。                                   | 根据指令类型动态分配执行周期数，一条指令需要多个时钟周期完成。            |
| **核心区别：CPI**     | **CPI = 1**（固定）。                                                 | **平均 CPI > 1**（且各指令 CPI 不同）。               |
| **核心区别：时钟周期长度**  | 取决于系统中**执行时间最长**的指令（如 Load 指令）。加入复杂指令会显著拖累整体性能。                  | 取决于最慢的**一个节拍（微操作）**的执行时间。时钟频率通常远高于单周期 CPU。 |
| **核心区别：硬件资源利用率** | 需大量专用数据通路（如独立的加法器和ALU同时存在）以实现单周期动作，硬件冗余高、部件极易空闲。                 | 允许功能部件**分时复用**（如 ALU 既算地址又算数据），资源利用率高。     |
| **联系**           | \1. 两者在指令层面上**都是串行执行**，前一条执行完才能取下一条。\2. 数据通路均包含控制器、运算器和寄存器等核心部件。 |                                            |
| **实现方式**         | 控制逻辑通常采用硬布线控制器（组合逻辑电路），一次性给出所有控制信号。                              | 控制逻辑采用硬布线（状态机）或微程序控制器，按节拍序列给出控制信号。         |
| **常见误区**         | ❌ 误以为单周期执行完一条指令，所以速度最快。✅ 实际上因为时钟周期被迫拉长，整体执行时间往往更劣。               | ❌ 误以为多周期就是流水线。✅ 多周期**不支持指令重叠**，本质仍是串行。     |
| **题目如何识别**       | 出现关键词：“CPI=1”、“时钟周期由最慢指令决定”、“各指令执行时间相同”。                         | 出现关键词：“部件复用”、“不同指令耗时不同”、“复杂指令分解为多个节拍”。     |

---

### 💡 408 核心关键点与易错提醒

1. **时钟频率与性能的博弈**： 单周期 CPU 增加一条复杂指令（例如浮点除法），会导致整个机器的时钟周期被迫变长，所有简单指令（如 ADD）也要陪着等这么长的时间，性能损失极大；而多周期 CPU 遇到复杂指令只需多分配几个节拍，不影响基本时钟频率。
2. **硬件复用陷阱**： 在单周期 CPU 中，一个功能部件在一个周期内只能使用一次（因为没有中间寄存器暂存状态）。而在多周期 CPU 中，**ALU 可以被多次复用**，这是两者在数据通路设计（单总线/多总线选择）上的核心区别考点。
3. **与流水线的辨析**： 考研极易把“多周期”和“流水线”混在一起考。记住：**多周期是在时间上细分，但空间上没有并行；流水线是时间上细分，空间上也有并行（指令重叠执行）**。
