- **章节主线** 在考研 408 中，循环队列是针对顺序队列（一维数组连续存储）的专项优化。它的核心使命是：**利用取模运算（`%`）在逻辑上将一维数组首尾相连成一个环，从而彻底解决顺序队列特有的“假溢出”问题**，同时保持入队和出队操作的 **$O(1)$** 极速时间复杂度。

---

### 核心知识框架（分点概括）

**1. 基础指针操作规则（默认 `rear` 指向队尾的下一个空闲位置）**

- **游标移动必须取模**：无论是入队（`rear` 向后跑）还是出队（`front` 向后跑），都绝对不能使用普通的 `++` 操作，必须使用取模：
    - 入队前进：`Q.rear = (Q.rear + 1) % MaxSize`。
    - 出队前进：`Q.front = (Q.front + 1) % MaxSize`。
- **队列当前长度公式（必考）**：因为是逻辑环形，`rear` 可能在 `front` 前面也可能跑到其后面，求长度万能公式为：**`(Q.rear + MaxSize - Q.front) % MaxSize`**。

**2. 队空与队满的判定冲突与三大解决方案（408 核心考点）**

- **核心矛盾**：在循环队列中，当队列全空时 `front == rear`；但当队列全满时，`rear` 绕了一圈追上 `front`，同样表现为 `front == rear`。如果不做特殊处理，机器将无法区分队空还是队满。
- **方案一：牺牲一个存储单元（最经典、最常考）**
    - **结论**：主动空出一个位置不存数据。
    - **队空**：`Q.front == Q.rear`。
    - **队满**：队尾指针的下一个位置如果是队头，就认为满了，公式为 **`(Q.rear + 1) % MaxSize == Q.front`**。
    - **代价**：数组容量为 `MaxSize`，但最多只能存 `MaxSize - 1` 个元素。
- **方案二：增设 `size` 变量**
    - **操作**：初始化 `size = 0`。入队成功 `size++`，出队成功 `size--`。
    - **判空/判满**：直接看大小，队空为 `size == 0`，队满为 `size == MaxSize`。（此方案下 `front == rear` 会同时在空和满时成立，但不作为判断依据）。
- **方案三：增设 `tag` 标志位**
    - **操作**：因为只有“入队”才可能导致队满，只有“出队”才可能导致队空。若因入队导致 `front == rear`，则设 `tag = 1`；若因出队导致 `front == rear`，则设 `tag = 0`。
    - **判空**：`front == rear && tag == 0`。
    - **判满**：`front == rear && tag == 1`。

### 🚨 高频考点与易错点辨析

- **陷阱 1：`rear` 指针初始指向引发的“公式大变异”（极其致命）**
    - **易错点**：无论题目怎么设定，无脑默写 `(rear + 1) % MaxSize == front` 作为队满条件。
    - **辨析**：上述所有公式成立的**刚性前提**是：`rear` 初始化为 0 且指向队尾的**下一个空位**（即入队时先存值，再移动指针）。
    - **考场变形**：如果题目规定 `rear` 指向**真实的队尾元素**（即入队时先移动指针，再存值），此时队满的条件（牺牲一个单元时）会变成 **`(rear + 2) % MaxSize == front`**！考场上做算法或分析题，**第一步必须看清题干对 `rear` 和 `front` 初始状态的定义，如果非默认，立刻画个 4 格的小圆环手动模拟一下边界**。
- **陷阱 2：“假溢出”与“真溢出”的概念混淆**
    - **易错点**：认为循环队列解决了溢出问题，所以它就不会发生上溢了。
    - **辨析**：**大错特错！** 循环队列解决的仅仅是**“假溢出”**（即数组前面明明有空位，但 `rear` 撞到了数组物理末尾导致无法插入）。当队列中所有的空位都被真正填满时，再强行插入依然会发生**“真溢出”**（此时应该报错或扩容）。只有链式队列才能天然规避假溢出并几乎免疫真溢出（直到内存耗尽）。
- **陷阱 3：“循环”二字带来的逻辑/物理结构误判**
    - **易混点**：看到“循环”，觉得它跟循环链表一样，属于链式存储结构。
    - **辨析**：**循环队列绝对是顺序存储结构！** 它在内存条上依然是一条笔直、连续的数组，所谓的“环”纯粹是通过算术取模（`%`）在你的代码逻辑里模拟出来的。

### 💡 复习检查清单（考场条件反射）

做选择题或大题时，请确保你能对循环队列形成以下肌肉记忆：

1. [ ] **看到“队列求元素个数”** $\rightarrow$ 默写 `(rear - front + MaxSize) % MaxSize`。
2. [ ] **看到“利用牺牲一个单元判满”** $\rightarrow$ 默写 `(rear + 1) % MaxSize == front`。
3. [ ] **看到“设置 tag 标志位判满”** $\rightarrow$ 反射出：只有**入队**动作引起的 `front == rear` 才是队满（`tag = 1`）。
4. [ ] **一旦题目中出现 `front` 和 `rear` 的各种加减** $\rightarrow$ 立刻检查代码里有没有加上 `% MaxSize`，如果直接用加减绝对错误。
