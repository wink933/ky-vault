- **结论** 共享栈本质上是顺序栈的一种**空间优化设计**。两者在底层的物理结构完全相同（均基于一维数组连续分配），且所有入栈、出栈操作的时间复杂度均保持在极速的 **$O(1)$**。核心分水岭在于：普通顺序栈独占整块数组，容易造成空间浪费或过早溢出；而共享栈通过“两端向中间生长”的巧妙机制，让两个栈共享同一块内存，极大地提升了空间利用率并降低了上溢风险。

### 关键点（核心维度对比）

| 对比维度         | 普通顺序栈                             | 共享栈                                                           |
| :----------- | :-------------------------------- | :------------------------------------------------------------ |
| **物理布局**     | 1 个栈独占 1 个一维数组，单向生长。              | **2 个栈**共同占用 1 个一维数组，两个栈底分别设在数组的两端，相向（向中间）生长。                 |
| **指针配置与初始化** | 仅有 1 个栈顶指针。通常初始化为 `top = -1`。     | 有 **2 个**栈顶指针。通常初始化为 `top0 = -1`（0号栈）和 `top1 = MaxSize`（1号栈）。 |
| **判满条件（必考）** | `top == MaxSize - 1`（以初值 -1 为例）。  | 两个栈顶指针相邻，即 **`top1 - top0 == 1`**（或 `top0 + 1 == top1`）。      |
| **空间利用率**    | 较低。一旦数据量超过设定容量直接上溢，即便内存中其他地方还有空闲。 | **极高**。两个栈的空间可以动态相互调节，只有当整个一维数组都被两个栈完全占满时才会发生上溢。              |
| **时间复杂度**    | 存取均为 **$O(1)$**。                  | 存取均为 **$O(1)$**。                                              |

### 易错点 / 易混点辨析（408 高频陷阱）

- **陷阱 1：“共享栈能提高存取效率”的幻觉**
    - **易错点**：做选择题时，看到选项说“共享栈相比普通顺序栈，不仅节省了空间，还提高了栈操作的时间效率”。
    - **辨析**：**大错特错！** 共享栈的唯一目的就是“更有效地利用存储空间，降低发生上溢的可能”。它对存取效率没有任何提升，因为普通的顺序栈存取时间本身就已经是极致的 $O(1)$ 了。
- **陷阱 2：共享栈的判满条件死记硬背**
    - **易错点**：无脑默写 `top1 - top0 == 1` 就是满。
    - **辨析**：必须高度警惕题目对**指针初始值**的定义！资料明确提示，如果题目把栈顶指针初值设为 `top0 = 0`，`top1 = n-1`，这就意味着指针指向的是“下一个可以插入的空闲位置”。此时的判满条件、甚至出入栈的加减顺序都会彻底改变（比如变成相遇即满）。考场上遇到共享栈，**第一步永远是画个数组图，标出初始状态**。

### 💡 复习检查清单（考场秒杀口诀）

在 408 考场上看到“共享栈”：

1. **“相向而行，相邻即满”**（`top0 + 1 == top1` 是最经典的满条件）。
2. **“空间动态互补，0号满了还能蹭1号的空位”**（这就是共享的最大优势）。
3. **“时间复杂度雷打不动都是 $O(1)$”**。
