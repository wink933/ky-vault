- **结论** 在 408 数据结构算法题中，参数传递时的引用符 `&` 指的是 **C++ 语言中的“引用调用（Reference passing）”**。它的核心使命是：**让函数内部的操作直接作用于外部传入的原变量实体**。如果不加 `&`（即采用 C 语言默认的“值传递”），函数内部接收到的只是原变量的一个“克隆副本”，任何对副本的修改在函数运行结束后都会随之灰飞烟灭，根本无法影响外部的原变量。

### 关键点（三大使用场景判定）

**1. 必须加 `&`：涉及“修改本体状态”的操作**

- **适用操作**：如线性表的初始化（`InitList`）、插入（`ListInsert`）、删除（`ListDelete`）等。
- **原因**：插入或删除必然会导致原表的结构发生物理改变（例如 `L.length` 加 1 或减 1，或者数组内元素被覆盖）。如果不加 `&`，你修改的仅仅是内存中临时复制出来的那一份形参 `L`，函数一结束，外部真正的线性表长度完全没变。
- **示例**：`bool ListInsert(SqList &L, int i, ElemType e)`。

**2. 必须加 `&`：充当“返回值带出结果”的通道**

- **适用操作**：出栈（`Pop`）、删除并返回元素（`ListDelete`）等。
- **原因**：C/C++ 的函数默认只能 `return` 一个值（比如用来返回操作是否成功的 `bool` 标志）。当你既需要知道操作是否成功，又需要把被删掉的元素值拿出来时，就可以在参数里塞一个带 `&` 的变量。函数内部对这个引用的赋值，外部调用者能直接接收到。
- **示例**：`bool ListDelete(SqList &L, int i, ElemType &e)`，这里的 `&e` 就是用来把被删除的元素值“拎”出函数的。

**3. 不必加 `&`：纯粹的“只读”操作**

- **适用操作**：查找操作（按值查找 `LocateElem`、按位查找 `GetElem`）、求表长（`Length`）、打印输出（`PrintList`）等。
- **原因**：这类操作仅仅是把数据拿过来“看一眼”，绝对不会修改原表的内容，也不会改变其长度。此时使用普通的“值传递”（不加 `&`）即可。
- **示例**：`int LocateElem(SqList L, ElemType e)`。

### 易错点 / 易混点辨析（408 极高频考场陷阱）

- **陷阱 1：与 C 语言中“取地址符”的混淆**
    - **易混点**：很多纯 C 语言底子的考生认为 `&` 是“取地址”，于是觉得传进来的应该是一个指针，试图在函数内部使用 `L->length`。
    - **辨析**：**大错特错！** 在函数形参定义（如 `SqList &L`）中，`&` 代表的是 **C++ 的引用**，它相当于给外部变量起了一个“别名”。在函数内部使用时，**语法上完全等同于普通变量，直接用 `L.length` 即可**，不需要像指针那样解引用（`*L`）或使用箭头（`L->`）。资料明确指出：C++ 的引用调用在 C 语言中可以通过指针实现相同效果，但在 408 手写算法时，强烈推荐使用 C++ 的 `&` 引用，可以极大简化代码书写，避免指针满天飞导致的出错。
- **陷阱 2：“伪修改”导致算法逻辑失效**
    - **易错点**：大题手写代码时，明明逻辑（循环移位、修改 length）全对，但函数签名写成了 `void ListInsert(SqList L, ...)`。
    - **后果**：致命逻辑错误！形参 `L` 只是副本，外部的表长没有增加，后续的所有遍历或判空操作全盘崩溃。凡是涉及到数据增、删、改的函数声明，**第一步先检查有没有给主角加上 `&`**。

### 💡 复习检查清单（参数传递秒杀口诀）

在 408 考场上手写代码，关于 `&` 的去留，请直接条件反射：

1. **“要改它，就加 `&`”**（增删改结构）。
2. **“要拿它当返回值，就加 `&`”**（保存被删元素/出栈元素）。
3. **“仅仅看看不乱动，不加 `&`”**（查找/遍历）。
4. **“加了 `&` 用点号（`.`），传指针才用箭头（`->`）”**。
