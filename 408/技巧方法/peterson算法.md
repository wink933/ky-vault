- **核心能力层级**：算法状态机时序推导与经典互斥模型辨析（408 经典真题原型：2010 年 408 统考第 24 题）
    
      
    

### 2. 【核心考点精析】

1. **Peterson 算法的变量定义与语义映射**：
    
      
    - 算法通过组合“双标志先修改法（`flag` 数组）”与“单标志法（`turn` 变量）”来解决双进程互斥访问：
        
          
        - `flag[i] = TRUE`：表示进程 $P_i$ **主动表达进入临界区的意愿（“我想进”）**；
            
              
            
        - `turn = j`：表示进程 $P_i$ 在表达意愿后，**谦让性地将优先使用权让给对方进程 $P_j$（“你先请”）**。
            
              
            
    - **进入临界区的等待判断条件**：
        
          
        - 进程 $P_0$ 执行 `while (flag[1] && (turn == 1));`：只有当“对方 $P_1$ 也想进入（`flag[1] == TRUE`）”且“当前轮到 $P_1$ 执行（`turn == 1`）”同时满足时，$P_0$ 才会陷入循环等待；
            
              
            
        - 进程 $P_1$ 执行 `while (flag[0] && (turn == 0));`：只有当“对方 $P_0$ 也想进入（`flag[0] == TRUE`）”且“当前轮到 $P_0$ 执行（`turn == 0`）”同时满足时，$P_1$ 才会陷入循环等待。
            
              
            
2. **互斥性证明（“能保证进程互斥进入临界区”）**：
    
      
    - 采用反证法：假设 $P_0$ 和 $P_1$ 同时进入了临界区。
        
          
        
    - 要让两进程同时跳过 `while` 循环进入临界区，必须在某一时刻同时满足：
        
          
        
        $$!(\text{flag}[1] \ \&\&\ (turn == 1)) \quad \text{与} \quad !(\text{flag}[0] \ \&\&\ (turn == 0))$$
        
    - 由于双方在进入前均已显式置位 `flag[0] = TRUE` 和 `flag[1] = TRUE`，因此两进程的跳出条件完全取决于整型变量 `turn` 的瞬时取值：
        
          
        - 若 $P_0$ 跳出循环，必须满足 $turn \neq 1 \implies turn == 0$；
            
              
            
        - 若 $P_1$ 跳出循环，必须满足 $turn \neq 0 \implies turn == 1$。
            
              
            
    - 然而，`turn` 是一个单标量全局整型变量，在物理内存中任何瞬时时刻只能存在唯一的确定取值（要么为 0，要么为 1），**绝不可能在同一时刻既等于 0 又等于 1**。
        
          
        
    - 必然是后写入 `turn` 的进程为先写入 `turn` 的进程做了谦让，导致后到达者在 `while` 处自旋阻塞，先到达者顺利进入临界区。因此，**Peterson 算法严格保证了互斥访问（Mutual Exclusion）**。
        
          
        
3. **空闲让进与有限等待验证（“不会出现饥饿现象”）**：
    
      
    - **空闲让进**：若临界区空闲且只有 $P_0$ 想进（`flag[0]=TRUE`, `flag[1]=FALSE`），此时虽然 $P_0$ 设置了 `turn=1`，但由于 `flag[1]` 为假，$P_0$ 的 `while` 循环条件立即打破，能够直接进入临界区，不会互相推诿。
        
          
        
    - **有限等待与抗饥饿**：若两进程同时发起竞争，$P_0$ 先把 `turn` 改为 1，$P_1$ 紧随其后把 `turn` 覆盖改为 0。此时 $P_0$ 检查到 `turn == 0` 成功进入临界区，而 $P_1$ 检查到 `turn == 0 && flag[0] == TRUE` 保持等待。
        
          
        
    - 当 $P_0$ 退出临界区时，会严格执行出区操作：`flag[0] = FALSE`。此时 $P_1$ 的 `while` 循环因 `flag[0]` 变为假而立刻打破，$P_1$ 必定在有限时间内得以进入临界区，**绝不会发生某个进程无限期被推迟等待的“饥饿（Starvation）”现象**。
        
          
        
    - 综上，**能保证进程互斥进入临界区，且不会出现“饥饿”现象**。本题正确答案选 **D**。
        
          
        

### 3. 【极值 / 边界与易错陷阱】

- **陷阱一：混淆“忙等（Busy Waiting）”与“饥饿（Starvation）”**。 Peterson 算法使用 `while` 循环自旋检查标志，这违反了“**让权等待**”准则（即进程不能进临界区时会消耗 CPU 忙等）。但**忙等绝不等于饥饿**！饥饿是指一个进程无限期等待而永远得不到资源；而在 Peterson 算法中，对方进程一旦出临界区，等待中的进程必然会获得进入权，因此等待时间是有界的，**绝无饥饿**。部分考生看到自旋死循环就误选 C（会出现饥饿）。
    
      
    
- **陷阱二：忽略代码语句的执行时序反转**。 如果将代码中的顺序颠倒：
    
      
    
    C
    
    ```
    turn = 1;
    flag[0] = TRUE;
    ```
    
    若此时发生进程并发交叉，便可能破坏互斥或引发死锁。Peterson 算法的精妙核心在于：**必须先表达意愿（置 flag 为 TRUE），再表达谦让（让 turn 为对方号）**；后让者必定把机会塞给先让者。
    
      
    
- **陷阱三：混淆软件互斥四种算法的缺陷**：
    
      
    - **单标志法**：违背“空闲让进”（强制交替轮流进入，若一方不想进，另一方也进不去）；
        
          
        
    - **双标志先检查法**：违背“忙则等待”（先看对方进不进，并发时可能同时跳过检查而同时进入）；
        
          
        
    - **双标志后检查法**：违背“空闲让进”与“有限等待”（先表态进，并发时双方互相等待引发死锁/饥饿）；
        
          
        
    - **Peterson 算法**：完美解决上述问题，满足互斥、空闲让进、有限等待，**唯独不满足“让权等待”**。
        
          
        

### 4. 【同源延伸与变式盲区】

- **同源变式一（对临界区互斥访问四大原则的逐条设问）**：
    
    若设问改为：“Peterson 算法满足下列哪些准则？”
    
      
    - ① 空闲让进：**满足**；
        
          
        
    - ② 忙则等待（互斥）：**满足**；
        
          
        
    - ③ 有限等待（无饥饿）：**满足**；
        
          
        
    - ④ 让权等待（无忙等）：**不满足**（因为等待进程在 `while` 处持续占用 CPU 自旋测试）。
        
          
        
- **同源变式二（将 Peterson 算法推广到 $N$ 个进程）**：
    
      
    - 若考查大于 2 个进程的纯软件互斥算法，代表算法为 **Bakery 算法（Lamport 面包店算法）**；
        
          
        
    - 面包店算法为每个排队进程分配带序号的“排队号”，号小者优先进入；号码相同时按进程标识符（PID）大小决胜，彻底消除饥饿。
        
          
        

> **解题心法**：
> 
> “双标表意后谦让，turn 取唯一斥无双；出区撤标即放行，虽有忙等无饥荒。”
