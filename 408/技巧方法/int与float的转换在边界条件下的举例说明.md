选取四组最具代表性的临界测试点，从底层二进制位的变化来剖析具体行为：

  

### 1. `int` 转 `float`：最大无损整数临界点（$2^{24}$）

IEEE 754 单精度尾数有 23 位，加上隐藏的最高位 $1$，有效位数一共是 **24 位**。因此：

  

- **$[0, 2^{24}]$ 范围内的所有连续整数** 都可以被 `float` 精确表示。
    
      
    
- 超过 $2^{24}$（即 $16{,}777{,}216$）后，浮点数开始出现“步长”，无法表示所有连续整数。
    
      
    

#### 边界对比：

- **$x = 2^{24} = 16{,}777{,}216$**：
    
      
    - 二进制：`1 0000 0000 0000 0000 0000 0000`（1 个 `1` 后接 24 个 `0`）。
        
          
        
    - 规格化为：$1.0 \times 2^{24}$。
        
          
        
    - 尾数需要记录小数点后的 24 个 `0`，因为全是 `0`，截断为 23 位后值仍然完全准确。
        
          
        
    - 结果：精确表示为 `16777216.0f`。
        
          
        
- **$x = 2^{24} + 1 = 16{,}777{,}217$**：
    
      
    - 二进制：`1 0000 0000 0000 0000 0000 0001`（有效跨度为 **25 位**）。
        
          
        
    - 规格化为：$1.000000000000000000000001 \times 2^{24}$。
        
          
        
    - 硬件尾数字段只能存储小数点后 23 位，末尾的第 24 位 `1` 被挤出。
        
          
        
    - **IEEE 754 默认舍入规则（向偶数舍入 / Round-to-even）**：
        
          
        - 被截断部分恰好为中间值（最低有效位保留位是 `0`，截断位是 `1` 且后续无更高位），舍入到最接近的偶数，即向下舍去。
            
              
            
    - **结果**：`(float)16777217` 变成了 `16777216.0f`。
        
          
        
    - **代码验证**：
        
          
        
        C
        
        ```
        int a = 16777217;
        float f = (float)a;
        printf("%d\n", a == (int)f); // 输出 0 (不等！)
        ```
        
- **$x = 2^{24} + 2 = 16{,}777{,}218$**：
    
      
    - 二进制：`1 0000 0000 0000 0000 0000 0010`。
        
          
        
    - 最低有效位是 `0`，除以 2 之后有效跨度缩减为 24 位：$1.00000000000000000000001 \times 2^{24}$。
        
          
        
    - 刚好能塞入 23 位小数中，因此它能被精确表示。
        
          
        
    - **现象**：在 $2^{24} \sim 2^{25}$ 区间内，`float` 只能精确表示偶数，所有奇数全部丢失。
        
          
        

### 2. `int` 转 `float`：32 位有符号整数最大值 `INT_MAX`

`INT_MAX` 为 $2^{31} - 1 = 2{,}147{,}483{,}647$。

  

- **二进制形式**：
    
      
    
    $$0111\ 1111\ 1111\ 1111\ 1111\ 1111\ 1111\ 1111_2 \quad (\text{共 31 位连续的 } 1)$$
    
- **规格化处理**：
    
      
    
    $$1.\underbrace{11111111111111111111111}_{23 \text{ 位全部为 1}}\ 1111111_2 \times 2^{30}$$
    
- **截断与舍入**：
    
      
    - 被挤出的末尾有 7 位全为 `1`（超过半数，必须向上进位）。
        
          
        
    - 进位操作向 23 位全为 `1` 的尾数 $+1$：
        
          
        
        $$1.111\dots1_2 + 0.000\dots1_2 = 10.000\dots0_2 = 1.0 \times 2^1$$
        
    - 尾数溢出右规，阶码 $+1$：指数从 $2^{30}$ 变为 $2^{31}$。
        
          
        
- **结果**：
    
      
    - `(float)INT_MAX` 的最终计算值变成了 $1.0 \times 2^{31} = 2{,}147{,}483{,}648.0f$。
        
          
        
    - **数值变大了**：转为浮点后不仅发生舍入，其浮点数值还直接超出了 32 位有符号整型的可表示上限。
        
          
        

### 3. `float` 转 `int`：上溢导致未定义行为（以 `INT_MAX` 转换为例）

承接上述结果，如果把刚才转换出的 `float` 转回 `int`：

  

C

```
int max_val = 2147483647;
float f = (float)max_val; // f 实际存储为 2147483648.0f
int back = (int)f;        // 越界！2147483648 > 2147483647
```

- **硬件层面表现（x86-64 汇编 `cvttss2si` 指令）**：
    
      
    - 指令试图把浮点数向零截断为 32 位补码。
        
          
        
    - 但目标数值 $2{,}147{,}483{,}648$ 在 32 位补码中无法表示（正数上限仅为 $2{,}147{,}483{,}647$）。
        
          
        
    - x86 芯片会将其判为转换溢出，写入保留的 **“整数不定值”（Integer Indefinite）**，其十六进制表示为 `0x80000000`。
        
          
        
- **运行结果**：
    
      
    - `back` 变成了 `-2147483648`（变为了负数极值 `INT_MIN`）。
        
          
        
    - 在 C/C++ 标准中，这是典型的 **Undefined Behavior (UB)**。
        
          
        

### 4. `float` 转 `int`：向零截断与极小值丢失

浮点数能表示极小的分数，但在转换为整数时，所有绝对值小于 1 的浮点数都会被直接“吃掉”。

  

- **正小数截断**：
    
      
    
    C
    
    ```
    float f1 = 0.99999994f;
    int i1 = (int)f1; // i1 = 0
    ```
    
    - 即使与 1 的差距仅在最后 1 个机器 epsilon，截断规则依然不进行四舍五入，而是强制丢弃小数，结果直接归零。
        
          
        
- **负小数截断**：
    
      
    
    C
    
    ```
    float f2 = -0.99999994f;
    int i2 = (int)f2; // i2 = 0
    ```
    
    - 向零截断（Truncate towards zero）不同于数学上的向下取整（Floor）。数学向下取整 $\lfloor -0.99 \rfloor = -1$，而向零截断直接砍掉小数位变成 `0`。
        

### 边界行为总结速查

|**测试用例**|**原始值与类型**|**转换后目标类型**|**转换后的实际数值**|**现象与底层原因**|
|---|---|---|---|---|
|**临界精度点**|`16777216` (`int`)|`float`|`16777216.0f`|**精确**（刚好占满 24 位有效位）|
|**首个丢失精度点**|`16777217` (`int`)|`float`|`16777216.0f`|**失真**（跨越 25 位，最低位被舍入丢弃）|
|**正整数极大值**|`2147483647` (`int`)|`float`|`2147483648.0f`|**向大舍入**（进位导致阶码从 $2^{30}$ 变为 $2^{31}$）|
|**反向溢出**|`2147483648.0f` (`float`)|`int`|`-2147483648` (UB)|**越界崩溃**（超出 `int` 正数上限，CPU 置为 `0x80000000`）|
|**临近 1 的小数**|`0.99999994f` (`float`)|`int`|`0`|**向零截断**（不按四舍五入，直接抹去有效小数位）|
