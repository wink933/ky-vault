在考研数据结构（408 及各校自命题）中，查找算法考查重点高度集中在**平均查找长度（ASL: Average Search Length）计算**、**动态查找树的调整与判定**、**散列表的冲突处理**以及**B/B+树的特性与分裂合并**。

  

### 一、 核心查找算法性能全景对比

| **查找算法**             | **存储结构要求**  | **最好时间** | **平均时间 (ASL)** | **最坏时间**      | **空间复杂度** | **特性与适用场景**                                |
| -------------------- | ----------- | -------- | -------------- | ------------- | --------- | ------------------------------------------ |
| **顺序查找**             | 顺序存储或链式存储   | $O(1)$   | $O(n)$         | $O(n)$        | $O(1)$    | 无序表；可使用哨兵优化边界判断；支持动态增删。                    |
| **折半查找 (二分)**        | **顺序存储且有序** | $O(1)$   | $O(\log_2 n)$  | $O(\log_2 n)$ | $O(1)$    | 仅限静态顺序表；判定树为平衡二叉树；增删代价极高。                  |
| **分块查找 (索引)**        | 块间有序、块内无序   | $O(1)$   | $O(\sqrt{n})$  | $O(\sqrt{n})$ | $O(b)$    | 索引表+主表；兼顾二分查找的高效与链式插入的灵活性。                 |
| **二叉排序树 (BST)**      | 二叉链表        | $O(1)$   | $O(\log_2 n)$  | $O(n)$        | $O(1)$    | 动态查找；性能受初始输入顺序影响，极端退化为单链表。                 |
| **平衡二叉树 (AVL)**      | 二叉链表        | $O(1)$   | $O(\log_2 n)$  | $O(\log_2 n)$ | $O(1)$    | 严格平衡（左右子树高度差 $\le 1$）；最坏情况严格对数级。           |
| **红黑树 (RBT)**        | 二叉链表        | $O(1)$   | $O(\log_2 n)$  | $O(\log_2 n)$ | $O(1)$    | 弱平衡；高度不超 $2\log_2(n+1)$；插入/删除调整旋转代价低于 AVL。 |
| **B 树 / B+ 树**       | 多路平衡树       | $O(1)$   | $O(\log_m n)$  | $O(\log_m n)$ | $O(1)$    | 专为**外存/磁盘索引**设计；树高极低（通常 3~4 层），减少 I/O 次数。  |
| **散列表 (Hash Table)** | 数组（散列地址）    | $O(1)$   | $O(1)$         | $O(n)$        | $O(m)$    | 平均 $O(1)$；性能取决于散列函数、冲突解决方式及装填因子 $\alpha$。  |

### 二、 线性表的查找与 ASL 手算规则

#### 1. 顺序查找 (Sequential Search)

- **带哨兵技巧**：将待查关键字放入 `A[0]`，循环从后往前扫描，免除每一步判断数组下标是否越界的开销。
    
      
    
- **等概率成功查找**：
    
      
    
    $$\text{ASL}_{\text{成功}} = \frac{1}{n} \sum_{i=1}^n i = \frac{n + 1}{2}$$
    
- **不成功查找**：
    
      
    - 无序表：必须比完全部元素，$\text{ASL}_{\text{失败}} = n + 1$。
        
          
        
    - **有序表（判定树）**：遇到首个大于（或小于）目标值的元素即可停下。设判定树有 $n$ 个成功节点和 $n+1$ 个失败虚拟节点（方块），$\text{ASL}_{\text{失败}} = \frac{1}{n+1} \sum (\text{失败节点深度} - 1)$。
        
          
        

#### 2. 折半查找 (Binary Search)

- **严格限制**：**必须是有序表，且必须使用顺序存储（支持 $O(1)$ 随机访问）**。链表不能进行折半查找。
    
      
    
- **判定树（判定二叉树）绘制规则**：
    
      
    - 若 $\text{mid} = \lfloor (low + high) / 2 \rfloor$，则对任意节点，其**右子树节点数 - 左子树节点数**为 $0$ 或 $1$。
        
          
        
    - 判定树是**严格的平衡二叉树**，其树高为 $h = \lceil \log_2(n + 1) \rceil$。
        
          
        
    - 比较次数最多不超过树高 $h$。
        
          
        

#### 3. 分块查找 (Blocking Search)

- **核心结构**：索引表（存储每块最大关键字及该块首地址，块间有序）+ 主表（块内元素无需有序）。
    
      
    
- **最优分块理论（选择题高频）**：
    
      
    - 设总记录数 $n$，均分为 $b$ 块，每块 $s$ 个记录（$n = b \times s$）。
        
          
        
    - 若索引表与块内均采用顺序查找：$\text{ASL} = \frac{b + 1}{2} + \frac{s + 1}{2} = \frac{s^2 + n}{2s} + 1$。
        
          
        
    - 当 **$s = \sqrt{n}$**（即块长等于块数）时，$\text{ASL}$ 取最小值 $\sqrt{n} + 1$。
        
          
        

### 三、 树形查找与平衡树专题

#### 1. 二叉排序树 (BST) 的判定与性质

- **判定标准**：一棵二叉树是 BST 的充要条件是其**中序遍历序列严格单调递增**。
    
      
    
- **平均查找长度与形态**：
    
      
    - 最好情况：形态接近完全二叉树，$\text{ASL} = O(\log_2 n)$。
        
          
        
    - 最坏情况：初始序列已基本有序，树退化为单支树，$\text{ASL} = O(n)$。
        
          
        

#### 2. 平衡二叉树 (AVL 树)

- **定义**：任一节点的平衡因子 $\text{BF} = \text{左子树高度} - \text{右子树高度} \in \{-1, 0, 1\}$。
    
      
    
- **高度与节点数递推关系**（手算必备）：
    
      
    - 高度为 $h$ 的 AVL 树所含**最少节点数**：$N_0 = 0, N_1 = 1, N_2 = 2, \dots, N_h = N_{h-1} + N_{h-2} + 1$。
        
          
        
    - 典型数值记忆：$N_1=1, N_2=2, N_3=4, N_4=7, N_5=12, N_6=20$。
        
          
        
    - _考查方式_：已知节点数求树的最大可能高度。
        
          
        

#### 3. 红黑树 (Red-Black Tree)

- **核心特征对比（与 AVL 树）**：
    
      
    - AVL 树追求严格平衡，适合**读多写少**；红黑树追求弱平衡，任意节点到叶节点的最长路径不超过最短路径的 2 倍。
        
          
        
    - 插入时两者都最多旋转 2 次；但**删除时，AVL 树可能需要 $O(\log n)$ 次旋转维持平衡，而红黑树最多只需 3 次旋转**，因此红黑树在**高频写（插入/删除）场景性能更优**。
        
          
        

### 四、 面向外部存储的多路平衡树：B 树与 B+ 树

考研对 B/B+ 树的考查重在**参数定义、节点关键字数量上下界、插入分裂与删除借位**。

  

|**对比维度**|**m 阶 B 树 (多路平衡查找树)**|**m 阶 B+ 树 (专为文件系统/数据库设计)**|
|---|---|---|
|**关键字与子树关系**|$n$ 个关键字对应 $n + 1$ 棵子树|$n$ 个关键字对应 $n$ 棵子树|
|**节点关键字数 $k$ 上下界**|根节点：$[1, m - 1]$；非根非叶节点：$[\lceil m/2 \rceil - 1, m - 1]$|根节点：$[1, m]$（若非叶）；非根非叶节点：$[\lceil m/2 \rceil, m]$|
|**叶子节点特征**|叶子节点为**外部虚拟失败节点**（不含任何信息），全都在同一层|叶子节点包含**全部关键字及对应记录指针**，且按序用链表相连|
|**内部节点功能**|内部节点直接存放记录数据/指针，找到即可终止|内部节点仅起**索引作用**，所有记录必须到叶节点获取|
|**遍历方式**|仅支持中序遍历|既可从根节点向下多路查找，也可**沿叶节点单/双向链表顺序扫描**|

#### B 树核心动态操作规则

1. **插入分裂**：新关键字总是插入在最底层非叶节点。若插入后关键字数达 $m$，则将中间位置（$\lceil m/2 \rceil$）的关键字**提升到父节点**，原节点以该位置为界分裂为左右两个兄弟节点。
    
      
    
2. **删除借位与合并**：
    
      
    - 若删除后非根节点关键字数 $< \lceil m/2 \rceil - 1$：
        
          
        - **兄弟够借**：采用“**父下来，兄上去**”原则从左或右兄弟借关键字（走父节点过渡，保持有序性）。
            
              
            
        - **兄弟不够借**：将该节点、其兄弟节点以及夹在两者中间的父节点关键字**三者合并**为一个新节点。若父节点关键字不足，则递归向上传递合并。
            
              
            

### 五、 散列表 (Hash Table) 深度辨析

- **装填因子 (Load Factor)**：
    
      
    
    $$\alpha = \frac{\text{表中记录数 } n}{\text{散列表长度 } m}$$
    
    - **散列表的平均查找长度直接取决于装填因子 $\alpha$ 和冲突处理方法，与记录总数 $n$ 无直接关联**。
        
          
        

#### 1. 常见冲突处理方法对比

- **开放定址法** ($H_i = (H(\text{key}) + d_i) \bmod m$)：
    
      
    - **线性探测法** ($d_i = 1, 2, 3, \dots, m-1$)：容易产生二次聚集（堆积）现象，即不同散列地址的记录争夺同一后继存储地址。
        
          
        
    - **平方探测法（二次探测法）** ($d_i = 1^2, -1^2, 2^2, -2^2, \dots$)：跳跃式探测，有效避免二次聚集；要求散列表长度 $m$ 必须是可以表示成 $4k + 3$ 的素数，才能保证探测到所有表项。
        
          
        
    - **伪随机探测法** ($d_i$ 为伪随机数序列)。
        
          
        
- **拉链法 (Chaining / 链地址法)**：
    
      
    - 将所有散列地址相同的记录链接在同一个单链表中。
        
          
        
    - 绝不发生二次聚集；删除操作仅需释放链表节点，无需打“删除标记”。
        
          
        

#### 2. ASL 计算避坑重点（选择题大分点）

- **$\text{ASL}_{\text{成功}}$**：分母是**实际存入的有效关键字数量 $n$**。比较次数等于从该关键字初始散列地址出发、经历探测步数到达该节点的位置编号（步数从 1 起算）。
    
      
    
- **$\text{ASL}_{\text{失败}}$**：分母是**散列函数取值域的长度（模数 $p$）**，绝不是表长 $m$。
    
      
    - _算法_：对每个可能的初始散列地址 $i \in [0, p-1]$，计算从当前地址出发探测到首个空单元（或拉链表的 NULL）所需要的比较次数，求和后再除以 $p$。
