### 2. 【核心考点精析】

1. **总线事务（Bus Transaction）的标准生命周期划分模型**
    
      
    
    一次完整的主存读或主存写总线事务，其时间开销 $T_{\text{total}}$ 在微观时序上均由以下四个基本阶段依次累加构成：
    
      
    
    $$T_{\text{total}} = T_{\text{仲裁}} + T_{\text{寻址}} + T_{\text{数据传输}} + T_{\text{撤销/结束}}$$
    
    - **申请与仲裁阶段（Arbitration）**：主设备（如 CPU、DMA 控制器）向总线仲裁器发出总线请求，获得总线使用权。若题干指明“已获得总线控制权”或“不计仲裁开销”，此阶段计为 $0$。
        
          
        
    - **寻址阶段（Addressing）**：主设备通过地址总线（或复用总线）发送目标主存单元的首地址及读/写控制命令，通常占用 **1 个时钟周期**。
        
          
        
    - **数据传输与等待阶段（Data Transfer & Wait States）**：进行实际的数据读写，是读、写事务产生时间差异的核心分水岭。
        
          
        
    - **撤销阶段（Termination）**：主设备释放总线信号，从总线撤销驱动，通常占用 $0 \sim 1$ 个周期（408 统考中若无明确说明默认忽略）。
        
          
        
2. **主存写事务（Write Transaction）的时间推导模型**
    
      
    - **硬件特征**：主设备（CPU/DMA）在发送写地址的同时或紧接着，数据就已经在本地就绪（或由 CPU 写入到总线写缓冲器 Write Buffer 中），主存仅需接收信号并执行锁存。
        
          
        
    - **非突发模式（普通传输）**：每传输一个总线宽度的数据块，都需要重新经历一次寻址：
        
          
        
        $$T_{\text{write}} = N \times (T_{\text{寻址}} + T_{\text{传单块数据}}) = N \times (1 + 1) \times T_{\text{clk}} = 2N \times T_{\text{clk}}$$
        
        其中 $N = \frac{\text{待写总数据量}}{\text{总线数据线宽度}}$ 为切片分块数。
        
          
        
    - **突发模式（猝发传输 Burst Transfer）**：仅需在开始时发送 1 次基准首地址，后续 $N$ 个连续数据块连续泵入：
        
          
        
        $$T_{\text{write\_burst}} = (1_{\text{寻址}} + N_{\text{数据}}) \times T_{\text{clk}}$$
        
        （注：若题目特别指明“主存写入内部完成延迟为 $W$ 个周期”，则需在末尾或每块后追加 $W$ 个等待周期）。
        
          
        
3. **主存读事务（Read Transaction）的时间推导模型（含存储存取延迟）**
    
      
    - **硬件特征**：主设备发出读地址后，**不能立即得到数据**。主存需要经过内部的“存取时间（Access Time）”进行行列译码、电容电荷放大感测后，才能将数据放到总线上。因此，读事务在“发地址”与“收数据”之间必然存在等待周期（Wait States）。
        
          
        
    - **非突发模式**：
        
          
        
        $$T_{\text{read}} = N \times (T_{\text{寻址}} + T_{\text{主存存取等待}} + T_{\text{总线传数据}})$$
        
    - **突发模式（以典型 SDRAM / 连续读为例）**：
        
          
        - 发送 1 个周期的起始地址；
            
              
            
        - 等待主存内部读出首个数据（等待 $k$ 个周期，即 CAS 延迟 / 存取等待周期）；
            
              
            
        - 随后连续 $N$ 个周期突发读入后续数据：
            
              
            
            $$T_{\text{read\_burst}} = (1_{\text{寻址}} + k_{\text{存取等待}} + N_{\text{数据}}) \times T_{\text{clk}}$$
            

### 3. 【极值 / 边界与易错陷阱】

- **“读”与“写”混淆忽略存取等待延时的致命陷阱**：
    
      
    - **核心差异**：写事务通常因为本地数据已备妥，可直接连续“推（Push）”上总线；而读事务必须等待主存“拉（Pull）”出数据。
        
          
        
    - **解题审查点**：审题时务必寻找题干中是否有“**主存读存取时间为 xx ns**”或“**主存需要等待 xx 个时钟周期方可提供数据**”。若有，读事务必须在地址周期后**严格插入该等待周期数**；若题目明确声明“不计内部延迟”或“数据传输占用 1 周期”，方可按理想流水计算。
        
          
        
- **复用总线 vs 独立总线的寻址周期占用**：
    
      
    - **地址/数据线复用（Multiplexed）**：地址和数据共用一组物理引脚，发送地址**必须显式占用独立的时钟周期**，绝对不能与数据重叠。
        
          
        
    - **地址线与数据线独立（Dedicated）**：如果支持总线流水重叠，在传输当前数据块的同时，地址总线可以并行预发下一个地址，可能消除后续事务的寻址周期。
        
          
        
- **单位换算与整除边界**：
    
      
    - 分块数计算公式为 $N = \lceil \frac{\text{传输位宽}}{\text{总线位宽}} \rceil$。若传输字节数不能被总线宽度整除，必须向上取整为完整传输周期数。
        
          
        
    - 频率与周期换算严谨对应：$100\text{ MHz} \leftrightarrow 10\text{ ns}$，$50\text{ MHz} \leftrightarrow 20\text{ ns}$，$133\text{ MHz} \leftrightarrow 7.5\text{ ns}$。
        
          
        

### 4. 【同源延伸与变式盲区】

- **命题变形**：
    
      
    - _变式 1（Cache 块缺失调块引发的总线事务耗时）_：
        
          
        - 题目常考：“CPU Cache 发生缺失，需要从主存调入一个 32 字节的 Cache 块，总线宽度为 32 位（4B），时钟频率 100MHz。主存首字读出需等待 3 个周期，后续字连续突发传送。求本次调块的总延迟？”
            
              
            
        - **拆解步骤**：
            
              
            1. 块内字数 $N = 32\text{B} / 4\text{B} = 8$ 次；
                
                  
                
            2. 读事务周期 $= 1(\text{首地址}) + 3(\text{等待}) + 8(\text{传输}) = 12$ 个周期；
                
                  
                
            3. 耗时 $= 12 \times 10\text{ ns} = 120\text{ ns}$。
                
                  
                
    - _变式 2（计算总线有效传输速率 vs 峰值带宽）_：
        
          
        - **理论峰值带宽**（仅看物理上限）：$\text{带宽} = \text{时钟频率} \times \text{总线位宽}$；
            
              
            
        - **有效实际传输率**（考虑事务开销）：$\text{有效率} = \frac{\text{有效载荷数据量}}{T_{\text{total}}}$。因为包含了寻址、等待等非数据周期，有效传输率必然小于峰值带宽。
            
              
            
- **解题心法**：
    
      
    
    > **“频率先翻倒数求单周（$T=1/f$），复用总线首周必传址；突发连续仅需一地址，写推数据读等取（读看等待写看推）。”**
