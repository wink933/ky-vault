**【结论】** 内存保护是存储器管理的核心功能之一，其根本目的是**确保各个并发执行的进程只能访问自身被授权的内存区域**，从而防止用户进程相互干扰，并严格防止用户进程非法破坏操作系统内核空间。为了保证系统的安全性和访存的高效性，内存保护不能仅靠操作系统软件来实现，**必须依赖操作系统与硬件机构（如 MMU）的紧密合作**。

**【关键机制】** 为实现进程独立内存空间的保护，在传统的连续分配方式中，常采用以下两种核心硬件机制：

- **策略一：上、下限寄存器法** 在 CPU 中设置一对上限寄存器和下限寄存器，分别存放该用户进程在内存中合法物理空间的上限地址和下限地址。每当 CPU 访问内存时，硬件会自动将目标物理地址与这两个寄存器的值进行比对，以判断是否越界。
- **策略二：重定位寄存器与界地址寄存器法（最常用）** 采用重定位寄存器（基址寄存器）和界地址寄存器（限长寄存器）配合实现。基址寄存器存放进程在内存中的**起始物理地址**，界地址寄存器存放进程的**逻辑地址的最大值（即程序长度）**。

其动态地址转换与保护的检查处理流程如下：

1. **发出寻址请求**：CPU 执行指令，产生目标操作数的**逻辑地址**。
2. **越界检查**：内存管理部件（MMU）的硬件将该逻辑地址与**界地址寄存器**中的值进行比较。
3. **处理越界异常**：若逻辑地址 $\ge$ 界地址寄存器的值，说明发生了越界，硬件会触发“越界异常（寻址错误）”中断，陷入内核态由操作系统接管并通常会终止该非法进程。
4. **计算物理地址**：若未越界（逻辑地址 $<$ 界地址寄存器的值），硬件将该逻辑地址加上**重定位寄存器**（基址）中的值，得出最终的**物理地址**。
5. **执行访存**：按照计算出的物理地址，顺利完成对主存的读写操作。

**【易错/易混点】**

- **软硬件分工陷阱**：408 极爱考“内存保护由谁完成”。请牢记：操作系统负责**在进程切换时（软件操作）**为该进程正确设置基址和限长寄存器的值；但是，指令执行期间每一次访存的**地址合法性校验与加法转换（硬件操作）**，出于对执行效率的极高要求，**绝对是且只能是由硬件全自动完成的**。
- **寄存器存储内容的辨析**：注意区分概念，“重定位（基址）寄存器”中装的是**物理地址**，而“界地址（限长）寄存器”中装的是**逻辑地址（通常为空间大小）**。

**【典型计算示例】** 在某个采用连续分配方式的操作系统中，假设进程 A 被加载到了内存的物理连续区间中。操作系统为其设置的硬件保护寄存器状态如下：

- 重定位寄存器（基址 Base）：`12000`（物理地址）
- 界地址寄存器（限长 Limit）：`500`（最大逻辑地址）

**场景 1：CPU 生成逻辑地址 $L = 250$**

1. **越界判断**：$L (250) < Limit (500)$，未越界，合法。
2. **地址转换**：$物理地址 = Base + L = 12000 + 250 = 12250$。
3. **结果**：硬件直接放行，成功访问物理地址 `12250`。

**场景 2：CPU 生成逻辑地址 $L = 600$**

1. **越界判断**：$L (600) > Limit (500)$，发生越界！
2. **结果**：硬件立即拦截该访存请求，并向 CPU 抛出越界异常（内部中断），当前指令被叫停，操作系统介入处理（通常为撤销进程 A 并报错）。
