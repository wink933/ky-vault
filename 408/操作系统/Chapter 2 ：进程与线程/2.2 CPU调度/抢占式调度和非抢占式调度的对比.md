你好！我是你的 **408 操作系统复习助手**。

在 408 考纲的“处理机调度”章节中，**非抢占式调度**与**抢占式调度**是决定 CPU 控制权如何流转的两大核心方式。理解它们的区别，是后续掌握 FCFS、SJF、RR 等具体调度算法底层逻辑的前提。

以下为你详细对比这两种调度方式的底层逻辑与高频考点：

### 结论

- **非抢占式调度（非剥夺方式）：** 当一个进程正在 CPU 上执行时，即使有更重要或紧迫的进程进入就绪队列，当前进程依然继续执行。只有当它**正常结束**或**主动阻塞（如请求 I/O）**时，才会让出 CPU。
- **抢占式调度（剥夺方式）：** 当一个进程正在 CPU 上执行时，若出现更高优先级的就绪进程，调度程序会**强行剥夺**当前进程的 CPU 使用权，将其分配给新到的高优先级进程。

---

### 关键机制

#### 1. 核心维度严格对比（表格化）

根据 408 命题规律，这两种调度方式在各维度的表现如下：

| **维度**   | **非抢占式调度 (Non-preemptive)** | **抢占式调度 (Preemptive)**      |
| :------- | :-------------------------- | :-------------------------- |
| **选择准则** | 进程主动交出控制权（运行结束或发生阻塞）        | 严格依据优先级高低，高优先级可强行剥夺         |
| **是否抢占** | 否                           | 是                           |
| **优点**   | 实现简单，系统上下文切换次数少，开销极小        | 提高了系统的吞吐率和响应效率，能及时处理紧急任务    |
| **缺点**   | 响应迟钝，可能导致短进程/紧急进程经历漫长的饥饿等待  | 频繁的上下文切换（保存和恢复现场）会导致较大的系统开销 |
| **适用场景** | 早期的批处理系统                    | 现代分时系统、严格的实时系统              |

#### 2. 抢占式调度的动态执行步骤

当系统采用抢占式调度时，一次典型的“抢占”过程严格遵循以下序号流转：

1. **触发抢占时机：** 一个更高优先级的进程到达（例如：因 I/O 完成被唤醒，或时间片中断触发）。
2. **调度程序评估：** 调度程序运行，对比就绪队列头部的新进程与当前正在 CPU 运行进程的优先级。
3. **分派程序介入（上下文保存）：** 若决定抢占，分派程序将当前运行进程的处理机现场信息，强制写入并保存到该进程的 **PCB** 中，并将其状态改为“就绪态”放入队列。
4. **移交控制权（上下文恢复）：** 分派程序将新进程的 PCB 现场数据装入 CPU 物理寄存器，完成控制权交接。

### 易错/易混点

针对 408 选择题中极其喜欢挖坑的系统级机制，请对以下逻辑边界保持绝对清醒：

- **陷阱 1：“非抢占式”就意味着一个进程一旦上台，就必须独占 CPU 一直运行到彻底结束吗？**
    - **辨析：绝对不是！** 非抢占式的核心是“不能被别人强行赶下来”，但它**可以自己主动下来**。如果该进程在运行中发起 I/O 请求（如读磁盘）或执行了 Block 原语陷入阻塞态，它依然会主动交出 CPU，调度程序此时也会把 CPU 分配给其他进程。
- **陷阱 2：如果在“抢占式”系统中，当前进程正在执行核心态的某些关键操作，也能被随时抢占吗？（极高频致死点！）**
    - **辨析：不能。** 即使是抢占式系统，也有绝对不能抢占的“禁区”。教材明确指出，如果在**处理中断的过程中**或**执行原子操作（如加锁、解锁原语）的过程中**，进程是绝对禁止被调度和抢占的，必须等这些底层关键动作执行完毕后才能进行抢占。
- **陷阱 3：哪些算法天然就是非抢占的？哪些是抢占的？**
    - **辨析：**
        - **先来先服务（FCFS）：** 永远是非抢占的。
        - **时间片轮转（RR）：** 天然是抢占的（时间片用完就会被时钟中断强制剥夺）。
        - **短作业优先（SJF）/ 优先级调度：** 既可以配置为非抢占式，也可以配置为抢占式（例如抢占式的 SJF 又被称为“最短剩余时间优先 SRTN”）。

### 记忆提示

- **形象类比：“餐厅就餐的霸座规则”**
    - **非抢占式（老式饭店）：** 你（进程）正在桌上吃饭（占用 CPU）。此时即使门口来了一位身价百亿的大老板（高优先级进程），老板也只能在门口干等。只有等你吃饱了抹嘴走人（**正常结束**），或者你去洗手间了（**主动阻塞**），老板才能上桌。饭店管理成本极低（**系统开销小**），但老板体验极差（**响应慢**）。
    - **抢占式（现代 VIP 会所）：** 你正在桌上吃到一半，大老板（高优先级进程）进门了。大堂经理（调度程序）立刻冲过来把你桌上的菜端走打包（**保存上下文到 PCB**），强行请你离桌回到门口排队（**变为就绪态**），然后立刻把桌子让给大老板。如果大老板吃着吃着，又来了一个更大的首富，经理会再次强行把大老板也请下去。这种方式让大人物满意（**响应效率高**），但大堂经理每天光端盘子换人就能累死（**频繁上下文切换开销大**）。
