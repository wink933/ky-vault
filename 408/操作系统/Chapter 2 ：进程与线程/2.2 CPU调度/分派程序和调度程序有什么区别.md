你好！我是你的 **408 操作系统复习助手**。

关于“分派程序（Dispatcher）”与“调度程序（Scheduler）”的区别，这是 408 考纲中“CPU 调度与上下文切换”极其经典的底层概念辨析。它完美体现了操作系统中 **“策略与机制分离”** 的核心设计哲学。

以下为你详细拆解两者的底层逻辑与协作机制：

### 结论

**调度程序（Scheduler）** 是“决策者”，负责根据特定的算法（如先来先服务、时间片轮转）决定**哪一个就绪进程**可以获得 CPU 的使用权。 **分派程序（Dispatcher，也称分派器）** 是“执行者”，负责将 CPU 的控制权**真正移交**给被调度程序选中的那个进程，完成具体的底层硬件级操作（如切换寄存器现场）。

---

### 关键机制（核心执行逻辑）

#### 1. 核心维度严格对比（表格化）

|**维度**|**调度程序 (Scheduler)**|**分派程序 (Dispatcher)**|
|:--|:--|:--|
|**核心职责**|决定 **Who**（接下来由谁运行）|决定 **How**（如何让它运行）|
|**设计定位**|策略（Policy）|机制（Mechanism）|
|**主要工作**|维护就绪队列（排队器）、计算优先级、挑选下一个目标进程|保存旧现场、恢复新现场、切换运行模式（用户态/内核态）、跳转指令|
|**运行频率**|极高（每次时钟中断或进程阻塞时运行）|极高（紧接在调度程序完成“选人”决策之后运行）|

#### 2. 动态执行协作过程（一次完整的进程切换）

当发生 CPU 切换时，调度程序和分派程序严格按以下序号步骤进行流水线协作：

1. **触发调度时机：** 发生时钟中断（时间片用完）或当前进程主动阻塞，CPU 产生内/外中断，陷入内核态。
2. **调度程序决策：** 调度程序运行，根据设定的调度算法（如 SJF、RR 等）从就绪队列中挑选出一个新进程。
3. **分派程序接管：** 调度程序将“选定新进程”的决定通知分派程序。
4. **上下文保存（分派执行）：** 分派程序（及其内部的上下文切换器）将当前被剥夺 CPU 进程的处理机现场（PC、PSW、通用寄存器等）保存到该进程的 PCB 中。
5. **上下文恢复（分派执行）：** 分派程序将新选出进程的 PCB 中保存的 CPU 现场，精准地装载到处理器的各个硬件寄存器中。
6. **态的切换与跳转（分派执行）：** 分派程序将 CPU 模式从内核态切回**用户态**，并跳转到新进程上次被中断的指令位置（PC 指针处），使其恢复执行。

### 易错/易混点

针对 408 极其喜欢挖坑的系统架构层级概念，请对以下逻辑边界保持绝对清醒：

- **陷阱 1：广义上的“调度程序”包含了“分派程序”吗？**
    - **辨析：是的。** 在 408 统考教材的语境中，用于实现 CPU 调度的完整软件组件统称为“调度程序”，它在内部通常包含三个子模块：**排队器、分派器（分派程序）和上下文切换器**。狭义的“调度”仅指“排队选人”，广义的调度软件包含了“选人 + 换人”。
- **陷阱 2：什么是“分派延迟”（Dispatch Latency）？它有何影响？**
    - **辨析：** 它是指分派程序停止一个进程并启动另一个进程所花费的全部时间。这段时间纯粹是操作系统的“额外开销（Overhead）”，CPU 此时完全在执行内核代码，没有做任何有用的用户级计算。因此，分派程序的代码必须极其精简且高效（通常全用汇编编写）。

### 记忆提示

- **形象类比：“部门经理（调度程序）与 部门秘书（分派程序）”**
    - **调度程序（经理）：** 看着大厅里排队等着干活的员工（就绪队列），根据谁的任务最急（调度算法），在纸上圈了一个名字：“接下来让张三去用全公司唯一的一台高级渲染电脑（CPU）”。
    - **分派程序（秘书）：** 经理圈好名字后，秘书负责具体的“交接动作”。秘书先把原来用电脑的李四的文件存盘（**保存旧上下文**），然后把张三叫过来坐下，帮张三输入密码登录他自己的账号（**恢复新上下文**），最后把鼠标递给张三说：“你接着干吧”（**移交 CPU 控制权，切回用户态**）。
