
### 结论

分派程序（Dispatcher，也称分派器）是操作系统 CPU 调度程序（Scheduler）的核心组件之一。它的主要职责是将通过调度程序（基于某种调度策略）所选出的进程，从就绪队列中移出，以便真正将 CPU 的控制权分配给该进程。

### 关键机制

- **组件协同：** 完整的调度程序通常由三部分组成：**排队器**（维护就绪队列）、**分派器**（移出选中进程分配 CPU）以及**上下文切换器**（负责保存和恢复 CPU 寄存器）。
- **物理动作执行者：** 调度算法只负责“选出”谁来执行，而分派程序才是实际完成“切换与控制权移交”物理动作的执行者。
- **纯系统开销：** 分派程序的运行本身需要占用 CPU 执行指令。这段用于切换和分派的时间属于系统的额外开销，系统在此期间无法推进任何用户进程。

### 分派程序的动态执行过程

在对 CPU 进行切换分配时，分派程序需要与上下文切换器密切配合，整个过程会发生**两对**上下文的切换操作：

1. **保存旧进程上下文：** 第一对切换开始，将当前正在运行的进程的上下文（CPU 现场信息）保存到该进程的 PCB 中。
2. **装入分派程序上下文：** 装入分派程序自身的上下文，使得 CPU 开始运行分派程序。
3. **执行分派动作：** 分派程序运行，将调度程序选出的新进程从就绪队列中移出。
4. **装入新进程上下文：** 第二对切换开始，移出分派程序的上下文，并将新选中进程的 CPU 现场信息装入 CPU 的各个相应寄存器，随后新进程开始执行。

### 易错/易混点

- **调度（Scheduling） vs 分派（Dispatching）（核心考点）：**
    - **调度**是“决策行为”——解决“应该让哪一个进程运行”的问题。
    - **分派**是“执行行为”——解决“如何把 CPU 交给该进程”的问题。
- **上下文切换的细节陷阱：** 在 408 考题或分析中，容易误以为进程切换只是“旧进程状态出，新进程状态入”的一次操作。实际上，系统必须先切入“分派程序”这个中间媒介来执行调度和交接动作，因此严格意义上发生了**两对**上下文切换。

### 典型计算示例

在考研计算题中，分派程序的执行时间通常被称为**分派延迟（Dispatch Latency）**或**切换开销**。 **场景描述：** 假设系统采用时间片轮转（RR）调度，时间片大小为 $q$，分派程序执行一次分派与上下文切换的耗时（分派延迟）为 $s$。

- **CPU 有效利用率公式：** $CPU 利用率 = \frac{q}{q + s}$
- **考点分析：** 每次分派程序运行的 $s$ 时间内，CPU 在做管理工作而非用户计算。如果为了追求极快的响应速度而将时间片 $q$ 设置得过小（甚至接近 $s$），将导致 CPU 利用率急剧下降，大量算力浪费在分派程序的两对上下文切换上。因此，在实际系统中，时间片的大小必须远大于分派程序的运行时间。
