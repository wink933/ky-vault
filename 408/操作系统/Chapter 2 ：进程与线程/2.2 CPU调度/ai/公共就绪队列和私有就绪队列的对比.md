你好！我是你的 **408 操作系统复习助手**。

在 408 考纲的“处理机调度”章节中，关于多处理机系统（SMP）的调度架构，**公共就绪队列**与**私有就绪队列**是两种截然相反的设计哲学。它们的本质区别在于“就绪进程是统一集中管理还是按 CPU 分散管理”，核心的博弈点是 **“负载均衡”** 与 **“处理机亲和性（Cache 命中率）”** 的取舍。

以下为你详细对比这两种队列的底层逻辑与核心考点：

### 结论

- **公共就绪队列：** 整个系统只维护一个就绪队列，所有 CPU 共享。主打**绝佳的负载均衡**，但牺牲了缓存性能。
- **私有就绪队列：** 每个 CPU 维护自己独立的就绪队列。主打**极高的处理机亲和性**，但容易出现“旱的旱死，涝的涝死”的负载不均情况。

---

### 关键机制（核心维度严格对比）

在 408 的命题视角下，这两种方案的优缺点对比如下表：

|**维度**|**公共就绪队列 (Common Ready Queue)**|**私有就绪队列 (Private Ready Queue)**|
|:--|:--|:--|
|**架构设计**|系统中仅包含**一个**公共就绪队列，所有 CPU 共享。|系统为**每个 CPU** 单独设置一个私有的就绪队列。|
|**负载均衡情况**|**天然完美**。只要有 CPU 空闲，就会立刻从公共队列中抓取进程运行，CPU 绝不会被闲置。|**极易失衡**。有的 CPU 队列塞满，有的 CPU 空闲，必须引入额外的“进程迁移”机制。|
|**处理机亲和性**|**较差**。进程可能前一次在 CPU 1 运行，下一次被分配到 CPU 2，导致它在 CPU 1 留下的 Cache 数据全部失效。|**极好**。进程被绑定在同一个 CPU 的队列中，上下文和 Cache 的命中率极高。|
|**并发同步开销**|极大。所有 CPU 去同一个队列里取进程，必须对公共队列加锁（互斥访问），极易形成性能瓶颈。|极小。每个 CPU 只访问自己的队列，不需要与其他 CPU 产生激烈的锁竞争。|
|**主要缺点**|处理机亲和性不好。|必须人为进行负载平衡干预。|

### 易错/易混点

针对 408 极其喜欢挖坑的概念边界，请对以下陷阱保持绝对清醒：

- **陷阱 1：什么是处理机亲和性（Processor Affinity）？（重要概念）**
    - **辨析：** 当一个进程在某个 CPU 上运行时，该 CPU 的高速缓存（L1/L2 Cache）和 TLB 中会累积大量关于该进程的数据。如果它中途阻塞，稍后又回到**同一个 CPU** 上运行（私有就绪队列），这些 Cache 就依然有效（命中率高），这叫作处理机亲和性好。如果它被分配到**另一个 CPU**（公共就绪队列），缓存全部白费，需要重新从内存读取，性能大打折扣。
- **陷阱 2：私有就绪队列如何解决“负载不平衡”？（极高频）**
    - **辨析：** 私有就绪队列必须配合 **“进程迁移”** 技术来维持系统的整体效率。系统提供了两种经典的迁移方案：
        1. **推迁移（Push Migration）：** 有一个专门的系统进程会周期性地巡逻，发现某个 CPU 超载了，就把该队列里的进程强制**“推”**到其他空闲 CPU 的队列里。
        2. **拉迁移（Pull Migration）：** 当某个 CPU 把自己队列里的活儿干完了（极度空闲），它会主动出击，从其他超负荷的 CPU 队列里**“拉（偷）”**一部分进程过来自己执行。

### 记忆提示

- **形象类比：“银行大厅的排队机制”**
    - **公共就绪队列（单一蛇形排队法）：** 整个大厅只拉一条长长的警戒线，所有客户排成一队。3 个柜台（CPU）谁办完上一单，就喊队伍最前面的那个人。
        - **优点：** 绝对没有柜台会闲着（负载极度均衡）。
        - **缺点：** 客户每次办理业务遇到的柜员都不一样，每次都要重新出示身份证解释一遍情况（Cache 频繁失效，亲和性差）。
    - **私有就绪队列（超市各自结账法）：** 3 个柜台前面各排一队。你固定在 1 号柜台排队。
        - **优点：** 如果你需要分多次办理业务，1 号柜员早就认识你了，连身份证都不用看，办事飞快（亲和性极高，Cache 命中）。
        - **缺点：** 如果 1 号队伍里有个大妈在存几万个硬币（严重超载），而 2 号柜台没人了，2 号柜员宁可玩手机也不会主动帮你结账（负载不平衡）。这时候就需要大堂经理强行把你从 1 号队伍调配到 2 号柜台（**推迁移/拉迁移**）。
