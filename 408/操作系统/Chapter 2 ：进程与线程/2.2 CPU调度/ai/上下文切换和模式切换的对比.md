你好！我是你的 **408 操作系统复习助手**。

在 408 考研统考中，**上下文切换（Context Switch，也称进程切换）**与**模式切换（Mode Switch，也称特权态切换）**的辨析，是第一章和第二章交界处极高频的综合陷阱题。命题人非常喜欢围绕“开销大小”、“TLB是否刷新”、“现场保存在哪”这三个维度对考生进行连环挖坑。

以下为你硬核拆解这两个核心动作的底层逻辑：

### 结论

- **模式切换** 是指 **“同一个进程”** 在执行过程中，由于发生了中断、异常或系统调用，导致 CPU 的运行模式在**用户态（目态）与内核态（管态）之间进行相互转换**。它的主体始终是当前进程，开销较小。
- **上下文切换** 是指操作系统调度程序决定剥夺当前进程的 CPU 控制权，并将 CPU **“移交给另一个全新的进程”**。它必须在内核态下完成，不仅涉及寄存器现场的彻底更换，还会引发内存地址空间的巨变，开销极大。

---

### 关键机制

#### 1. 核心维度严格对比（表格化）

在 408 命题视角下，这两个机制必须从以下物理维度进行精确对比：

| **维度**             | **模式切换 (Mode Switch)** | **上下文切换 (Context Switch / 进程切换)**       |
| :----------------- | :--------------------- | :-------------------------------------- |
| **发生的主体**          | **同一进程内部**状态的改变        | **两个不同进程（或线程）**之间的交接                    |
| **触发原因**           | 中断、异常（如缺页）、系统调用（陷入指令）  | 时间片耗尽、高优先级抢占、进程主动阻塞/终止                  |
| **处理机现场保存位置**      | 当前进程的 **内核栈**          | 旧进程的 **PCB（进程控制块）**                     |
| **内存页表基址**         | **不改变**，依然是原进程的地址空间    | **发生改变**，必须将新进程的页表首地址装入寄存器              |
| **TLB（快表）与 Cache** | 通常不受影响，保持有效            | **极其致命：必然导致 TLB 刷新（失效）和 Cache 大量命中率下降** |
| **系统开销代价**         | **较小**（仅少量寄存器入栈、出栈）    | **极大**（涉及大量状态保存及巨大的内存访存惩罚）              |

#### 2. 上下文切换的动态图景（完整步骤）

当系统发生一次完整的进程上下文切换时，它**必然包含模式切换**，其底层的动态执行步骤严格如下：

1. **保存断点与模式切换：** 当前进程由于时钟中断或系统调用被中断，CPU 硬件自动将当前的 PC、PSW 等核心断点状态压入当前进程的**内核栈**中，CPU 进入内核态。
2. **保存原进程上下文：** 操作系统的分派程序将旧进程的全部通用寄存器、栈指针等剩余硬件现场提取，并完整写入到该旧进程的 **PCB** 中。
3. **调度决策：** 调度程序运行，根据调度算法（如 RR 或 SJF）从就绪队列中挑选出一个新进程。
4. **更新页表基址（最重开销）：** 操作系统将新进程的页表起始物理地址装入页表基址寄存器（PTBR）。**这一动作会直接导致 TLB 快表中的旧进程映射失效**。
5. **恢复新进程上下文：** 分派程序从新进程的 **PCB** 中读出其上次被剥夺时保存的硬件现场，原样装入 CPU 的各个物理寄存器中。
6. **模式切换返回：** 执行中断返回指令（如 IRET），将新进程的 PC 和 PSW 恢复，CPU 模式从内核态切回**用户态**，新进程正式接管 CPU 开始运行。

### 易错/易混点

针对 408 选择题的挖坑，请对以下逻辑边界保持绝对清醒：

- **陷阱 1：发生中断就一定会导致上下文切换（进程切换）吗？（极高频！）**
    - **辨析：绝对不是！** 发生中断必然会导致**模式切换**（从用户态进入内核态处理中断），但中断处理完成后，如果当前进程的时间片没用完，且没有被更高优先级的进程抢占，系统会直接通过中断返回指令切回用户态，**继续执行原进程**。整个过程发生了两次模式切换，但**零次上下文切换**。
- **陷阱 2：上下文切换可以发生在用户态吗？**
    - **辨析：绝对不能。** 教材明确指出，上下文切换是一项核心特权操作，它涉及读写系统级数据结构（PCB）以及修改页表寄存器。因此，**上下文切换只能在内核态下进行**。
- **陷阱 3：同一个进程内的多个“内核级线程”切换，和“进程切换”开销一样大吗？**
    - **辨析：不一样。** 线程切换被称为“轻量级”上下文切换。同进程内的线程共享同一个内存地址空间。因此，线程切换只需要更换 TCB（保存寄存器现场），**不需要切换页表基址，也不会导致 TLB 和 Cache 的刷新**，开销远低于进程切换。

### 记忆提示

- **形象类比：“去财务部报销（模式切换）” vs “被公司开除换新人（上下文切换）”**
    - **模式切换：** 你（进程）在普通工位干活（**用户态**）。你想报销，于是拿着发票走进了平时不让进的财务部机要室（**陷入内核态**），把你刚写到一半的报表草稿锁在工位抽屉里（**保存到内核栈**）。报销完后，你走回自己的工位，拿出草稿继续写（**返回用户态**）。**你还是你，你的工位和资源都没变（不刷 TLB）**。
    - **上下文切换：** 你在干活时，老板（调度程序）通知你被停职了。保安冲过来把你抽屉里所有的私人物品打包放进地下室的人事绝密保险柜里（**完整保存现场到 PCB**）。然后，新招的员工李四被安排坐到了你的工位上。李四把桌面清理干净，摆上他自己的水杯和参考书（**重置页表，TLB 刷新失效**）。这个交接过程非常漫长，严重影响公司进度（**开销极大**）。
