
### 结论

上下文切换（Context Switch）是指将 CPU 的控制权从一个进程转移到另一个进程的任务过程。在这个过程中，系统需要保存当前进程的状态，并恢复另一个进程的状态。进程的上下文主要由其进程控制块（PCB）表示，包含了 CPU 寄存器的值、进程状态、内存管理信息等关键运行环境数据。

### 关键机制

- **实质性环境变化：** 在上下文切换过程中，进程的运行环境会发生实质性的变化，意味着 CPU 开始完全服务于一个新的进程实体。
- **高昂的系统开销：** 上下文切换是一项开销较大的操作，需要执行大量寄存器的保存与恢复指令。虽然单次切换通常仅为微秒量级，但在高负载系统中（每秒数百次切换），累积的切换时间会导致 CPU 有效利用率下降。
- **状态的保存与恢复：** 核心逻辑是“保存旧进程上下文至其 PCB”与“从新进程 PCB 加载上下文”。

### 上下文切换的动态执行过程

进程的上下文切换涉及一系列严密的动作，其标准的执行步骤如下：

1. **挂起当前进程：** 将当前正在运行进程的 CPU 上下文（如程序计数器、寄存器等）保存到其 PCB 中。
2. **移入对应队列：** 将该进程的 PCB 移入相应的系统队列（例如：若时间片用完则移入就绪队列；若等待 I/O 事件则移入阻塞队列）。
3. **选择新进程：** 调度程序选择另一个合适的进程准备执行，并更新其 PCB 中的相关状态信息。
4. **恢复上下文：** 从新选择进程的 PCB 中恢复其 CPU 上下文数据到物理寄存器中。
5. **跳转执行：** 跳转到新进程 PCB 中程序计数器（PC）所指向的指令位置，正式开始执行该新进程。

### 易错/易混点

- **上下文切换 vs 模式切换（非常重要）：**
    - **模式切换**（用户态和内核态之间的切换）发生在**同一进程内部**，比如进程通过系统调用请求内核服务时，只涉及执行特权级的改变，不改变进程实体，因此**不涉及上下文切换**。
    - **上下文切换**必然涉及两个不同进程之间的交替。由于调度和切换只能在内核态下完成，因此**上下文切换必然伴随模式切换**（先陷入内核态，切换进程后，再切回用户态）。
- **调度与切换的区别：** “调度”是决策行为（决定将 CPU 分配给哪个进程），而“切换”是执行行为（实际完成 CPU 控制权的物理转移）。

### 典型计算示例

在 408 考研中，单独计算上下文切换时间的题目较少，通常将其融入到 **时间片轮转（RR）调度算法的 CPU 效率计算** 中定性或定量考查。 **场景描述：** 假设系统中有 $n$ 个就绪进程，时间片大小为 $q$，单次上下文切换的系统开销时间为 $s$。

- **CPU 有效利用率公式：** $CPU 利用率 = \frac{q}{q + s}$
- **考点分析：**
    - 若时间片 $q$ 极小（如接近微秒级），则切换开销 $s$ 的占比会急剧放大，导致 CPU 把大量时间浪费在上下文切换上，系统吞吐量骤降。
    - 为了保证系统的执行效率，通常要求时间片 $q$ 必须远大于上下文切换时间 $s$（例如至少大一个数量级），以此来摊薄上下文切换带来的性能损耗。
