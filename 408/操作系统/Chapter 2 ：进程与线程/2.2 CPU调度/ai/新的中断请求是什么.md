### 结论

“新的中断请求”本质上是指**来自 CPU 外部硬件设备发送给 CPU 的异步电信号（即外中断，Interrupt）**，用于通知操作系统有外部事件发生并需要立即处理。在闲逛进程的语境下，正是这些外部中断打破了系统的“空闲”状态，将原本处于阻塞态的用户进程唤醒，从而让 CPU 重新开始执行有效任务。

### 关键机制

结合 408 考纲，能唤醒闲逛进程的中断请求主要分为以下两大核心类：

- **I/O 中断（I/O Interrupt）：** 当一个进程因请求磁盘读写等 I/O 操作而进入阻塞态时，如果系统中没有其他就绪进程，CPU 就会执行闲逛进程。一旦外部设备完成 I/O 操作，设备控制器就会向 CPU 发出 I/O 中断信号。
- **时钟中断（Clock Interrupt）：** 硬件定时器定期发出的信号（如每 10ms 一次）。它是操作系统驱动调度的“心脏跳动”。即使系统完全空闲，时钟中断也会不断发生，操作系统会借此检查是否有睡眠/延时的进程已经到期需要被唤醒。

**闲逛进程被中断打断的动态执行过程：** 当闲逛进程正在死循环时，一个新中断请求到来的完整处理流程如下：

1. **检测信号：** CPU 在执行完闲逛进程的当前指令后，检测到中断引脚上的有效信号。
2. **硬件隐蔽指令（保存现场）：** CPU 硬件自动关中断，并将闲逛进程的程序计数器（PC）和程序状态字（PSW）等压入内核栈。
3. **查向量表：** 硬件根据中断号查询中断向量表，找到对应的中断服务程序入口地址。
4. **执行服务与唤醒：** 执行内核中的中断服务程序（如处理 I/O 完成）。在此过程中，系统会将等待该事件的进程从阻塞队列移入**就绪队列**。
5. **重新调度：** 中断处理结束后，由于就绪队列中有了新的高优先级进程，调度程序介入，剥夺闲逛进程的 CPU 执行权，进行上下文切换。

### 易错/易混点

- **外中断（Interrupt） vs 内中断/异常（Exception）：** 闲逛进程等待的必然是**外中断**（由时钟、外设等硬件触发）。因为闲逛进程自身的代码只是一个极简的空循环，它绝对不会主动执行“陷入指令”（系统调用），也不会引发“故障”（如缺页、除零出错）等内中断。
- **中断处理完毕后的流向陷阱：** 中断处理程序执行完毕后，并不一定会返回被中断的程序。在闲逛进程被中断的场景中，一旦中断处理程序唤醒了某个用户进程，调度程序会立即触发抢占，CPU 的控制权将转移给新唤醒的进程，而不是返回闲逛进程。

### 典型计算示例

在 408 考试中，常常通过计算**中断处理的系统开销**来考查对中断频率的理解。 **场景描述：** 假设系统时钟每 $1ms$ 产生一次时钟中断请求，每次执行时钟中断服务程序（包含保存/恢复现场和更新队列状态）的系统开销为 $5\mu s$。

- **中断开销占比计算公式：** $$中断开销占比 = \frac{单次中断处理时间}{中断周期} = \frac{5\mu s}{1ms} = \frac{5\mu s}{1000\mu s} = 0.5%$$
- **考点分析：** 时钟中断请求虽然是唤醒系统、打破闲逛状态以及驱动时间片轮转的关键，但其本身属于纯系统开销。如果硬件将时钟中断频率设置得过高（例如周期缩小为 $10\mu s$），则中断开销占比将飙升至 $50%$，导致 CPU 把一半的算力浪费在响应和处理中断上。因此，系统设计必须在“响应及时性”与“CPU 利用率”之间寻找平衡。
