
### 结论

在操作系统中，进程是动态执行的实体。为了对并发执行的进程进行有效控制和调度，操作系统按进程在执行过程中的不同情况，将其划分为五种基本状态：**创建态、就绪态、运行态、阻塞态和终止态**。其中，就绪、运行和阻塞是进程生命周期中最核心的三大基本状态。

### 关键机制

进程在生命周期内会因竞争资源或外部事件，在不同状态之间发生动态流转。其核心的状态转换过程如下：

1. **创建态 $\rightarrow$ 就绪态**：
    - 操作系统为一个新进程分配 PID（进程标识符）、申请空白 PCB（进程控制块），并为其分配除了 CPU 以外的内存等所有必需资源。创建工作完成后，将其插入就绪队列。
2. **就绪态 $\rightarrow$ 运行态**：
    - 处于就绪态的进程“万事俱备，只欠东风（CPU）”。当调度程序（Scheduler）按特定的调度算法（如时间片轮转、优先级调度）从就绪队列中选中该进程时，将处理机分配给它，进程进入运行态。
3. **运行态 $\rightarrow$ 就绪态**：
    - 正在执行的进程分配给它的**时间片用完**；或者在可抢占式调度中，有**更高优先级**的进程进入就绪队列，当前进程的 CPU 使用权被强行剥夺。此时进程被迫退回就绪队列等待下一次调度。
4. **运行态 $\rightarrow$ 阻塞态（等待态）**：
    - 进程在运行中需要等待某一事件发生（如请求外设 I/O 操作、等待其他进程的同步信号）。此时进程执行 `Block` 原语，**主动**让出 CPU，进入阻塞队列。
5. **阻塞态 $\rightarrow$ 就绪态**：
    - 进程所等待的事件已经完成（如 I/O 外设数据传输完毕，硬件触发中断）。中断处理程序执行 `Wakeup` 原语，将该进程唤醒，它**被动**地从阻塞队列移入就绪队列，重新等待获取 CPU。
6. **运行态 $\rightarrow$ 终止态**：
    - 进程正常执行完毕（如调用 `exit`）或由于发生严重错误（如非法指令、越界访问内存）被系统强制终止。系统将其置为终止态，随后回收其占用的全部资源及 PCB。

### 易错/易混点

针对 408 考研命题，进程状态转换有极多概念陷阱，必须死记以下规则：

- **陷阱 1：严禁“越级”的单行道**
    - **就绪态绝对不能直接变成阻塞态！** 因为进程在就绪态时根本没有占用 CPU，无法执行请求 I/O 或申请资源的指令，也就不会发生阻塞。
    - **阻塞态绝对不能直接变成运行态！** 阻塞的进程被唤醒后，只能先进入就绪队列排队，必须经过调度程序的重新调度才能获得 CPU 进入运行态。
- **陷阱 2：状态转换的主动性与被动性（高频考点）**
    - “运行 $\rightarrow$ 阻塞”是进程执行自身代码遇到条件不满足时（如发起系统调用请求 I/O）引发的**主动行为**。
    - “阻塞 $\rightarrow$ 就绪”是由外部事件（如 I/O 操作完成发出的硬件中断）唤醒触发的，对该进程而言是一种**被动行为**。
- **陷阱 3：单核 CPU 下的极值问题** 若系统只有一个单核 CPU，在任何时刻，处于运行态的进程**最多只有 1 个**；但处于就绪态和阻塞态的进程可能有很多个（构成各自的队列）。

### 典型计算示例

结合进程状态，常考查在引入 I/O 阻塞后，进程的**周转时间与处理机利用率**。分析的核心是：进程在运行态（占 CPU）、阻塞态（占 I/O）和就绪态（排队）的耗时拆解。

- **变量含义**：
    
    - $T_{run}$：进程在 CPU 上的纯计算时间（运行态）。
    - $T_{block}$：进程因 I/O 等待耗费的时间（阻塞态）。
    - $T_{ready}$：进程在就绪队列中等待调度的排队时间（就绪态）。
    - $T_{turnaround}$：周转时间，公式为 $T_{turnaround} = T_{run} + T_{block} + T_{ready}$。
- **完整计算过程举例**： 假设单核 CPU 系统中有两个并发进程 P1 和 P2（P1 优先级高于 P2，采用抢占式调度），在 $t=0$ 时刻同时到达就绪队列。 进程 P1：需执行 CPU 5ms $\rightarrow$ 磁盘 I/O 10ms $\rightarrow$ CPU 5ms。 进程 P2：需执行 CPU 8ms。
    
    **问：画出执行时序并计算 P2 的总周转时间及其各状态耗时？**
    
    1. $t = 0 \sim 5\text{ms}$：P1 优先级高，进入**运行态**。P2 进入**就绪态**排队。
    2. $t = 5 \sim 15\text{ms}$：P1 发起 I/O，进入**阻塞态**。此时就绪队列中只有 P2，P2 被调度进入**运行态**。
    3. $t = 13\text{ms}$：P2 已经运行了 8ms，执行完毕，进入**终止态**。此后 $13 \sim 15\text{ms}$ CPU 空闲，P1 仍在阻塞态。
    4. $t = 15\text{ms}$：P1 的 I/O 完成，由阻塞态转为**就绪态**，立刻被调度进入**运行态**。
    5. $t = 15 \sim 20\text{ms}$：P1 完成最后的 CPU 执行。
    
    **针对 P2 状态耗时分析结论**：
    
    - P2 的到达时间为 0，完成时间为 13ms。因此 **P2 的周转时间 $T_{turnaround} = 13\text{ms}$**。
    - P2 的运行态耗时：$T_{run} = 8\text{ms}$（在 $5 \sim 13\text{ms}$ 期间占用 CPU）。
    - P2 的阻塞态耗时：$T_{block} = 0\text{ms}$（全程无 I/O 请求）。
    - P2 的就绪态耗时：$T_{ready} = 5\text{ms}$（在 $0 \sim 5\text{ms}$ 期间等待 P1 放弃 CPU）。
    - 验算：$8\text{ms} + 0\text{ms} + 5\text{ms} = 13\text{ms}$，计算无误。
