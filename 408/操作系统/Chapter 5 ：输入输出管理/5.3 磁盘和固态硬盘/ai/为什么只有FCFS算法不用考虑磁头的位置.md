### 结论

在众多磁盘调度算法中，**FCFS（先来先服务 / First-Come, First-Served）** 是唯一一个**完全不需要知道/考虑当前磁头位置**的调度算法。

其根本原因在于：FCFS 算法的选择准则纯粹基于**请求到达的时间顺序（时间维度）**，而 SSTF、SCAN、C-SCAN 等其他算法的选择准则均基于**请求磁道与当前磁头位置的物理距离或移动方向（空间维度）**。

---

### 关键机制

为了厘清 FCFS 与其他磁盘调度算法在决策机制上的本质差异，下表对比了各种经典磁盘调度算法的决策依据与对磁头位置的依赖性：

|**磁盘调度算法**|**决策依据（选择准则）**|**依赖维度**|**是否需要知道当前磁头位置**|**是否需要知道磁头移动方向**|
|:--|:--|:--|:--|:--|
|**FCFS（先来先服务）**|请求进入队列的 **先后时间顺序**|时间|**否**（只看队列 FIFO 顺序）|**否**|
|**SSTF（最短寻道时间优先）**|距当前磁头位置 **磁道距离最近** 的请求|空间|**是**（需计算相对距离）|**否**|
|**SCAN（扫描算法 / 电梯算法）**|沿当前移动方向 **最近** 的请求（到达边界反向）|空间 + 方向|**是**（起点判定）|**是**（方向判定）|
|**C-SCAN（循环扫描算法）**|沿单向移动方向 **最近** 的请求（单向服务，快速返回）|空间 + 方向|**是**（起点判定）|**是**（方向判定）|
|**LOOK / C-LOOK**|沿移动方向 **最近** 的请求（到达最远请求即反向/返回）|空间 + 方向|**是**（起点判定）|**是**（方向判定）|

**算法决策逻辑详解：**

1. **FCFS 的纯时间逻辑：** 系统维护一个先入先出的请求队列，只要队列非空，就直接弹出队头请求交给磁盘执行。算法内部逻辑没有任何关于距离的计算（如 `|目标磁道 - 当前磁道|`），因此磁头在什么位置对决策结果**零影响**。
2. **其他算法的空间物理逻辑：** SSTF 每次选择时，都必须计算所有候选请求磁道与当前磁头位置的绝对差值，取最小值；SCAN、C-SCAN、LOOK 则必须结合当前磁头的物理磁道号以及磁头的“内/外移动方向”来筛选下一个服务目标。

### 易错/易混点

针对 408 统考真题选择题对“磁盘调度算法特性”的高频命题陷阱，请保持绝对清醒：

- **陷阱 1：“FCFS 不考虑磁头位置，所以它不需要移动磁头？”（极高频概念混淆！）**
    - **辨析：绝对错误！** FCFS 在**决策阶段**不需要知道磁头位置，但在**执行阶段**，磁头必须真实地移动（寻道）到目标磁道上。正因其决策时不管距离，极易导致磁头在磁盘内外侧来回剧烈“穿梭（摆动）”，导致**平均寻道长度（Seek Distance）极大、寻道性能最差**。
- **陷阱 2：“在特定情况下，FCFS 的性能可能会比 SSTF 或 SCAN 更好吗？”**
    - **辨析：是的！** 当磁盘请求的访问序列本身在物理磁道上就已经非常集中/连续，或者系统处于**低 I/O 负载（队列中请求极少，几乎随到随做）**时，FCFS 没有额外的计算与排序开销，且公平无饥饿，此时性能可接受甚至优于复杂的调度算法。
- **陷阱 3：固态硬盘（SSD）还需要考虑磁头位置吗？**
    - **辨析：SSD 没有磁头，所有算法都不需要考虑物理磁头位置！** 在 SSD 中，由于没有机械寻道与磁头臂运动，SSTF、SCAN 等算法失去了意义，操作系统对 SSD 往往直接采用类似 FCFS 的简单队列调度（或 FCFS 变体）即可。

### 例子 / 推导 / 记忆提示

#### 408 经典计算场景对比（以磁头位于 100 号磁道为例）

假设磁盘请求队列为：`55, 58, 39, 18, 90, 160, 150, 38, 184`。 当前磁头位于 **100** 号磁道：

- **采用 FCFS 算法：**
    - 决策依据：直接取队列首元素 `55`。
    - 访问顺序：`55 -> 58 -> 39 -> 18 -> 90 -> 160 -> 150 -> 38 -> 184`。
    - **结论**：假设初始磁头位置从 100 变成 200，FCFS 的**访问顺序完全不发生改变**（依然是 `55` 开头），这完美证明了 FCFS 的决策**零依赖**磁头初始位置。
- **采用 SSTF 算法：**
    - 决策依据：计算 `|55-100|=45`, `|90-100|=10`, `|160-100|=60` ... 最近的是 `90`。
    - 访问顺序：`90 -> 58 -> 55 -> 39 -> 38 -> 18 -> 150 -> 160 -> 184`。
    - **结论**：如果初始磁头位置变成 200，离 200 最近的是 `184`，访问顺序将彻底变成 `184 -> 160 -> 150 ...`。这证明 SSTF 等算法**极其依赖**磁头的初始物理位置。

#### 记忆口诀

- **FCFS 只看先后（时间），管你磁头在天边；**
- **SSTF 贪心算距离（空间），SCAN 沿路顺道拣；**
- **决策不知磁头位，唯有先来先服务！**
