### 结论

**位示图法（Bit Map）** 是利用二进制的一位（bit）来表示磁盘中一个物理盘块使用状态的空闲空间管理方法。通常规定“0”表示空闲，“1”表示已分配（或反之）。

理解位示图法的优缺点，核心在于看透它**用极其紧凑的“位”代替了庞大的表项或指针，从而实现了内存常驻和极速寻址**，但它在面对现代海量磁盘时也会遭遇“体积膨胀”的瓶颈。

---

### 关键机制与优缺点剖析

#### 1. 优点（高效与全能）

- **兼顾连续与离散分配：** 查找极为灵活。它既能快速找到散落的单个“0”位（支持离散分配），也能通过简单的位移与按位与运算，快速匹配一连串连续的“0”（支持连续分配）。
- **占用空间极小，可常驻内存：** 一个盘块只需要 1 bit 的记录空间。因为体积小，整个位示图通常可以完整地加载并常驻进物理内存中，避免了像空闲链表法那样在分配时需要频繁产生磁盘 I/O。
- **修改极快：** 盘块的分配或回收，只需要通过位运算将对应的 bit 置 1 或清 0 即可，计算和修改都极其高效。

#### 2. 缺点（容量扩展的阿喀琉斯之踵）

- **位示图大小随磁盘容量线性增长：** 尽管 1 bit 很小，但这在现代海量磁盘架构下依然是致命的。例如，对于一个 1TB 的磁盘，若盘块大小为 4KB，则有 $2^{28}$ 个盘块，位示图需要占用 $2^{28} \text{ bit} = 32\text{MB}$ 的连续主存空间。对于更大规模的系统（如 PB 级），位示图依然会吃掉庞大的内存。因此它**更适用于小型或中等规模的文件系统**（现代大型文件系统通常采用基于该思想升级的成组链接法）。

### 易错/易混点

针对 408 命题陷阱，位示图法可以说是**最喜欢考查计算题**的知识点，请务必避开以下大坑：

- **陷阱 1：下标是 0 起点还是 1 起点？（极高频必考）**
    - **辨析：** 题目会给出一个 $m$ 行 $n$ 列的二维位示图。在计算“盘块号”与“字号(行)、位号(列)”的转换时，**必须死死盯住题目给的盘块号、字号、位号是从 0 开始还是从 1 开始！** 差 1 就全错，这是 408 历年真题最爱挖的陷阱。
- **陷阱 2：“0”和“1”的含义反转。**
    - **辨析：** 绝大多数情况“0”代表空闲，“1”代表已分配。但 408 偶尔会故意反设（如“1”代表空闲），做题时必须仔细看清题目定义。

### 典型计算示例（408 核心考法模板）

**【题型设定】** 盘块的分配与回收转换计算。 假设位示图由若干行（字） $n$ 列（位）组成，每个字含 $n$ 位。

**情况 A：所有下标均从 1 开始**（盘块号 $b=1,2...$；行号 $i=1,2...$；列号 $j=1,2...$）

- 已知行 $i$ 列 $j$，求盘块号：**$b = n(i-1) + j$**
- 已知盘块号 $b$，求分配在位示图中的坐标 $(i, j)$：
    - 行号：**$i = (b-1) \text{ DIV } n + 1$** （DIV 为整除）
    - 列号：**$j = (b-1) \text{ MOD } n + 1$** （MOD 为取余）

**情况 B：所有下标均从 0 开始**（盘块号 $b=0,1...$；行号 $i=0,1...$；列号 $j=0,1...$）—— **这是计算机硬件与 408 考题中最常见的默认设定**

- 已知行 $i$ 列 $j$，求盘块号：**$b = n \times i + j$**
- 已知盘块号 $b$，求分配在位示图中的坐标 $(i, j)$：
    - 行号：**$i = b \text{ DIV } n$**
    - 列号：**$j = b \text{ MOD } n$**

### 记忆提示

- **形象类比：电影院的“选座大屏幕”**
    - **位示图**就像是电影院买票时的选座屏幕。
    - **优点（直观高效）：** 屏幕上的绿色小方块（0，空闲）和红色小方块（1，已分配）一目了然。你想买单人座（离散分配）或情侣连座（连续分配）都能瞬间找到。前台电脑（内存）加载这张图轻而易举。
    - **缺点（大容量受限）：** 如果要把全中国所有电影院的座位都放在这一块屏幕里（超大容量磁盘），这张图会大到连前台电脑的内存都装不下。
