### 结论

**BIOS（基本输入/输出系统，Basic Input/Output System）**是计算机通电后由 CPU 执行的**第一段软件代码**。它是一组固化在计算机主板 **ROM（只读存储器）**芯片上的程序，主要负责底层硬件的通电自检（POST）、基本外设的初始化，并**拉开操作系统链式引导（Booting）过程的序幕**。从操作系统的视角来看，BIOS 就是把 OS 从沉睡的磁盘中“唤醒”并拉入内存的第一棒交接者。

### 关键机制

BIOS 在操作系统引导初期的动态执行过程如下，必须严格遵循序号顺序：

1. **CPU 激活与提取 BIOS**：计算机通电后，CPU 的程序计数器（PC）会被硬件强制设置为一个特定的物理地址，直接指向主板 ROM 中的 BIOS 程序入口，CPU 开始执行 BIOS 代码。
2. **硬件自检与初始化（POST）**：BIOS 首先执行通电自检（Power-On Self Test），检测 CPU、内存及底层外设是否正常。同时，它会建立初步的**中断向量表**，为引导阶段的磁盘读取等设备访问提供最基础的服务支持。
3. **定位并挑选启动设备**：BIOS 检查通过后，会读取 CMOS 中的设置参数，确定引导设备的优先级序列（如优先 USB 启动还是硬盘启动），挑选出首个有效的启动物理设备。
4. **加载主引导记录（MBR）并交接**：这是 BIOS 的终极使命。BIOS 将选中磁盘的**首个物理扇区（即 MBR，包含引导代码与磁盘分区表）**按原样完整地读取并加载到内存中。随后，BIOS 执行跳转指令，将 CPU 的控制权正式移交给驻留在内存中的 MBR 引导程序，BIOS 退出主舞台。

### 易错/易混点

针对 408 命题陷阱，必须死记以下关于 BIOS 的边界红线：

- **陷阱 1：BIOS 能直接加载操作系统内核吗？** **绝对不能！** 408 选择题极爱考查引导的“接力层级”。BIOS 的代码逻辑非常原始，它根本不认识诸如 FAT32、NTFS 等高级文件系统，因此它找不到内核文件。它**只负责盲读磁盘的第 0 个物理扇区（MBR）**。后续是由 MBR 加载 PBR，PBR 加载启动管理器（如 GRUB），最后才由启动管理器加载操作系统内核。
- **陷阱 2：BIOS 的存储介质混淆** 考题常设坑问 BIOS 存在哪里。必须牢记：**BIOS 存放在主板的 ROM 中**（断电不丢失），而操作系统的内核、MBR、PBR 都存放在**磁盘（硬盘）**上。引导的本质就是 BIOS 牵头，把磁盘上的程序层层搬运到 RAM（主存）里的过程。
- **陷阱 3：现代操作系统运行期间还依赖 BIOS 吗？** **不依赖。** 在早期的 MS-DOS 时代，系统运行时会依赖 BIOS 提供的中断服务来操作硬件。但在现代操作系统（如 Linux、Windows）中，内核一旦被加载并接管系统，就会彻底废弃 BIOS 构建的简陋中断机制，**全面重建自己的中断向量表并加载专属的设备驱动程序**。

### 典型计算示例

虽然 BIOS 本身不涉及动态调度计算，但 408 经常结合 BIOS 的核心动作——“加载 MBR 扇区”来考查**磁盘数据结构的物理容量计算**。

- **变量含义**：
    
    - $S_{sector}$：BIOS 从磁盘加载的首个物理扇区大小（固定为 $512\text{B}$）。
    - $S_{DPT}$：MBR 内部的磁盘分区表（Disk Partition Table）大小。标准结构下支持 4 个主分区，每个分区表项占 $16\text{B}$。
    - $S_{magic}$：MBR 扇区结束标志（魔数 `0x55AA`）占用的空间（$2\text{B}$）。
- **完整计算过程举例**： 在系统引导的第 4 步中，BIOS 将 MBR（512 字节）读入内存。**问：在这被 BIOS 加载的 512 字节中，留给“主引导程序代码”的有效存储空间最大是多少？**
    
    1. **明确总载入容量**：BIOS 规定只加载 1 个物理扇区，即 $512\text{B}$。
    2. **扣除分区表开销**： $4 \text{ 个主分区} \times 16\text{B/分区} = 64\text{B}$。
    3. **扣除魔数开销**：固定占用 $2\text{B}$。
    4. **得出结论**： 引导代码最大空间 $= S_{sector} - S_{DPT} - S_{magic} = 512 - 64 - 2 = \mathbf{446\text{B}}$。
    
    _(注：正因为 BIOS 能够留给初始引导代码的空间仅有区区 446 字节，这段代码不足以装下庞大的文件系统解析器，这就从物理计算层面解释了为什么 BIOS 之后必须采取“MBR $\rightarrow$ PBR $\rightarrow$ Bootmgr”的多级链式接力架构。)_
