
### 结论

中断向量表（Interrupt Vector Table）是操作系统内存中的一个重要数据结构（通常实现为数组），专门用于存放**各个中断处理程序（或异常服务程序）的入口地址**。当发生中断或异常时，CPU 利用中断类型号查询该表，能以 $O(1)$ 的时间复杂度快速定位并跳转到对应的中断处理程序执行，从而极大提高中断处理效率。

### 关键机制

理解中断向量表，需要把握它的生命周期与硬件的协同配合过程：

1. **表的内容与结构**
    - **中断向量**：表中的每一个表项称为一个“中断向量”，它本质上就是某一个特定中断服务程序的**入口内存地址**。
    - **数组结构**：为了保证突发中断的极速响应，向量表采用连续的数组结构存储。通过“基址 + 偏移量”的方式即可实现 $O(1)$ 的极速寻址。
2. **初始化（软件行为）**
    - 中断向量表并不是天生就有的，它由**操作系统在系统初始化阶段**负责构建和写入。OS 会预先将各种硬件中断、软件陷阱对应的服务程序入口地址填入表的相应位置。
3. **查询与执行过程（硬件行为）**
    - **生成向量号**：当 CPU 检测到中断信号后，会根据中断源（如 I/O 完成、缺页、系统调用等）获取一个标识身份的**中断类型号（向量号）**。
    - **硬件查表跳转**：CPU（硬件）自动根据该类型号，计算出在中断向量表中的索引位置，提取出对应的入口地址，并自动修改程序计数器（PC）跳转执行，这整个查表动作由硬件自动完成，无须 OS 软件干预。

### 易错/易混点

- **陷阱 1：“查中断向量表”的执行主体** 408 考题中极易在这里设置陷阱！**初始化**中断向量表是由操作系统（软件）完成的；但是，中断发生时**查询**中断向量表、取出中断向量并跳转的过程，是由**硬件（CPU）自动完成的**，绝不是由操作系统的中断处理程序去查表。
- **陷阱 2：中断向量 vs 中断服务程序** “中断向量”只是一个地址指针（Entrance Address），存放在中断向量表中；而“中断服务程序”是实际执行的一段代码逻辑，存放在内存的内核代码区中。两者不可混为一谈。
- **陷阱 3：中断处理过程的时序** 完整的保护现场包含两步。查中断向量表跳转之前，硬件会自动保存断点（PC 和 PSW）；跳转到中断处理程序后，再由软件（中断处理程序）保存各通用寄存器的值。

### 典型计算示例

在结合《计算机组成原理》与 OS 的跨学科考查中，常要求根据中断类型号计算中断向量的物理存储地址。

- **变量含义**：
    - $Base$：中断向量表的首地址（基址）。
    - $N$：发生的中断类型号（或向量号）。
    - $L$：每个中断向量所占用的字节数（如 32 位系统中通常为 4B）。
    - $Addr_{vector}$：该中断对应的中断向量在内存中的地址。
- **计算公式**： $Addr_{vector} = Base + N \times L$
- **完整计算过程举例**： 假设某 32 位计算机系统中，中断向量表存放在内存的最底端，首地址为 `0x0000 0000`。每个中断向量占用 4 个字节（4B）。现用户程序执行了一条陷入指令（如 `int 0x80`）发起系统调用，其中断类型号为 `128`（即十进制的 $128$ 对应十六进制 `0x80`）。 **问：系统去哪个物理地址读取系统调用的入口地址？**
    
    1. 确认基址：$Base = 0x0000 0000$。
    2. 计算偏移量：$Offset = N \times L = 128 \times 4\text{B} = 512\text{B}$。
    3. 转换为十六进制：$512$ 对应的十六进制为 `0x200`。
    4. 得出地址：$Addr_{vector} = 0x0000 0000 + 0x200 = 0x0000 0200$。
    
    - **结论**：硬件会自动访问内存地址 `0x0000 0200` 处，取出其中的 4 字节数据（即系统调用总控程序的入口地址），送入 PC 开始执行内核态代码。时间复杂度表现为完美的 $O(1)$。
