## 操作系统引导

操作系统（如 Windows、Linux 等）是一种程序，程序以数据的形式存放在硬盘中，而硬盘通常分为多个区，一台计算机中又可能有个或多种外部存储设备。  
操作系统引导是指计算机利用 CPU 运行特定程序，通过程序**识别硬盘**，识别**硬盘分区**，识别**硬盘分区上的操作系统**，最后**通过程序启动操作系统**，一环扣一环地完成上述过程。

### 引导过程

常见操作系统的引导过程如下：

1. **激活 CPU**。激活的 CPU 读取 ROM 中的 boot 程序，将指令寄存器置为 BIOS（**基本输入/输出系统**）的第一条指令，即开始执行 BIOS 的指令。
    
2. **硬件自检**。BIOS 程序在内存最开始的空间构建**中断向量表**，接下来的 POST（通电自检）过程要用到**中断**功能。  
   然后进行通电自检，检查硬件是否出现故障。  
   如有故障，主板会发出不同含义的蜂鸣，启动中止；  
   如无故障，屏幕会显示 CPU、内存、硬盘等信息。
    
3. **加载带有操作系统的硬盘**。通电自检后，BIOS 开始读取 Boot Sequence（通过 CMOS 里保存的启动顺序，或者通过与用户交互的方式），将控制权交给启动顺序排在第一位的存储设备，然后 CPU 将该存储设备引导扇区的内容加载到内存中。
    
4. **加载主引导记录（MBR）**。硬盘以特定的标识符区分引导硬盘和非引导硬盘。  
   若发现一个存储设备不是可引导盘，就检查下一个存储设备。如无其他启动设备，就会死机。  
   主引导记录 MBR 的作用是告诉 CPU 去硬盘的哪个主分区去找操作系统。
    
5. **扫描硬盘分区表，并加载硬盘活动分区**。  
   MBR 包含硬盘分区表，硬盘分区表以特定的标识符区分活动分区和非活动分区。  
   主引导记录扫描硬盘分区表，进而识别含有操作系统的硬盘分区（活动分区）。  
   找到硬盘活动分区后，开始加载硬盘活动分区，将控制权交给活动分区。
    
6. **加载分区引导记录（PBR）**。读取活动分区的第一个扇区，这个扇区称为分区引导记录（PBR），其作用是寻找并激活分区根目录下用于引导操作系统的程序（启动管理器）。
    
7. **加载启动管理器**。分区引导记录搜索活动分区中的启动管理器，加载启动管理器。
    
8. **加载操作系统**。将操作系统的初始化程序加载到内存中执行。



### 结论

**操作系统引导（OS Booting）**是指计算机在通电后，通过执行一系列预设的引导程序，依次定位启动设备、确定可引导的磁盘分区、将外部存储设备（如硬盘）中的**操作系统内核映象加载到内存中**，并最终将计算机控制权交接给操作系统的链式过程。简而言之，就是把操作系统这个“管家”从静态的磁盘唤醒并请入内存工作的过程。

### 关键机制

操作系统的引导过程是一个极其严密的**多级接力、链式加载**的动态执行流程，具体步骤如下：

1. **CPU 激活与 BIOS 初始化**：计算机通电后，CPU 首先从主板上的 ROM 中读取并执行 BIOS（基本输入/输出系统）程序。BIOS 会初始化基本硬件，并建立中断向量表，为后续的底层设备访问提供支持。
2. **硬件自检与启动设备选择**：BIOS 执行通电自检（POST），检测 CPU、内存及外设是否正常。随后，依据 CMOS 中的设置确定启动设备的优先级，挑选首个有效的启动设备（如第一块硬盘）。
3. **加载主引导记录（MBR）**：BIOS 定位到目标硬盘后，将其**首扇区**（即主引导记录 MBR，包含引导代码与磁盘分区表）读取并加载到内存中执行。
4. **定位活动分区并加载 PBR**：MBR 中的引导代码开始运行，它负责解析磁盘分区表，找出标记为“活动”状态的分区，然后将该活动分区的**首扇区**（即分区引导记录 PBR）加载到内存中。
5. **加载启动管理器**：PBR 中的代码开始执行，它的任务是从活动分区的文件系统中寻找并加载**启动管理器**（如 Windows 的 Bootmgr 或 Linux 的 GRUB）。启动管理器会为用户提供多操作系统或内核版本的选择界面。
6. **加载操作系统内核**：启动管理器根据用户的选择，将对应的**操作系统内核映象**真正加载到内存中，并跳转执行。此时，OS 内核正式接管系统的控制权，并重建自己的中断处理机制（不再依赖 BIOS 提供的简陋服务）。
7. **内核初始化与用户环境启动**：内核开始大展拳脚，完成核心子系统的初始化（如构建页表、初始化 PCB 链表及就绪/阻塞队列、加载设备驱动）。一切就绪后，内核启动第一个用户态进程（如 Linux 的 `init` 进程），至此引导彻底完成，进入用户操作界面。

### 易错/易混点

针对 408 命题陷阱，必须死记以下接力棒的“交接边界”：

- **陷阱 1：BIOS 能直接加载操作系统内核吗？** **绝对不能！** 408 选择题极爱考查加载的层级关系。BIOS 的能力非常弱，它**只负责加载 MBR**。随后是 MBR 加载 PBR，PBR 加载启动管理器，最后由启动管理器来加载内核。这是一个不可跨级的“套娃”过程。
- **陷阱 2：引导程序存放在哪里？** 考题常将引导程序的存放位置混淆。必须清晰界定：
    - **BIOS**：存放在主板的 **ROM**（只读存储器）中，断电不丢失。
    - **MBR / PBR / 内核**：存放在**磁盘（硬盘）**上。引导的过程本质就是把后三者从磁盘逐级搬运到 RAM（内存）中的过程。
- **陷阱 3：内核初始化包括哪些内容？** 内核初始化不仅需要加载设备驱动，还必须初始化进程控制块（PCB）、调度队列和空闲进程等系统级的数据结构，绝非仅仅停留在硬件层面。

### 典型计算示例

虽然操作系统引导主要考查定性的流程，但在 408 与计算机组成原理的交叉考点中，常结合**磁盘物理扇区结构**来考查 MBR 的空间分配计算。

- **变量含义**：
    - $S_{sector}$：标准磁盘的一个物理扇区大小（通常为 $512\text{B}$）。
    - $S_{DPT}$：磁盘分区表（Disk Partition Table）的大小。标准 MBR 中支持 4 个主分区，每个分区表项占 $16\text{B}$。
    - $S_{magic}$：MBR 结束标志（魔数 Magic Number，固定为 `0x55AA`）占用的大小（$2\text{B}$）。
- **完整计算过程举例**： 在系统引导的第 3 步中，BIOS 会将硬盘的第 0 扇区（MBR）原封不动地读入内存。**问：在 MBR 这一扇区中，留给“主引导程序代码”的存储空间最大是多少字节？**
    1. **明确总容量**：MBR 占用 1 个扇区，总大小 $= 512\text{B}$。
    2. **扣除固定结构开销**：
        - 分区表总开销 $= 4 \text{ 个主分区} \times 16\text{B/分区} = 64\text{B}$。
        - 结束标志魔数 $= 2\text{B}$。
    3. **得出结论**： 主引导代码可用空间 $= S_{sector} - S_{DPT} - S_{magic} = 512 - 64 - 2 = \mathbf{446\text{B}}$。 _(注：正因为主引导代码的体积被死死限制在 446 字节内，它无法包含复杂的文件系统驱动，所以才必须引入后续的 PBR 和独立的启动管理器来进行多级接力加载。)_
