### 结论

**往返时延（Round-Trip Time, RTT）**是指从发送端**发送出一个数据分组开始**，直到**收到接收端发回的确认信号（ACK）**所经历的总时间。在 408 考纲中，RTT 是量化网络交互性能、计算有效数据交付时间以及设定传输层超时重传机制（如 TCP 的 RTO）的绝对核心指标。

### 关键机制

要精准量化 RTT，必须明确它在数据流转过程中“包含了什么”和“剔除了什么”：

- **RTT 的组成部分（包含项）：**
    - **往返传播时延：** 电磁波在发送端与接收端之间一来一回所花费的纯物理飞行时间（通常为 $2 \times 单向传播时延$）。
    - **处理与排队时延：** 包含接收端收到数据后进行处理的时间，以及在互联网环境中沿途各中间路由器所产生的排队时延和处理时延。
- **RTT 的剔除部分（绝对考点）：**
    - **不包含数据分组的发送时延：** RTT 的计时起点是“发出第一个比特”，终点是“收到确认”，在这段时间内，发送端一直在把后续的比特推上链路。因此，**往返时延绝对不包括数据分组本身的发送时延**。
    - **通常忽略确认分组（ACK）的发送时延：** 因为确认控制帧通常极短，其发送时延微乎其微，408 计算中除非明确给出 ACK 的大小和带宽，否则默认忽略不计。
- **追踪应用场景：**
    - **网络层探测：** 常用的 `PING` 命令就是通过发送 ICMP 回送请求和回答报文，来测量两台主机之间的 RTT 连通性。

### 易错/易混点高感度提示

- **陷阱 1：计算“完整交互总时间”时直接等同于 RTT**
    - **命题点：** 题目问“从主机 A 发送数据开始，到 A 确认数据已被 B 成功接收的总耗时”。
    - **避坑逻辑：** $总时间 \neq RTT$！根据时空流转图，发送端必须先把数据全部推上链路（产生发送时延），加上往返飞行和确认的时间（RTT），因此核心公式为：**$完成一次交互的总时间 = 数据分组的发送时延 + RTT$**。
- **陷阱 2：局域网 CSMA/CD 协议中的争用期（碰撞窗口）**
    - **命题点：** 以太网最短帧长计算。
    - **避坑逻辑：** 在以太网中，端到端的往返传播时延被称为**争用期（$2\tau$）**。它其实是 RTT 的一个物理层特例（仅考虑纯物理信道的往返传播时间）。主机如果在 $2\tau$ 时间内没有检测到冲突，才能肯定这次发送没有发生碰撞。
- **陷阱 3：TCP 建立连接的 RTT 累加陷阱**
    - **命题点：** 考查建立 TCP 连接并发送 HTTP 请求的时间。
    - **避坑逻辑：** TCP 三次握手前两次交互消耗 $1$ 个 RTT。第三次握手（带数据）发出后，再等确认又是一个交互。牢记：**$总耗时 = 建立连接的 RTT + 数据发送时延 + RTT$**。

### （可选）示例 / 推导 / 拓扑结构

**【408 经典时延计算演练】** **场景追踪：** 假设主机 A 向主机 B 发送一个大小为 $1000\text{ B}$ 的数据分组，A 的网卡发送速率为 $10\text{ Mb/s}$。A、B 之间的一条直连链路长度为 $200\text{ km}$，电磁波在该介质中的传播速率为 $2 \times 10^8\text{ m/s}$。假设 B 收到分组后立即回复一个极小的 ACK 确认帧（忽略 B 的处理时延及 ACK 的发送时延）。求 RTT 及 A 完成此次数据交付的总时间。

**公式推导：**

1. **明确单位换算：**
    - 数据长度：$L = 1000\text{ B} = 8000\text{ bit}$。
    - 发送速率：$C = 10\text{ Mb/s} = 10 \times 10^6\text{ b/s}$。
    - 链路长度：$D = 200\text{ km} = 2 \times 10^5\text{ m}$。
2. **计算往返时延 (RTT)：**
    - 单向传播时延 $t_{prop} = \frac{D}{V} = \frac{2 \times 10^5\text{ m}}{2 \times 10^8\text{ m/s}} = 10^{-3}\text{ s} = 1\text{ ms}$。
    - 因为忽略了处理时延，所以 $RTT = 2 \times t_{prop} = 2\text{ ms}$。
3. **计算数据分组发送时延：**
    - $t_{send} = \frac{L}{C} = \frac{8000\text{ bit}}{10 \times 10^6\text{ b/s}} = 8 \times 10^{-4}\text{ s} = 0.8\text{ ms}$。
4. **计算总时间：**
    - $交互总时间 = 发送时延 + RTT = 0.8\text{ ms} + 2\text{ ms} = 2.8\text{ ms}$。
