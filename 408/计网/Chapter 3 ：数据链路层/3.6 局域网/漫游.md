### 结论

在 IEEE 802.11 无线局域网中，**漫游（Roaming）**是指移动站（STA，如手机、笔记本）从一个基本服务集（BSS1）的覆盖范围移动到另一个基本服务集（BSS2）的覆盖范围，且这两个 BSS 属于同一个扩展服务集（ESS）时，**保持其网络层 IP 地址不变，且上层网络连接（如 TCP 会话）不发生中断的底层无缝切换过程**。

漫游的核心本质是：**网络层（IP）的静态屏蔽与数据链路层（MAC）的动态重连**。在漫游过程中，移动站的默认网关（Portal）和 IP 子网完全没有改变，唯一改变的是底层无线介质的接入点（AP）以及 802.11 MAC 帧首部中的 BSSID（AP 的 MAC 地址）。

---

### 关键机制

- **同一子网的逻辑屏蔽：** 多个 AP 通过分配系统（DS）连接成一个 ESS。在网络层看来，这整个 ESS 构成了**唯一的一个 IP 广播域（同一个网段）**。因此，移动站在 ESS 内部物理位置的移动，不会触发 DHCP 重新请求，IP 地址得以继续保持。
- **信号侦听与重新关联（MAC层动作）：**
    - 移动站的网卡会持续被动侦听（或主动探测）周围其他 AP 发出的信标帧（Beacon）。
    - 当当前连接的 AP1 信号强度衰减到某个阈值以下，且探测到同 SSID 下的 AP2 信号更强时，移动站会在数据链路层发起向 AP2 的**重新关联（Re-association）**请求。
- **分配系统（DS）的转发表刷新：**
    - 当移动站成功关联到新的 AP2 后，AP2 会通过有线的分配系统（DS）发出更新报文（如更新以太网交换机的 MAC 地址转发表）。
    - 这会使得发往该移动站的下行数据流，在 DS 内部自动改道，不再被送往旧的 AP1，而是精准路由到新的 AP2。
- **BSSID 替换：**
    - 漫游完成后，移动站收发的所有 802.11 MAC 帧中，代表当前服务集标识的地址字段（`地址 1` 或 `地址 2`）必须从 AP1 的 MAC 地址**更替为 AP2 的 MAC 地址**。

---

### 易错/易混点

- **陷阱：漫游会改变 IP 地址吗？**
    - **绝对不会。** 408 考题中常以此考察对分层架构的理解。如果移动站跨越了 ESS，进入了另一个完全不同的网络（例如从家里的 Wi-Fi 连上了星巴克的 Wi-Fi），此时它的 IP 地址会改变，原有的 TCP 连接必定全部断开。这在网络术语中只能叫“重新连网”，**绝不属于同一 ESS 内的标准无缝漫游**。
- **辨析：漫游发生在哪个协议层？**
    - **只发生在数据链路层（MAC子层）和物理层。** 漫游完全是对网络层透明的。IP 层根本不知道底层的无线网卡刚刚“换了一个基站”，它只管继续向下层递交 IP 数据报。
- **避坑：漫游是由谁主导决定的？**
    - 在传统的 802.11 网络中，漫游的决策权**掌握在移动站（客户端）手中**。是手机或笔记本的网卡固件觉得信号不行了，才主动向新 AP 发起关联，而不是 AP 强制把终端“踢”给别人（尽管现代企业级 WLAN 引入了控制器 AC 辅助漫游，但 408 基础理论中仍以终端主动切换为准）。

### 示例 / 推导 / 拓扑结构

**【数据流转图景：移动站跨 AP 漫游前后的底层动态交互】**

假设在一个企业网络中（同一个 ESS，由多台 AP 和中心交换机组成），员工拿着笔记本电脑（STA）正在通过 TCP 下载文件，并从会议室（由 AP1 覆盖）走向了工位（由 AP2 覆盖）。

1. **初态（连接 AP1）：**
    - STA 向外发送数据时，封装的 802.11 帧中，`地址 1` (接收端) 填入的是 **AP1 的 MAC 地址**。
    - 交换机（DS）的 MAC 地址表记录着：`STA的 MAC 地址 -> 对应连接 AP1 的交换机端口`。外网回传的文件数据全由 AP1 转发给 STA。
2. **切换与重新关联（走向工位）：**
    - STA 发现 AP1 信号变弱，检测到同 ESS 的 AP2 信号极强。
    - STA 的 MAC 层与 AP1 断开关联（Disassociation），并立刻向 AP2 发出**重新关联请求（Re-association Request）**。
    - AP2 接受请求。此时 TCP 传输会经历极其短暂的底层延迟，但由于未超时，连接依然存活。
3. **DS 转发表动态更新（网络拓扑自适应）：**
    - AP2 马上通过有线线路向企业中心的交换机发送控制帧（或免费 ARP）。
    - 交换机学习到新信息，刷新 MAC 地址表：`STA的 MAC 地址 -> 变更为连接 AP2 的交换机端口`。
4. **终态（连接 AP2 并恢复传输）：**
    - 外网服务器继续下发 TCP 报文段，目的 IP（STA 的 IP）没变。
    - Portal 网关将 IP 分组交给企业交换机，交换机根据最新转发表，将报文发给 **AP2**。
    - AP2 将其封装为 802.11 下行帧发给 STA，此时帧首部的 `地址 2` (发送端) 已经赫然变成了 **AP2 的 MAC 地址**。
    - STA 顺利解封，上交网络层，TCP 下载任务无缝继续，用户感受不到网络曾经发生了切换。
