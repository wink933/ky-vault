在 408 的数据链路层（以及早期传输层理论）考点中，**后退 N 帧协议（Go-Back-N, 简称 GBN）**是滑动窗口协议的绝对核心。理解 GBN 的工作流程，必须牢牢抓住它**“发送窗口 $> 1$，接收窗口 $= 1$”**的本质特征，以及它与上一问我们讨论过的“累计确认”机制的深度绑定。

下面我将为你详细拆解 GBN 协议的完整工作流程。

### 结论

GBN 协议是一种利用流水线技术提高信道利用率的可靠传输协议。它的核心逻辑是：允许发送方在未收到确认的情况下连续发送多个帧；但**接收方只能按序接收（接收窗口为 1）**，任何乱序到达的帧都会被无情丢弃；一旦出现丢包或差错，发送方必须**“后退 N 步”**，重传那个出错的帧以及它之后发送的所有帧。

---

### 关键机制

- **非对称的窗口大小：**
    - **发送窗口 ($W_T$)：** $1 < W_T \le 2^n - 1$（$n$ 为帧序号的比特数）。发送方可以在窗口允许的范围内连续发送多个帧。
    - **接收窗口 ($W_R$)：** $W_R = 1$。接收方只接收期望序号的那一个帧，绝不缓存乱序帧。
- **累计确认 (Cumulative ACK)：** 接收方不必对收到的每一个帧逐个发送 ACK。它可以连续收到几个帧后，只发送对按序到达的最后一个帧的确认。如前所述，发回 $ACK_n$ 表示：“第 $n$ 号帧及之前的帧都已正确无误接收，现在期待收到第 $n+1$ 号帧”。
- **捎带确认：** 接收方在有数据需要发送给对方时，可以将 ACK 确认信息“顺便”放在数据帧的首部带过去，以减少控制帧的开销。
- **超时定时器：** 发送方仅需为**发送窗口内最老的一个未被确认的帧**维护一个超时计时器。

### 动态交互过程（GBN 正常与异常流转图景）

假设发送方 A 向接收方 B 发送数据，采用 GBN 协议。

**1. 连续封装与发送（发送方动作）**

1. **数据封装**：A 的网络层将多个分组向下传递，数据链路层将它们依次封装成带有序号的 MAC 帧（如 0, 1, 2, 3 号帧）。
2. **流水线发送**：只要 A 的发送窗口未满，A 就可以连续将这些帧注入物理介质。同时，A 启动（或重置）针对 0 号帧的超时计时器。

**2. 按序到达与解封（正常接收流转）**

1. **按序查验**：0 号帧、1 号帧依次到达 B。B 检查帧校验序列（FCS）无误，且序号正好是接收窗口期望的（$W_R$ 依次期待 0, 1）。
2. **向上交付与确认**：B 剥离链路层首部，将数据上交网络层，接收窗口向前滑动。B 可以选择发回 $ACK_1$（表示 0 和 1 都收到了，期待 2 号帧）。
3. **窗口滑动**：A 收到 $ACK_1$ 后，发送窗口向前滑动两个位置，A 可以继续封装发送新的数据帧。

**3. 差错/丢包发生与乱序丢弃（核心特征展现）**

1. **跳号到达**：假设 2 号帧在传输中因为噪声导致 FCS 校验失败（或直接丢失），而后续的 3 号帧、4 号帧完美无瑕地到达了 B。
2. **无情丢弃**：B 检查 3 号帧，虽然它没有物理误码，但 B 当前期待的是 2 号帧（$W_R$ 卡在 2）。由于 GBN 接收窗口为 1，B **不缓存**乱序的帧，直接将 3 号帧和 4 号帧**丢弃**。
3. **发送冗余 ACK**：B 发现失序，为了催促 A，B 针对之前最后一次按序收到的帧，回送冗余确认（即再次发送 $ACK_1$）。

**4. 计时器超时与后退 N 帧重传（差错恢复）**

1. **超时研判**：A 迟迟收不到 2 号帧的确认。最终，A 维护的最老未确认帧（2 号帧）的超时计时器到期。
2. **重传惩罚**：A 判定 2 号帧已丢失。尽管 3 号和 4 号帧 A 早就发过了（甚至 B 的网卡都已经摸过它们了），但因为 GBN 协议的死板特性，A 必须“后退”到出错的起点。
3. **批量重传**：A 将发送窗口内的 2、3、4 号帧全部重新发送一遍。

### 协议对比辨析

在 408 中，GBN 往往与停止-等待协议（SW）和选择重传协议（SR）放在一起对比考察：

|**维度**|**停止-等待 (Stop-and-Wait)**|**后退 N 帧 (GBN)**|**选择重传 (Selective Repeat, SR)**|
|---|---|---|---|
|**发送窗口 ($W_T$)**|$W_T = 1$|$1 < W_T \le 2^n - 1$|$1 < W_T \le 2^{n-1}$|
|**接收窗口 ($W_R$)**|$W_R = 1$|**$W_R = 1$ (最核心区别)**|$W_R > 1$ (通常 $W_R = W_T$)|
|**确认机制**|逐个确认|**累计确认** (允许捎带)|独立/逐个确认 (必须确认每一个帧)|
|**对乱序帧的处理**|丢弃 (根本不会产生乱序)|**直接丢弃，不予缓存**|**缓存于接收窗口中**，等缺失帧到达后一起交付|
|**重传代价**|小 (仅重传丢失的那1帧)|**极大** (需重传丢失帧及后续所有帧)|小 (仅重传真正丢失的那个帧)|
|**信道利用率**|极低|较高 (但在误码率高的链路上性能暴跌)|极高 (适合高误码率、高延迟链路)|

### 易错/易混点高感度提示

1. **陷阱：发送窗口的最大尺寸为什么是 $2^n - 1$ 而不是 $2^n$？**
    - **避坑：** 408 必考选择题。假设序号用 3 个比特表示（序号范围 0~7）。如果 $W_T = 8$，A 发送了 0~7 号帧。B 全部正确收到，并发回 $ACK_7$。若该 $ACK_7$ 在网络中丢失，A 超时后会重传这 8 个旧帧（序号又是 0~7）。但 B 的接收窗口早已滑动到下一轮的 0 号帧。B 会把这些重传的**旧帧**误认为是下一轮的**新帧**，导致数据重复交付。限制 $W_T = 7$，就能让新旧窗口的序号产生错位，从而避免这种歧义。
2. **陷阱：累计确认的“掩护”作用。**
    - **避坑：** 在计算题中，如果 A 发送了 0, 1, 2 号帧。B 收到了 0 和 1，分别发回 $ACK_0$ 和 $ACK_1$。此时如果 **$ACK_0$ 丢失，但 $ACK_1$ 顺利到达 A**。A 需不需要重传 0 号帧？**绝对不需要！** 因为 $ACK_1$ 的意思是“1 号及之前的帧全收到了”，它完美掩护了 $ACK_0$ 的丢失。
3. **计算陷阱：信道利用率与最小帧长。**
    - **避坑：** 题目常问“为了达到 100% 的信道利用率，发送窗口最小是多少？”核心公式是：$连续发送窗口的数据发送总时间 \ge 往返传播时延(RTT) + 一帧的发送时间$。即只要在等第一个 ACK 回来之前，发送方能一直不停地把数据往信道上塞，利用率就是 100%。
