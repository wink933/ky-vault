你好！我是你的**“408 计算机网络复习助手”**。

在 408 数据链路层（及传输层可靠传输理论）的考查中，**自动重传请求（ARQ）协议**是经久不衰的绝对重点。三种 ARQ 协议——**停止-等待（SW）**、**后退 N 帧（GBN）**和**选择重传（SR）**的演进，本质上是一场**“用空间（缓存）和复杂度换取时间（信道利用率）”**的优化过程。

下面我将为你对这三种 ARQ 协议进行全维度的深度对比与拆解。

### 结论

三种 ARQ 协议的核心差异在于**窗口大小的配置**与**确认机制的选择**。

- **停止-等待（SW）：** 窗口极小（发送=1，接收=1），发一个等一个，效率最低。
- **后退 N 帧（GBN）：** 扩大发送窗口（流水线发送），但接收窗口仍为 1。出错时必须“连坐”重传出错帧及其后续所有帧。
- **选择重传（SR）：** 进一步扩大接收窗口，允许乱序缓存。出错时实现“精准打击”，仅重传丢失的帧，效率最高但逻辑最复杂。

---

### 关键机制

- **发送窗口 ($W_T$) 与接收窗口 ($W_R$)：** 滑动窗口的大小直接决定了协议的类型和处理乱序帧的能力。
- **确认机制的演变：**
    - SW 采用**逐个确认**（收到 $n$ 就回 $ACK_n$）。
    - GBN 采用**累计确认**（回 $ACK_n$ 表示 $n$ 及之前的全收到了，可掩护丢失的 ACK）。
    - SR 采用**独立确认**（因为有乱序缓存，只能单独确认收到的每一个帧，不能累计）。
- **超时定时器的分配：** SW 和 GBN 只需要维护**一个**定时器（GBN 维护最老未确认帧的）；而 SR 必须为发送窗口里的**每一个帧**分别维护独立的定时器。

### 网络计算（性能量化与窗口上限）

在 408 计算题中，必须牢记以下核心公式（设帧序号占 $n$ 个比特，即序号范围 $0 \sim 2^n-1$）：

**1. 窗口尺寸上限公式**

- **SW 协议：** $W_T = 1, W_R = 1$。
- **GBN 协议：** $1 < W_T \le 2^n - 1$。
    - _注：如果 $W_T = 2^n$，所有的 ACK 丢失时，重传的旧帧会被接收方误认为下一轮的新帧，产生序号重叠歧义。_
- **SR 协议：** $W_T + W_R \le 2^n$。
    - _注：为了达到最大效率，通常取 $W_{Tmax} = W_{Rmax} = 2^{n-1}$。_

**2. 信道利用率公式**

- **核心公式：** $信道利用率 (U) = \frac{连续发送的有效数据耗时}{总耗时} = \frac{W_T \times 帧发送时延}{帧发送时延 + 往返传播时延(RTT) + ACK发送时延}$
- **最大化条件：** 要想让信道利用率达到 100%（即信道上始终有数据在飞），发送窗口必须满足：$W_T \ge \frac{RTT + 帧发送时延}{帧发送时延}$。

### 易错/易混点高感度提示

1. **陷阱：GBN 协议中 ACK 丢失的后果。**
    - **避坑：** 由于 GBN 采用**累计确认**，如果 $ACK_0$ 丢失了，但后续的 $ACK_1$ 顺利到达了发送方。发送方会认为 0 号和 1 号帧都已经被正确接收，**绝对不会重传 0 号帧**。而 SR 协议由于是独立确认，某个 ACK 丢了就必定会导致该帧重传。
2. **陷阱：SR 协议收到“窗口下方”的旧帧。**
    - **避坑：** 408 曾考过，在 SR 协议中，由于 ACK 可能丢失，导致发送方超时重传了接收方早已经接收并交付的旧帧。此时接收方绝对不能直接丢弃并保持沉默，而是**必须丢弃该帧，并补发一个该旧帧的 ACK**，否则发送方的窗口将永远卡住无法滑动。
3. **计算陷阱：传播时延（单程）与 RTT（双程）的混淆。**
    - **避坑：** 计算信道利用率周期时，使用的是**双程往返时延（$RTT = 2 \times \tau$）**，加上数据帧的发端发送时延。如果题目给出了 ACK 帧的长度，还必须加上 ACK 帧在收端的发送时延。

### 动态交互过程（丢包场景下的数据流转对比）

为了直观体会三者的差异，我们推演一个经典场景：**发送方依次发送 0, 1, 2, 3 号帧，其中 1 号帧在网络中丢失，其余帧完美到达。**

**1. 停止-等待 (SW) 的处理过程**

1. 发送 0 号帧 $\rightarrow$ 收到 $ACK_0$。
2. 发送 1 号帧 $\rightarrow$ **丢失**。
3. 傻等，直到 1 号帧的计时器超时。
4. 重传 1 号帧 $\rightarrow$ 收到 $ACK_1$。
5. 才能继续发送 2 号帧。（完全没有流水线，慢得出奇）

**2. 后退 N 帧 (GBN) 的处理过程**

1. 流水线连续发送 0, 1, 2, 3 号帧。
2. 接收方收到 0 号帧，回传 $ACK_0$。
3. **1 号帧丢失**。
4. 接收方收到 2 号和 3 号帧（乱序）。因为接收窗口为 1，接收方**直接丢弃** 2 和 3，并向发送方连续发回两个 $ACK_0$（冗余确认）。
5. 发送方的 1 号帧计时器超时。
6. 发送方被迫**后退**，重新发送 1、2、3 号帧。（“连坐”机制，浪费了已经成功抵达的 2 和 3 的带宽）

**3. 选择重传 (SR) 的处理过程**

1. 流水线连续发送 0, 1, 2, 3 号帧，并分别启动 4 个定时器。
2. 接收方收到 0 号帧，回传 $ACK_0$。窗口滑动。
3. **1 号帧丢失**。
4. 接收方收到 2 号和 3 号帧。因为接收窗口大于 1，接收方将 2 和 3 **存入缓存**，并分别回传 $ACK_2$ 和 $ACK_3$（独立确认）。
5. 发送方收到 $ACK_2$ 和 $ACK_3$，标记它们已到达，但窗口因为卡在 1 号无法滑动。
6. 发送方的 1 号帧计时器超时。发送方**仅重传 1 号帧**。
7. 接收方收到重传的 1 号帧，回传 $ACK_1$。此时缓存中的 1, 2, 3 连成一片，一同向上交付，接收窗口大步向前滑动。（精准恢复，效率极高）
