### 结论

在 408 考试大纲中，**路由选择（Routing）**和**分组转发（Forwarding）**是网络层路由器最核心的两大基本功能。

这两者的本质区别在于：**路由选择**属于**控制平面**，其任务是纵观全局，通过运行特定的路由协议算法来“寻找最优路径”并构建路由表；而**分组转发**属于**数据平面**，其任务是着眼局部，根据转发表将刚刚到达路由器输入端口的单个数据报极速“搬运”到合适的输出端口。

简而言之：**路由选择负责“指引大方向（画地图）”，分组转发负责“具体带路（过路口）”。**

---

### 关键机制

为了透析这两者的差异，我们从架构平面和动态交互过程两个维度进行拆解：

**1. 机制对比剖析表**

| **维度**      | **路由选择 (Routing)**                     | **分组转发 (Forwarding)**           |
| :---------- | :------------------------------------- | :------------------------------ |
| **所属体系平面**  | **控制平面**（Control Plane）                | **数据平面**（Data Plane）            |
| **核心任务与目标** | 根据网络拓扑变化，动态计算出到达全网各目的地的最佳路径            | 将到达输入端口的 IP 数据报快速移动到正确的输出端口     |
| **处理实体与速度** | 路由处理机（CPU**软件**计算），速度较慢（毫秒~秒级）         | 交换结构（ASIC等**硬件**处理），速度极快（纳秒级）   |
| **核心数据结构**  | 维护**路由表**（包含代价、协议类型、定时器等复杂信息）          | 维护**转发表**（由路由表提取而来，仅含前缀、下一跳、端口） |
| **协议/算法支撑** | RIP (Bellman-Ford)、OSPF (Dijkstra)、BGP | 硬件查表算法、最长前缀匹配原则                 |

**2. 动态交互与数据流转图景**

当网络正常运转时，这两个平面是并行工作的。以下是分组在路由器中被转发时，数据平面的完整处理流向及协议首部状态变化：

1. **链路层接收与解封：** 路由器的物理层接收电信号，交由数据链路层。链路层检查 MAC 帧的目的 MAC 地址是否为本接口。若是，则剥离 MAC 首部和尾部（**解封**），将内部的 IP 数据报送至网络层的数据平面。
2. **IP 首部检查与查表（查转发表）：**
    - **提取目的 IP：** 网络层提取 IP 首部中的**目的 IP 地址**。
    - **硬件查表：** 在**转发表**（注意不是路由表）中利用**最长前缀匹配**寻找对应的输出端口和下一跳 IP 地址。
    - **更新 IP 首部：** 将 IP 首部中的 `TTL`（生存时间）字段减 1。由于首部发生改变，必须重新计算并更新 `首部检验和` 字段。
3. **链路层重新封装与发送：**
    - 网络层将更新后的 IP 数据报交递给选定的输出端口的数据链路层。
    - 通过 **ARP 协议** 查出下一跳 IP 对应的 MAC 地址。
    - **首部篡改（封装状态）：** 重新封装为新的 MAC 帧。此时，**源 IP 和目的 IP 保持不变**（端到端寻址），**源 MAC 变更为路由器该输出端口的 MAC 地址，目的 MAC 变更为下一跳设备的 MAC 地址**（点到点寻址）。

### 易错/易混点

- **混淆“路由表”与“转发表”（408 经典概念陷阱）：**
    - 在日常用语中，大家常说“路由器根据路由表转发分组”。但在 408 严格的考题中，路由器**控制平面**运行路由算法生成的是**路由表**；而实际指导**数据平面**快速移动数据报的直接依据是**转发表**。转发表是从路由表中提取出精华信息并针对硬件查找优化后生成的。
- **SDN（软件定义网络）中的割裂：**
    - 在传统路由器中，路由选择（控制平面）和分组转发（数据平面）物理上被集成在**同一台路由器设备**内部。
    - 但在 SDN 架构中，**控制平面被完全分离**，集中部署在远程的 SDN 控制器上（负责“路由选择”）；而底层的 SDN 交换机只保留了数据平面（仅负责简单的“分组转发”），它们之间通过 OpenFlow 等南向接口协议通信。

### 示例 / 推导 / 拓扑结构

**【路由选择与分组转发的协同推导场景】**

假设存在拓扑：`源主机A --- 路由器R1 --- 路由器R2 --- 目的主机B`。 突然，`R1` 到 `R2` 的主干链路光纤被挖断了，只能走备用链路 `R1 --- 路由器R3 --- 路由器R2`。

我们来看这两个功能是如何协同处理这次故障的：

1. **分组转发（面临失败）：**
    - 此时主机 A 发来一个目的 IP 为 B 的分组。`R1` 的数据平面查当前的转发表，发现下一跳还是 `R2`（主干链路的端口）。
    - 数据平面试图将分组从该端口发出去，但物理层链路断开，发送失败，此时转发表无法自己找新路。
2. **路由选择（介入救场，重新画图）：**
    - `R1` 的控制平面（OSPF 协议）迟迟收不到 `R2` 的 Hello 报文，确认链路断开。
    - 控制平面立即触发 LSU 链路状态更新，并向全网洪泛。
    - `R1` 的 CPU 重新运行 Dijkstra 算法（**路由选择过程**），计算出到达 B 的新最优路径是途径 `R3`。
3. **转发表更新与恢复转发：**
    - 控制平面将新路径 `(目的网络B，下一跳R3，对应端口)` 更新到自己的**路由表**中。
    - 随后，路由表立即将这条规则编译并下发给数据平面的**转发表**。
    - 当主机 A 再次发来分组时，`R1` 的数据平面极速查表（**分组转发过程**），顺利将其重新封装，从连接 `R3` 的物理端口发送出去。
