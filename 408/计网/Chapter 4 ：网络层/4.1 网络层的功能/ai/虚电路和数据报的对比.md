### 结论

在 408 计算机网络的考查体系中，**数据报服务（Datagram Service）**和**虚电路服务（Virtual Circuit Service）**是网络层向其上层（传输层）提供的两种截然不同的数据交付模式。

**数据报服务**的核心理念是“无连接与尽最大努力交付”，网络层只负责将分组送达，不保证可靠性和顺序，复杂性留给边缘的主机（这也是现代 Internet TCP/IP 体系的选择）。**虚电路服务**则借鉴了电信网的思路，核心理念是“面向连接与可靠交付”，在数据发送前必须先建立一条逻辑上的专用路径，由网络本身来保证数据的无差错和按序到达。

---

### 关键机制

这两种服务在底层数据流转和协议设计上有着本质差异，其核心机制拆解如下：

- **数据报服务（灵活自由的“盲发”）：**
    - **独立路由：** 发送方随时可以发送数据，无需预先建立连接。网络中的路由器将每个分组视为完全独立的个体，为其**独立地进行路由选择和查表转发**。
    - **全地址封装：** 因为没有上下文状态，每个分组的首部都必须携带**完整的目的地址和源地址**（如 IP 分组中的源/目的 IP 地址），这就导致了首部开销相对较大。
- **虚电路服务（严谨有序的“铺路”）：**
    - **三阶段交互：** 通信必须严格经历**“虚电路建立 $\rightarrow$ 数据传输 $\rightarrow$ 虚电路释放”**三个阶段。建立阶段会在源主机到目的主机之间规划出一条固定的逻辑路径。
    - **短标识符替换：** 只有在建立连接阶段的“呼叫请求”分组才需要携带完整的目的地址。一旦虚电路建立成功，后续传输的数据分组首部只需携带一个长度很短的**虚电路号（VCID）**，极大地减小了首部开销。
    - **固定路径：** 属于同一条虚电路的所有分组，将严格按照建立时所确定的那条同一路由进行转发，天然保证了按序到达。

### 易错/易混点

针对 408 命题陷阱，必须对以下“深坑”保持极高敏感度：

**1. “虚电路”与“电路交换”的本质混淆深坑**

- **陷阱：** 误认为虚电路就是物理层面的电路交换，独占了线路带宽。
- **避坑：** 必须严格界定！虚电路依然属于**分组交换**的范畴。它只是一条**逻辑上**的连接，物理链路的带宽依然是由穿过该链路的多条虚电路上的分组通过**统计复用（存储转发）**来共享的，并未独占物理信道。

**2. 可靠性的责任归属边界**

- **陷阱：** 认为只要应用层能可靠传输数据，底层的网络一定提供了虚电路服务。
- **避坑：** 这是 408 最常考的架构哲学。在**数据报网络（如 Internet）**中，网络层提供的是不可靠服务，**可靠性完全由网络边缘的端系统（如传输层的 TCP 协议）来负责**。而在**虚电路网络**中，由于沿途路由器会进行差错控制和流量控制，**可靠性是由通信子网（网络自身）来保证的**。

**3. 对网络故障的脆弱性倒挂**

- **陷阱：** 认为虚电路服务更高级，因此抗故障能力更强。
- **避坑：** 恰恰相反！数据报服务因为每个分组独立寻路，如果某台路由器宕机，后续分组可以**立刻动态切换到新路由**，适应性极强。而虚电路服务由于路径是固定绑定的，一旦路径中某个节点发生故障，**所有经过该节点的虚电路都将全部崩溃**，必须重新发起建立请求。

### 示例 / 推导 / 拓扑结构

**【表解】数据报服务 vs 虚电路服务全维对比**

在解答 408 综合选择题时，请直接映射以下核心对比维度：

| **维度**        | **数据报服务 (Datagram)**           | **虚电路服务 (Virtual Circuit)**   |
| ------------- | ------------------------------ | ----------------------------- |
| **工作基础**      | 分组交换                           | 分组交换                          |
| **连接的建立**     | **不需要**                        | **必须有**                       |
| **目的地址**      | 每个分组都有**完整的目的地址**              | 仅建立阶段使用，后续分组使用**虚电路号 (VCID)** |
| **路由选择**      | 每个分组**独立地**进行路由选择              | 属于同一条虚电路的分组按照**同一路由**转发       |
| **分组顺序**      | **不保证按序到达** (可能失序/重复)          | **保证按序到达**                    |
| **可靠性保证**     | 不保证可靠通信，可靠性**由用户主机来保证**        | 可靠性**由网络保证**                  |
| **对网络故障的适应性** | 出故障的节点丢失分组，其他分组可另寻路由，**适应能力强** | 所有经过故障节点的虚电路**均不能正常工作**       |

**【全景数据流转追踪：虚电路的跨节点交互图景】**

假设主机 A 要通过虚电路向主机 B 发送数据，其底层跨层/跨节点的序号流转过程如下：

1. **连接建立阶段（完整寻址）：** A 首先发出一个特殊的“呼叫请求”分组，该分组首部包含 B 的完整 IP 地址。网络中的各路由器根据路由算法将该分组一步步送达 B，并在沿途的每个路由器内部建立转发表项，为该逻辑连接分配一个本地的 **虚电路号（VCID）**。
2. **呼叫应答阶段：** 若 B 同意连接，则逆向返回一个“呼叫应答”分组，至此，一条贯穿全网的虚电路正式打通。
3. **数据传输阶段（短号匹配）：** A 开始发送真正的数据分组。此时，**A 不再将 B 的 IP 地址填入首部，而是仅仅填入第一跳路由器分配的 VCID**。
4. **路由器的逐跳转换：** 沿途的路由器在收到数据分组后，不再进行复杂的 IP 最长前缀匹配计算，而是直接根据到达端口和首部的 VCID 查虚电路表。找到下一跳端口后，**将当前的 VCID 替换为下一段链路的 VCID，并将其转发出去**（这种查表速度远快于数据报的 IP 路由查表）。
5. **连接释放阶段：** 数据传输完毕后，A 发送“释放请求”分组，沿途路由器逐个删除对应的虚电路表项，彻底释放该逻辑连接的资源。
