### 结论

在 408 计算机网络分层架构中，**复用（Multiplexing）**和**分用（Demultiplexing）**是实现多任务并发通信的核心机制。

简单来说：**复用**是指发送端多个高层实体（如多个应用进程）共同使用一个低层协议进行数据封装与发送（**“多对一”向下汇聚**）；**分用**是指接收端低层协议在解封报文后，能够准确地将数据分发给对应的高层实体（**“一对多”向上分派**）。这一机制在传输层（利用端口号）表现得最为典型，同时也贯穿于网络层和数据链路层。

---

### 关键机制

复用和分用的核心依赖于各层报文首部中的**服务访问点（SAP）**字段。以最典型的传输层为例，其动态交互与数据流转过程如下：

1. **应用层生成数据（无封装）：** 发送端主机上同时运行着多个应用进程（如 Web 浏览器的 HTTP 进程，和正在后台下载文件的 FTP 进程），它们分别生成各自的应用层报文。
2. **传输层复用（下行封装）：**
    - 传输层（TCP 或 UDP）从不同的应用进程套接字（Socket）收集数据。
    - **封装状态：** 加上传输层首部，生成 `[ 源端口 (标识发送进程) | 目的端口 (标识接收进程) | 应用层数据 ]` 的报文段。尽管来自不同的进程，但这些报文段都被统一交递给下层的网络层（IP 协议）。
3. **网络层复用（下行封装）：**
    - 网络层不仅接收 TCP 报文段，还可能接收 UDP 报文段或 ICMP 报文。
    - **封装状态：** 加上 IP 首部，生成 `[ 协议字段 (如 6 代表 TCP，17 代表 UDP) | 源 IP | 目的 IP | 传输层报文段 ]`。此时所有的流量被复用成单一的 IP 数据报流，发往数据链路层。
4. **接收端网络层分用（上行解封）：**
    - 接收端网络层收到 IP 数据报，检查首部中的 `目的 IP` 是否为本机，若是则**解封**剥离 IP 首部。
    - **分用决策：** 提取 IP 首部中的 **`协议`** 字段。如果值为 6，就将解封后的载荷（数据部分）向上定向分派给 TCP 模块；如果为 17，则分派给 UDP 模块。
5. **接收端传输层分用（上行解封）：**
    - TCP 或 UDP 模块收到报文段后，**解封**剥离传输层首部。
    - **分用决策：** 提取传输层首部中的 **`目的端口`** 字段（如 80 或 21），准确地将应用层数据分发给监听该端口的 Web 进程或 FTP 进程。

---

### 易错/易混点

- **TCP 分用 vs UDP 分用的核心差异（408 必考高频陷阱）：**
    - **UDP（无连接分用）：** 仅根据 **二元组 {目的 IP，目的端口}** 来进行分用。如果两个不同的源主机向服务器的同一个目的 IP 和目的端口发送 UDP 报文，这两个报文会被分派到服务器上的**同一个**套接字（进程）中。
    - **TCP（面向连接分用）：** 必须根据 **四元组 {源 IP，源端口，目的 IP，目的端口}** 来进行分用。即使目的 IP 和目的端口完全相同（例如多个客户端同时访问服务器的 80 端口），只要源 IP 或源端口不同，TCP 就会将它们分派到**不同的**连接套接字中，由并发服务器的不同线程/进程来处理。
- **各层的“分用标识符（SAP）”混淆：**
    - 经常有题目偷换概念，需牢记：链路层的分用看**类型（Type）**，网络层的分用看**协议（Protocol）**，传输层的分用看**端口（Port）**。

### 示例 / 推导 / 拓扑结构

**【协议对比：各层复用/分用机制剖析表】**

为了彻底透析分层架构中的复用分用原理，我们将其在底层到高层的实现进行对比：

|**维度**|**数据链路层**|**网络层**|**传输层**|
|:--|:--|:--|:--|
|**工作层次**|第二层（点到点/多点）|第三层（主机到主机）|第四层（进程到进程）|
|**服务访问点 (SAP)**|MAC 帧首部中的 **类型 (Type)** 字段|IP 数据报首部中的 **协议 (Protocol)** 字段|TCP/UDP 首部中的 **端口 (Port)** 字段|
|**复用/分用对象**|区分上层是 IPv4、IPv6 还是 ARP 协议|区分上层是 TCP、UDP 还是 ICMP、OSPF 等协议|区分上层是 HTTP、FTP、DNS 等不同的应用进程|
|**典型字段值**|`0x0800` (IPv4) `0x0806` (ARP)|`6` (TCP) `17` (UDP) `1` (ICMP)|`80` (HTTP) `53` (DNS)|

**【主机并发通信拓扑推导】**

假设你的电脑（IP: `192.168.1.100`）正在同时进行两项操作：

1. 使用浏览器（分配源端口 `50001`）访问百度 Web 服务器（目的端口 `80`，TCP）。
2. 后台程序（分配源端口 `50002`）正在向 DNS 服务器请求域名解析（目的端口 `53`，UDP）。

- **发送时的复用推导：** 浏览器的 HTTP 数据加上 TCP 首部（源 `50001`，目的 `80`）；DNS 请求加上 UDP 首部（源 `50002`，目的 `53`）。这两个传输层报文向下汇聚到 IP 层，IP 层为它们分别加上 IP 首部（一个协议字段填 `6`，一个填 `17`），复用同一张网卡发往以太网。
- **接收时的分用推导（以收到百度 Web 响应为例）：** 你的网卡收到 MAC 帧，查 `Type=0x0800`，剥离 MAC 帧交给 IP 层；IP 层查 `Protocol=6`，剥离 IP 首部交给 TCP 模块；TCP 模块查目的端口是 `50001`（你的浏览器发送时用的源端口，在响应中变成目的端口），最终将网页数据精准无误地交给了你的浏览器进程，而不会错发给 DNS 后台程序。
