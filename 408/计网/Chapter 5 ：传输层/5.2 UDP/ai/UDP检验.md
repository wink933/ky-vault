你好！我是你的**“408 计算机网络复习助手”**。

UDP 作为一种无连接、尽最大努力交付的传输层协议，虽然本身不保证可靠性，但它提供了基本的**差错检测**机制。408 考试中，UDP 检验和的计算过程及其与“伪首部”的关系是高频考点。下面我将为你详细拆解 UDP 的检验过程。

### 结论

UDP 检验和的核心在于：它不仅检验 **UDP 首部**，还跨层检验 **UDP 用户数据** 以及提取自 IP 首部的 **12B 伪首部**，采用 **16 位字长的二进制反码求和再取反** 的算法来实现端到端的差错控制。

---

### 关键机制

- **伪首部（Pseudo-header）的构造：** 为了确保 UDP 数据报确实是发送给本机的，且协议类型正确，UDP 检验时会临时构造一个 12B 的伪首部。
    - 源 IP 地址（4B）：来自网络层。
    - 目的 IP 地址（4B）：来自网络层。
    - 全 0 字段（1B）。
    - 协议字段（1B）：UDP 的协议号为 `17`。
    - UDP 长度（2B）：即 UDP 首部长度与数据长度之和。
- **全覆盖检验：** 不同于 IP 首部只检验首部，UDP 的检验范围是：`伪首部 + UDP 首部 + 数据`。
- **字节填充：** 由于检验是基于 16 位字（即 2 字节）进行的，若 UDP 报文的数据部分为奇数个字节，必须在末尾**临时填充一个全 0 字节**。

---

### 动态交互过程（UDP 差错检测全流程）

**1. 发送方（封装与计算过程）**

1. **添加伪首部**：在封装好的 UDP 报文前面，临时加上 12B 的伪首部。
2. **补齐偶数**：如果 `UDP 报文长度（首部+数据）` 是奇数，就在末尾追加一个全 0 的字节（该字节不发送）。
3. **重置字段**：将 UDP 首部中的“检验和”字段初始化为全 0。
4. **反码求和**：将上述构成的整个序列按 16 位为一个字段切分。从低位到高位按二进制进行加法运算：若最高位产生进位，则将**进位加到最低位**（此为二进制反码求和的规则）。
5. **结果取反**：对上一步求和得到的 16 位最终结果按位取反，将其填入 UDP 首部中的“检验和”字段。
6. **剥离下发**：去除临时的伪首部和填充的 0 字节，将真正的 UDP 数据报交付给网络层封装入 IP 分组。

**2. 接收方（解封与校验过程）**

1. **重构伪首部**：从收到的 IP 数据报首部提取源/目的 IP 等信息，重新构造出 12B 的伪首部并附在收到的 UDP 报文前。
2. **补齐偶数**：若数据不是偶数个字节，同样在末尾补上 1 个全 0 字节。
3. **反码求和**：按 16 位字长对所有内容（包含重构的伪首部、UDP 首部、其中已有的检验和、数据、填充字节）进行二进制反码求和。
4. **无错判定**：如果传输过程中没有发生比特反转，所有的比特相加后的结果应该为**全 1**（即 `11111111 11111111`）。
5. **处理决策**：若结果不为全 1，说明报文在传输中出现差错，接收方通常会**直接丢弃**该 UDP 数据报（少数实现可能会交付给应用层，但附带错误警告）。

### 协议对比辨析

| **维度**   | **IP 头部检验和**          | **UDP 检验和**                    |
| -------- | --------------------- | ------------------------------ |
| **工作层次** | 网络层 (层 3)             | 传输层 (层 4)                      |
| **检验范围** | **仅检验 IP 首部**，不包括数据部分 | **伪首部 + UDP 首部 + 数据**          |
| **是否强制** | IPv4 中强制要求            | IPv4 中**可选**（不用时填全 0）；IPv6 中强制 |
| **主要目的** | 防止路由器因首部错误导致路由转发错误    | 防止端到端传输中数据损坏，验证目的 IP 投递正确      |
|          |                       |                                |

### 易错/易混点高感度提示

1. **陷阱：伪首部的去向**
    - **避坑：** 伪首部**既不向下传送给网络层，也不向上递交给应用层**。它仅仅是一个“逻辑结构”，专门为了在传输层计算检验和时防范“IP 路由投递错误”而设计的临时护身符。
2. **陷阱：不使用检验和的表示方法**
    - **避坑：** 如果发送方不想计算检验和，会将该字段填为 `0000`。如果发送方真实计算出的检验和恰好全为 0，为了与“未启用检验和”区分，它会将检验和字段填为**全 1**（在反码运算中，全 0 和全 1 的数值意义等价）。
3. **计算陷阱：进位的回卷 (Wrap-around)**
    - **避坑：** 在进行二进制反码加法时，如果最高位溢出产生进位 1，**绝对不能舍弃**，必须把它加回到结果的最末尾（最低位）。

---

### 示例 / 推导（反码求和具体算例）

为量化这一计算过程，我们假设需要进行检验的二进制字列简值如下（以三个 16 位字为例）：

- 第 1 个字：`01100110 01100000`
- 第 2 个字：`01010101 01010101`
- 第 3 个字：`10001111 00001100`

**第一步：前两个字相加**

```
  01100110 01100000
+ 01010101 01010101
-------------------
  10111011 10110101  (无最高位进位)
```

**第二步：将结果与第三个字相加**

```
  10111011 10110101
+ 10001111 00001100
-------------------
 01001010 11000001  (最高位产生了进位 1)
```

由于产生了进位，需要发生**进位加至最低位（回卷）**：

```
  01001010 11000001
+                 1
-------------------
  01001010 11000010  (反码求和的最终和)
```

**第三步：取反得到最终的检验和** 对上述结果按位取反得到待发送的检验和： `10110101 00111101`

接收端在收到报文后，会将第1、2、3字加上此检验和一起进行反码求和，只要传输无错，最后必然得到全 `1` 的结果。
