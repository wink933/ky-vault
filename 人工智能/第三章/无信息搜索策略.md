在4月19日的期中考试中，第三章的“无信息搜索（Uninformed Search，也称盲目搜索）”是必考的基础大题和理论辨析核心。无信息搜索指的是：除了问题定义中提供的状态信息外，没有任何附加信息。算法只能生成后继并区分状态是不是目标状态，无法比较非目标状态的好坏。

为了应对考试，你必须将以下五种核心无信息搜索策略的**完备性**、**最优性**、**时间复杂度**与**空间复杂度**形成肌肉记忆，这是图3.21性能比较表中的绝对重点。

### 1. 宽度优先搜索 (Breadth-First Search, BFS)

- **机制**：总是先扩展深度最浅的未扩展结点，通常使用 FIFO（先进先出）队列实现。
- **完备性**：**完备**（假设分支因子 $b$ 是有限的）。
- **最优性**：**最优**（当且仅当所有单步行动代价相同时）。
- **时间复杂度**：$O(b^d)$，其中 $d$ 是最浅目标结点的深度。
- **空间复杂度**：**$O(b^d)$**。指数级的内存需求是 BFS 在实际应用中比执行时间更令人头疼的致命缺陷。

### 2. 一致代价搜索 (Uniform-Cost Search, UCS)

- **机制**：扩展路径消耗 $g(n)$ 最小的结点，通过将边缘结点集组织成按 $g$ 值排序的优先级队列来实现。
- **完备性**：**完备**（前提是每步代价都大于等于某个正的常数 $\epsilon$）。
- **最优性**：**最优**（对于任何一般的步骤代价而言）。
- **时间复杂度与空间复杂度**：均为 __$O(b^{1+\lfloor C^_/\epsilon \rfloor})$_*，其中 $C^*$ 是最优解的代价。当所有单步耗散相等时，它与 BFS 类似，但它由于要在所有深度检查最优代价，可能会比 BFS 略多做一些无意义的工作。

### 3. 深度优先搜索 (Depth-First Search, DFS)

- **机制**：总是扩展搜索树的当前边缘结点集中最深的结点，使用 LIFO（后进先出，即栈）队列实现。
- **完备性**：**不完备**（在树搜索版本中会陷入死循环，在无限状态空间中即使是图搜索也会失败）。
- **最优性**：**不最优**。
- **时间复杂度**：$O(b^m)$，其中 $m$ 是搜索树的最大深度。在最坏情况下极高。
- **空间复杂度**：**$O(bm)$**。这是 DFS 的巨大优势，它具有线性的空间复杂度，所需内存极小。

### 4. 深度受限搜索 (Depth-Limited Search, DLS)

- **机制**：为了避免 DFS 陷入无穷路径，为搜索设置一个深度界限 $l$，深度为 $l$ 的结点被当作没有后继对待。
- **完备性**：**不完备**（如果最浅解的深度 $d > l$）。
- **最优性**：**不最优**（如果 $d < l$）。
- **时间复杂度**：$O(b^l)$。
- **空间复杂度**：$O(bl)$。

### 5. 迭代加深的深度优先搜索 (Iterative Deepening Search, IDS)

- **机制**：结合了 BFS 和 DFS 的优点，不断增大深度限制（先为0，接着为1，依此类推）来调用深度受限搜索，直到找到目标。
- **完备性**：**完备**（当 $b$ 有限时）。
- **最优性**：**最优**（当单步代价相同时）。
- **时间复杂度**：**$O(b^d)$**。虽然上层结点会被重复生成多次，但绝大多数结点在底层，额外代价不大。
- **空间复杂度**：**$O(bd)$**。保持了 DFS 的线性内存优势。**一般来讲，当搜索空间较大且不知道解所在深度时，迭代加深搜索是首选的无信息搜索方法**。

### 【期中考试解题实战：一致代价搜索 (UCS) 步骤推导】

**核心考点陷阱**：在 UCS 中，目标测试必须应用于**结点被选择扩展时**，而不是在结点生成时。如果一个目标结点在生成时就被检测并直接返回，可能会找到一条次优路径。

**经典考题推导**：基于罗马尼亚地图，模拟一致代价搜索从 Sibiu 到 Bucharest 的执行过程（假设到达目标前的局部状态空间）：

- 已知代价：Sibiu -> Rimnicu Vilcea (80); Sibiu -> Fagaras (99); Rimnicu Vilcea -> Pitesti (97); Fagaras -> Bucharest (211); Pitesti -> Bucharest (101)。

**Step-by-step 推导过程**：

1. **初始状态**：将起点 Sibiu 放入边缘优先级队列（Frontier）。`Frontier = {Sibiu (0)}`
2. **第一次选择**：弹出 Sibiu（0），进行扩展。生成后继 Rimnicu Vilcea 和 Fagaras。 `Frontier = {Rimnicu Vilcea (80), Fagaras (99)}`
3. **第二次选择**：弹出当前 $g$ 值最小的结点 Rimnicu Vilcea (80)，进行目标测试（否）。扩展它，生成 Pitesti（80 + 97 = 177）。 `Frontier = {Fagaras (99), Pitesti (177)}`
4. **第三次选择**：弹出当前最小结点 Fagaras (99)，目标测试（否）。扩展它，生成目标结点 Bucharest（99 + 211 = 310）。 _注意：此时目标结点已生成，但算法绝不停止！必须将其放入队列。_ `Frontier = {Pitesti (177), Bucharest (310)}`
5. **第四次选择**：弹出 Pitesti (177)，目标测试（否）。扩展它，生成到达 Bucharest 的新路径（177 + 101 = 278）。 _发现新路径代价 (278) < 队列中老路径代价 (310)，执行替换。_ `Frontier = {Bucharest (278)}`
6. **第五次选择**：弹出 Bucharest (278)。**此时进行目标测试，发现是目标结点，算法终止并返回最优解。**
