
同学你好！距离4月19日的期中考试越来越近了。**真空吸尘器世界（Vacuum World）** 是这门课程中最经典的“玩具问题”（Toy Problem），它贯穿了从第一部分“智能Agent设计”到第二部分“问题求解与搜索”的多个核心章节。

为了帮你高效拿分，我们把这个场景在期中考试里可能出现的**三大核心考点**一次性彻底打通：

### 🎯 考点一：智能Agent的设计与分析（对应第2章）

在考试的简答题中，出题老师常要求你对真空吸尘器进行环境分析和Agent设计。

1. **PEAS 描述**：
    - **P（性能度量）**：例如每清理一个方格奖励1分，或者统计8小时内清理的灰尘总量。
    - **E（环境）**：只有两个地点：方格A和方格B。
    - **A（执行器）**：向左移动（Left）、向右移动（Right）、吸尘（Suck）、无操作。
    - **S（传感器）**：感知Agent所处的位置以及该位置是否有灰尘（例如感知输入为 `[A, Dirty]`）。
2. **简单反射型Agent设计**： 在完全可观察环境下，吸尘器的Agent程序可以极度精简为基于当前感知的“条件-行为规则（if-then rules）”。
    - **实战代码表达**：`if status = Dirty then return Suck`；`else if location = A then return Right`；`else if location = B then return Left`。

### 🎯 考点二：经典搜索问题的精确形式化（对应第3章）

如果题目要求你“对真空吸尘器问题进行形式化”，你必须在试卷上写出以下5个标准组成部分（这是**必考的大题步骤**）：

1. **状态（State）**：由Agent的位置（2个）和灰尘的分布情况（$2^2=4$个）共同确定，因此状态空间总共有 $2 \times 4 = 8$ 个可能的世界状态。
2. **初始状态（Initial state）**：8个状态中的任意一个都可以被设为初始状态。
3. **行动（Actions）**：在每个状态下可执行的动作集合，即 `Left`, `Right`, `Suck`。
4. **转移模型（Transition model）**：描述行动的后果。例如，在最左边（方格A）执行 `Left`，Agent会保持在原地；在有灰尘的位置执行 `Suck` 会使该位置变干净。
5. **目标测试（Goal test）**：检测所有位置（方格A和B）是否都已经干净。
6. **路径耗散（Path cost）**：每执行一步行动，耗散值为1。整个解路径的耗散值就是路径中的行动步数。

### 🎯 考点三：非确定性与无感知环境进阶（对应第4章，压轴难点）

当环境变得复杂时，吸尘器世界会作为考察高阶搜索算法的背景：

1. **不稳定的吸尘器（非确定性环境）**：
    
    - **情景**：假设吸尘器出故障了，在干净的区域执行 `Suck` 可能会把脏东西掉在地毯上。
    - **解题方法**：此时不能用普通的BFS/DFS，必须使用**与或搜索树（AND-OR graphs）**。Agent的行动形成“或结点”，环境的随机反馈形成“与结点”。
    - **解的特性**：此时的解不再是一个固定的动作序列，而是一个**条件规划（Conditional plan）**（包含 if-then-else 分支），例如 `[Suck, if State = 5 then [Right, Suck] else []]`。
2. **无传感器吸尘器（无观察信息的搜索）**：
    
    - **情景**：Agent的传感器坏了，感知不到任何信息（相容问题）。
    - **解题方法**：Agent必须在**信念状态（Belief State）**空间中搜索。初始信念状态包含了所有8个可能的物理状态。
    - **推导实战**：通过执行特定的“强制性动作序列”（如 `[Right, Suck, Left, Suck]`），不论Agent最初在哪里，也不管灰尘原本怎么分布，Agent都能盲操迫使世界转移到全干净的目标状态。这种设计体现了AI在极端不确定下的问题求解能力。
