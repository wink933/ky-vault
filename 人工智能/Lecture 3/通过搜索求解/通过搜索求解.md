
在第3.3节“通过搜索求解”中，教材详细探讨了如何利用搜索算法寻找从初始状态到目标状态的行动序列。为了应对4月19日的期中考试，你必须牢牢掌握以下核心概念、算法评价标准，以及标准图搜索算法的执行推导步骤。

### 🎯 核心考点一：状态与结点的本质区别（易考概念辨析）

在考试中，必须严格区分“状态（State）”和“结点（Node）”：

- **状态（State）**：对应于问题世界的一个物理配置情况（即客观存在的局面）。
- **结点（Node）**：是搜索算法在构造搜索树时使用的数据结构。一个结点包含四个核心元素：
    1. `STATE`：对应的状态空间中的状态。
    2. `PARENT`：生成该结点的父结点。
    3. `ACTION`：父结点生成该结点时所采取的行动。
    4. `PATH-COST`（通常用 $g(n)$ 表示）：从初始状态到达该结点的路径消耗。

### 🎯 核心考点二：树搜索与图搜索的区别

搜索算法的基本过程是从初始状态的根结点出发，不断“扩展（Expand）”状态（即应用合法行动生成新的子结点），并将其加入“边缘（Frontier/Open List）”中等待后续探索。

- **树搜索（Tree-Search）**：不记录历史，可能会反复探索**冗余路径（Redundant paths）**或陷入**有环路径（Loopy paths / 死循环）**。
- **图搜索（Graph-Search）**：为了避免重复历史，图搜索增加了一个名为**探索集（Explored set / Closed 表）**的数据结构，用来记录每个已经扩展过的结点。如果新生成的结点与探索集或边缘集中的某个结点状态匹配，就会被直接丢弃。

### ⚠️ 核心考点三：搜索算法的四大性能评价标准（必考大题分析点）

在分析任何搜索算法（如BFS、DFS、A*等）时，你必须根据以下四个维度进行评价，并理解其复杂度变量 $b$（分支因子）、$d$（最浅目标结点的深度）、$m$（状态空间中路径的最大长度）：

1. **完备性（Completeness）**：当问题有解时，算法是否能保证找到解？
2. **最优性（Optimality）**：算法是否能找到路径耗散最小的最优解？
3. **时间复杂度（Time Complexity）**：找到解需要花费多长时间？（通常由搜索过程中产生的结点数目来度量）。
4. **空间复杂度（Space Complexity）**：在执行搜索的过程中需要多少内存？（通常由内存中存储的最多结点数来度量）。

### 📝 解题实战：一步步（Step-by-step）推导图搜索算法执行过程

在期中考试的计算题中，经常会要求你模拟搜索算法的扩展步骤。以下是标准的**图搜索（Graph-Search）**算法推导过程，请在做题时严格遵循这5个步骤不断循环，直到找到解：

**初始准备阶段：**

- **Step 1**：利用问题的初始状态建立一个根结点，将其加入到边缘集（Frontier）中。
- **Step 2**：初始化探索集（Explored set / Closed 表）为空集。

**循环探索阶段：**

- **Step 3（判空测试）**：检查边缘集是否为空。如果边缘集为空，说明所有可达状态均已探索完毕，直接返回失败（Failure）。
- **Step 4（选择与目标测试）**：根据特定的搜索策略（如FIFO、LIFO或优先级队列），从边缘集中选出一个叶结点并将其移除。立刻对该结点进行**目标测试**（注意：一般图搜索是在结点被选择扩展时进行目标测试）。如果该结点包含目标状态，则返回相应的解。
- **Step 5（加入探索集与扩展）**：
    1. 将刚刚选出的结点状态加入到**探索集（Explored set）**中。
    2. 扩展该选中的结点，生成其所有可能的后继子结点。
    3. **【核心查重步骤】**：对于每一个新生成的后继子结点，**仅当其状态既不在边缘集（Frontier）中，也不在探索集（Explored set）中时**，才将其加入到边缘集中等待未来的扩展。

掌握了这套图搜索的防重复机制和结点的扩展逻辑，你就为接下来推导宽度优先（BFS）、深度优先（DFS）、一致代价搜索（UCS）和A*搜索的搜索树画法打下了最坚实的基础。
