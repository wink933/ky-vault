### 🎯 核心考点一：问题形式化与“解”的本质转变（必考概念辨析）

在经典搜索中，环境是确定的，行动只会产生唯一结果，因此“解”是一个固定的行动序列。但在不确定环境中，这被彻底颠覆：

1. **转移模型的改变**：在不确定性环境中，`RESULT(s, a)` 函数不再返回单一状态，而是返回**一组可能的状态**。
2. **解的形式的改变**：因为无法预知未来（如吸尘器吸尘后可能把其他地方弄干净，也可能把脏东西掉出来），Agent的未来行动必须依赖于未来的感知信息。因此，问题的解不再是一个序列，而是一个**应急规划（Contingency Plan，也称策略）**。
3. **代码表达（实战得分点）**：应急规划表现为包含 `if-then-else` 语句的嵌套结构（它本质上是一棵树而不是序列）。例如：`[Suck, if State = 5 then [Right, Suck] else []]`。

### 🎯 核心考点二：与或搜索树（AND-OR Search Trees）的构造（大题画图核心）

遇到不确定性问题，普通的搜索树就不够用了，必须画**与或搜索树**。在考试画图或简答时，必须严格区分并标明两类结点：

1. **或结点（OR node）**：由 Agent 在每个状态下的“选择”形成（例如选择执行 `Left`、`Right` 或 `Suck`）。
2. **与结点（AND node）**：由环境的非确定性反馈（即行动的每个可能后果）形成。

**【考场必背：什么是与或树的有效解？】** 如果题目问“如何判断这棵与或树找到了解”，请直接默写以下三个条件：

1. 解的每个叶子上都必须是**目标结点**。
2. 在每个**或结点**上，必须规范一个特定的行动（只选一条分支）。
3. 在每个**与结点**上，必须包含该行动的**所有可能后果**（即保留所有环境反馈的分支）。

### 🎯 核心考点三：算法特性与循环死胡同处理（高阶分析题）

在算法特性分析中，不确定性环境引入了极其棘手的“环（Loop）”问题。

- **完备性保证（查重机制）**：如果在搜索中，当前状态与从根结点出发的某条路径上的状态相同，算法必须**返回失败**。通过这种路径上的历史检查，可以保证算法在任何有限的状态空间内终止，从而保证完备性（理由是每条路径必定到达目标、死胡同或遇到重复状态）。
- **注意陷阱**：算法只检查“当前路径上的祖先”，并不检查“从根出发的其他路径上的重复状态”，因为在不确定性问题中，从当前状态出发也许没有解，但这不意味着从另一个历史分支到达该状态时也没有解。

### 📝 解题实战：处理“不断尝试”的循环解（Step-by-step）

**考题模拟**：假设吸尘器的移动动作（如 `Right`）是不稳定的，有时会失败导致留在原地。此时与或树会返回失败吗？如何表示它的解？

**【标准推导步骤】**：

1. **识别循环**：因为行动不稳定，单纯的与或图深度优先搜索在遇到原地不动的重复状态时会返回失败，此时不存在非循环解。
2. **引入标签（Label）改写规划**：只要非确定的行动最终总会生效（如试错多次总能成功移动），我们可以在规划中添加一个标签（如 $L_1$）来表示一直尝试直到成功。
3. **写出最终解的表达式**：在试卷上，把解写成带有循环跳转的形式： `[Suck, L1: Right, if State = 5 then L1 else Suck]`。 _(也可以写成更好理解的语法：`while State = 5 do Right`)_。
