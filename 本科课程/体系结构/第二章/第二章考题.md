### 📝 第一部分：《2025年春季期末A卷》真题解答

#### 1. M3 跨架构兼容性问题（第 4 题第 2 小问，3分）

**题目**：假设有个针对 X86 的 Win 10 开发的英雄联盟游戏安装包，在苹果 M3 Mac pro 上安装 ARM 版 Win 10 系统后，该游戏安装包能否正常执行？为什么？ **解答**：

- **结论**：**不能在硬件上“原生（Native）”执行，但可以通过操作系统层面的“二进制翻译/仿真器（Emulator）”正常运行**。
- **原因剖析**：从指令集架构（ISA）的底层来看，该游戏基于的 **X86 属于 CISC（复杂指令集）**架构，而苹果 M3 芯片基于的 **ARM 属于 RISC（精简指令集）**架构。两者的指令编码格式、寻址方式、通用寄存器模型和机器状态完全不同，缺乏底层的二进制兼容性，因此 M3 的硬件译码器无法直接读懂 X86 的机器码。必须依赖 Windows on ARM 内置的 x86 仿真翻译层（类似于苹果 macOS 的 Rosetta 2 技术），在软件层面将 X86 指令动态翻译成 ARM 指令后才能执行。

#### 2. 大立即数的编译处理（第 5 题第 1 小问，2分）

**题目**：已知某 RISC 仅支持立即数为 12bit 的加法操作，现有一个语句：`int A=B+1000000`；问编译器要如何编译该语句？ **解答**：

- **推导**：因为 $1000000$ 的二进制表示需要至少 20 位有效位，超出了 12 位有符号立即数（最多只能表示 $-2048 \sim 2047$）的范围，所以单条指令无法装下这个常数。
- **编译策略**：编译器必须将其拆分为多条指令（通常为两条）来协同完成。
    1. 先使用一条**装载高位立即数指令**（例如 RISC-V 中的 U 型指令 `LUI`），将 $1000000$ 的高位部分装载到一个临时的通用寄存器中。
    2. 再使用一条**常规的加法指令**（例如 I 型指令 `ADDI`），将该临时寄存器、剩余的低位立即数部分以及寄存器 B 的值进行累加，最后将结果写回 A 所在的寄存器。

#### 3. 指令最小编码长度计算（第 5 题第 2 小问，3分）

**题目**：在某 RISC 处理器中，有 63 条指令，支持 64 个寄存器。指令集包括 `Add R1，R2，R3` 等三元操作数指令。问算术指令编码指令的最小长度是多少，为什么？ **解答**：

- **结论**：最小长度为 **24 bit**。
- **计算原因**：
    1. **操作码（Opcode）**：要区分 63 条不同的指令，至少需要 $\lceil \log_2 63 \rceil = 6$ 位的操作码字段。
    2. **寄存器操作数（Operand）**：要寻址 64 个通用寄存器，每个寄存器编号至少需要 $\lceil \log_2 64 \rceil = 6$ 位。
    3. **三元操作数总长**：因为包含 `Add R1，R2，R3` 这样的指令（1 个目的寄存器，2 个源寄存器），所以需要 $3 \times 6 = 18$ 位的操作数字段。
    4. **总和**：$6 \text{ (Opcode)} + 18 \text{ (Operands)} = 24 \text{ bit}$。

#### 4. 四种经典 ISA 架构的汇编编写（第 5 题第 3 小问，5分）

**题目**：写出四种处理器完成计算 `X = (A+C)×B+(B×C+B)/D` 的指令级别汇编代码（假设变量全在内存）。 **解答**： _(为保持严谨，使用常规 Load/Store、Add/Sub/Mul/Div、Push/Pop 指令)_

**(1) 累加器架构 (Accumulator)** —— 隐式使用单个 AC，通常借助临时内存变量 $T1, T2$ 暂存。

```
Load B       ; AC = B
Mul C        ; AC = B * C
Add B        ; AC = B * C + B
Store T1     ; 暂存 (B*C+B) 到 T1
Div D        ; AC = (B*C+B) / D
Store T2     ; 暂存右半部分到 T2
Load A       ; AC = A
Add C        ; AC = A + C
Mul B        ; AC = (A+C) * B
Add T2       ; AC = (A+C)*B + (B*C+B)/D
Store X      ; 存回 X
```

**(2) 堆栈架构 (Stack)** —— 操作数隐式在栈顶，后缀表达式思维。

```
Push A
Push C
Add          ; 栈顶为 (A+C)
Push B
Mul          ; 栈顶为 (A+C)*B
Push B
Push C
Mul          ; 栈内顶部为 B*C
Push B
Add          ; 栈内顶部为 (B*C+B)
Push D
Div          ; 栈内顶部为 (B*C+B)/D
Add          ; 栈顶为 (A+C)*B + (B*C+B)/D
Pop X        ; 弹出至 X
```

**(3) 寄存器-内存架构 (Register-Memory)** —— ALU 指令允许一个操作数来自内存。

```
Load R1, A   ; R1 = A
Add R1, C    ; R1 = A + C
Mul R1, B    ; R1 = (A+C) * B
Load R2, B   ; R2 = B
Mul R2, C    ; R2 = B * C
Add R2, B    ; R2 = B * C + B
Div R2, D    ; R2 = (B*C+B) / D
Add R1, R2   ; R1 = (A+C)*B + (B*C+B)/D
Store X, R1
```

**(4) 寄存器-寄存器架构 (Load/Store)** —— 运算只能在通用寄存器间进行。

```
Load R1, A
Load R2, C
Load R3, B
Load R4, D
Add R5, R1, R2   ; R5 = A + C
Mul R6, R5, R3   ; R6 = (A+C) * B
Mul R7, R3, R2   ; R7 = B * C
Add R8, R7, R3   ; R8 = B*C + B
Div R9, R8, R4   ; R9 = (B*C+B) / D
Add R10, R6, R9  ; R10 = Result
Store X, R10
```

### 📝 第二部分：《2024年期末考试回忆版》真题解答

#### 5. R-R型比 R-M型有优越性判断题（第 2 题局部）

**题目**：判断“R-R型（寄存器-寄存器型）比R-M型（寄存器-内存型）有优越性”并解释。 **解答**：

- **判断**：**正确**。
- **解释**：R-R型（即 Load/Store 架构）将访存操作与算术逻辑运算进行了严格分离。这种设计的优越性在于：它使得指令的格式高度规整、指令长度固定，极大地简化了硬件译码器的设计；同时，因为所有 ALU 运算指令只在寄存器之间进行，不涉及不可预测的内存访问延迟，所以这些指令的执行周期通常非常短且固定，这使得它**完美适配现代计算机的流水线设计**（极大地减少了结构冒险和数据冒险导致的流水线停顿）。

#### 6. 寻址方式与 ISA 设计正交性原则（第 9 题，10分）

**题目**：(1) 你都知道哪些寻址方式？ (2) 怎么理解 ISA 设计的正交性原则。 **解答**：

- **(1) 常见寻址方式罗列**：在 ISA 体系中常见的寻址方式包括：寄存器寻址（操作数在寄存器中）、立即数寻址（操作数在指令编码中）、偏移/位移寻址（基址寄存器+常数偏移）、寄存器间接寻址、绝对寻址、变址寻址（基址+变址）、比例变址寻址以及后递增/前递减寻址等。
- **(2) 理解正交性原则（Orthogonality）**：在 ISA 设计中，正交性意味着**指令的操作码（Opcode）、寻址方式（Addressing Modes）以及数据类型（Data Types）可以相互独立地进行自由组合**，而没有任何特殊的捆绑限制或人为制约。 例如，任何一条通用运算指令（如 ADD 或 SUB）都可以任意使用上述的立即数、偏移寻址或寄存器间接寻址，并作用于任何一个通用寄存器。**正交设计的最大好处是**：它使得指令集的底层编码更加规整统一，极大地降低了编译器的开发难度（编译器无需专门记忆“某个寄存器只能配合某种指令”这种特例），同时也提高了硬件硬布线控制器译码的效率。
