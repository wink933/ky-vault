## 📅 Day 1：定量分析基础与部件加速比（定量设计）

### 1. CPU 性能通用公式与 CPI 深度分析

在定量设计中，CPU 执行时间（T_{CPU}）是衡量性能的最核心指标。

- **综合公式**：$T_{CPU} = IC \times CPI \times T_{Clock}$ 其中，IC 为指令条数，CPI 为每条指令平均时钟周期数，T_{Clock} 为时钟周期时间（频率的倒数）。
- **第 i 类指令的平均时钟周期数公式**： $CPI = \frac{\sum_{i=1}^{n} (IC_i \times CPI_i)}{IC}$
- **性能影响因子对照矩阵**：

|   |   |   |   |
|---|---|---|---|
|层级|指令数 (IC)|平均时钟周期数 (CPI)|时钟周期 (T)|
|**程序 (Program)**|直接影响|间接影响|-|
|**编译器 (Compiler)**|直接影响|直接影响|-|
|**指令集架构 (ISA)**|直接影响|直接影响|间接影响|
|**微架构 (Microarchitecture)**|-|直接影响|直接影响|
|**工艺技术 (Technology)**|-|-|直接影响|

- **算法影响对比（Scoreboard vs. Tomasulo）**：
    - **Tomasulo 算法**：通过寄存器重命名消除 WAR 和 WAW 相关，允许指令更乱序地执行。相比记分牌，它能显著减小 **CPI**（减少了由于假相关导致的停顿），虽然硬件复杂度可能略微增加时钟周期 T，但总体执行时间通常变小。

### 2. Amdahl 定律与加速比手算

Amdahl 定律定义了对系统中某个部件改进后所能获得的整体加速比。

- **核心公式**：$S_{overall} = \frac{1}{(1 - F_e) + \frac{F_e}{S_e}}$ （$F_e$：可改进部分占原执行时间的比例；S_e：该部分的加速比）
- **真题模型演练**：
    - **软件乘法改进**：原执行时间中软件乘法占 40%，需 200 周期；硬件改进后仅需 4 周期（S_e = 50）。
        - F_e = 0.4, S_e = 200/4 = 50。
        - S_{overall} = \frac{1}{(1-0.4) + 0.4/50} \approx \frac{1}{0.608} \approx 1.645。
    - **性能递减原则**：若乘法仅占 10%，则加速比显著下降至约 1.11，说明必须改进占比高的部分。

## 📅 Day 2：指令集架构（ISA）设计哲学与编码

### 1. CISC 与 RISC 的性能权衡

- **CISC**（复杂指令集）：目标是强化指令功能，通过减少 IC 来提升性能，但代价是 CPI 极高且电路实现复杂。
- **RISC**（精简指令集）：通过简化指令使 CPI \approx 1（理想状态），虽然 IC 略增，但由于其易于流水线化且时钟频率 T 可大幅提升，总体速度更快。
- **RISC-V 核心特征**：简单、模块化、Load/Store 结构、字对齐、大量通用寄存器、三操作数格式。

### 2. 指令编码大题专项

- **大立即数处理**：若立即数限制在 12bit（如 RISC-V），赋值 `int A = B + 1000000` 时，编译器需使用 `lui` 指令加载高 20 位，再用 `addi` 或 `ori` 补全低 12 位，分两步完成。
- **最小长度推导**：
    - 条件：63 条指令（需 \lceil \log_2 63 \rceil = 6 bits），64 个通用寄存器（需 6 bits）。
    - 指令格式 `Add R1, R2, R3`：操作码 (6) + Rd (6) + Rs1 (6) + Rs2 (6) = **24 bits**。

### 3. 四种架构汇编对比分析（X = (A * B) + (C - D)）

|   |   |   |   |
|---|---|---|---|
|架构类型|典型指令序列|指令数|访存次数 (R/W)|
|**寄存器-寄存器**|`LD R1,A; LD R2,B; MUL R3,R1,R2; ...`|多|4 读 1 写|
|**寄存器-内存**|`LD R1,A; MUL R1,B; ...`|中|4 读 1 写|
|**累加器**|`LD A; MUL B; ST X1; LD C; ...`|很多|5 读 2 写|
|**栈**|`PUSH A; PUSH B; MUL; PUSH C; ...`|极多|5 读 2 写|

## 📅 Day 3：经典 5 级流水线与冒险消减

### 1. 五段流水线硬件动作

- **IF**（取指）：根据 PC 从指令存储器读指令，PC+4。
- **ID**（译码）：读取寄存器堆，符号扩展立即数。
- **EX**（执行）：ALU 计算地址、逻辑运算或分支判定。
- **MEM**（访存）：仅 Load/Store 指令访问数据存储器。
- **WB**（写回）：将结果写入寄存器堆。

### 2. 2025 真题代码序列流水线时空图分析

代码：`I1: load r2, 8(r1)`; `I2: sub r4, r2, r1`

- **无转发**：I2 在 ID 阶段发现 r2 尚未写回，必须在 I1 完成 WB 后才能读取，产生 **2 个时钟周期** 的 Stall。
- **有转发**：I1 的 MEM 阶段结果产生后直接通过旁路定向至 I2 的 EX 阶段，仅需 **1 个周期** Stall（由于 Load 延迟无法消除）。

### 3. 流水线性能公式

- **实际吞吐率**：TP = \frac{n}{T_{total}}。
- **加速比**：S = \frac{T_{non-pipelined}}{T_{pipelined}} = \frac{k}{1 + Stall\_cycles}（k 为段数）。
- **MIPS R4000 8 级流水线**：由于采用了超流水线技术，其分支延迟增大至 3 个周期，因为分支判定在较晚的阶段（TC 或 DS）完成。

## 📅 Day 4：存储层次结构与 Cache 性能优化

### 1. Cache 映像与 AMAT 计算

- **AMAT 公式**：AMAT = Hit\_time + Miss\_rate \times Miss\_penalty。
- **2025 真题计算（分离 vs. 统一）**：
    - **16KB 分离 Cache**：
        - AMAT_{inst} = 1 + 0.64\% \times 200 = 2.28
        - AMAT_{data} = 1 + 6.47\% \times 200 = 13.94
        - 由于程序中指令访问占 75%，数据占 25%，加权 AMAT = 2.28 \times 0.75 + 13.94 \times 0.25。
    - **32KB 统一 Cache**：
        - 由于结构冲突（端口唯一），数据访存需额外 +1 周期。
        - AMAT = (1 + 1.99\% \times 200) + 0.33 \times 1（假设 33% 访存冲突）。

### 2. 包含性规则

- **包含式 (Inclusive)**：L1 中的数据必须存在于 L2 中。优点是简化了一致性协议（只需查 L2），缺点是浪费容量。
- **互斥式 (Exclusive)**：L1 与 L2 存储内容完全不重叠，容量利用率最高。

## 📅 Day 5：ILP 动态调度大题突围（20 分双表填表）

### 1. Tomasulo 算法核心填表逻辑

针对代码：`fdiv.d f6, f0, f6` (I5) 与 `fmul.d f6, f8, f2` (I6)。

- **寄存器重命名**：当 I6 发射时，它会将寄存器状态表中的 F6 指向其所在的保留站（如 `Mult2`）。这样，I5 的结果即便后写回，也只会写到它自己的目标，而不会覆盖 I6 的结果。
- **保留站字段说明**：
    - **Vj, Vk**：源操作数的值。
    - **Qj, Qk**：产生源操作数的保留站名称（若为 0 则表示值已就绪在 Vj/Vk 中）。
    - **Busy**：单元忙碌标志。

### 2. 分支预测

- **2-bit BHT**：相比 1-bit，它需要连续两次预测错误才会改变状态，极大改善了循环（Loop）结束时的抖动。

## 📅 Day 6：多发射与多线程

### 1. 多发射技术对比

- **超标量 (Superscalar)**：硬件动态检测相关，每个周期发射指令数可变。
- **VLIW**：完全依赖编译器静态打包，指令组内无相关，译码器极简，但对编译器要求极高。

### 2. 浪费分析

- **垂直浪费**：由于长延迟操作导致整个时钟周期没有任何指令流出。
- **水平浪费**：在多发射处理器中，某周期内部分发射槽位（Slot）未使用。
- **SMT（同时多线程）**：在同一周期内混合发射来自不同线程的指令，能同时消除垂直和水平浪费。

## 💡 附录：前沿学术思考

- **跨架构兼容性（Apple M3 运行 x86）**：需克服 **语义差距 (Semantic Gap)**。由于 ARM 与 x86 的强弱内存模型差异，硬件需支持额外的同步指令（如 TSX 模拟），软件层（Rosetta 2）则通过二进制翻译将 x86 指令映射为等效的 ARM 序列。
- **DSA（领域专用架构）**：在摩尔定律失效背景下，通过定制化硬件（如 TPU 处理张量）而非增加通用 CPU 频率来获取性能。
