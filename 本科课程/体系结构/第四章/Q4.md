在 Cache 设计的四个基本问题（4Q）中，**Q4 指的是“写策略（Write Policy）”**，即探讨**当 CPU 修改了 Cache 中的某块数据后，应该在什么时候、以什么方式将这些修改同步到下一级存储器（主存）中**，以解决 Cache 与主存之间的数据一致性问题。

结合课程讲义，写策略面临着独特的物理挑战与工程折中：

### 1. 为什么“写”操作非常特殊？

- **阿姆达尔定律的制约**：统计表明，程序对存储器的读操作约占访问数据 Cache 的 75%，而写操作约占 25%。虽然根据“大概率事件优先原则”我们应该大力优化读操作，但根据阿姆达尔定律（Amdahl's Law），如果写的速度太慢，依然会成为系统的性能瓶颈。
- **必须串行执行**：读 Cache 时，可以把读数据阵列和比较 Tag 并行起来；但写操作**必须先读出标识并确认命中后，才能真正对 Cache 进行写入（这是一个严格的串行操作）**，否则一旦发生误写，就会摧毁其他块的正确数据。

### 2. 写命中（Write Hit）时的两种经典策略

当 CPU 要写的数据已经在 Cache 中时，有两种更新主存的做法：

- **写直达法（Write-through）**：
    - **机制**：处理器在修改 Cache 内容的同时，**同步将数据写入内存**。
    - **优缺点**：优点是易于实现，且 Cache 和主存的数据始终保持强一致性；缺点是每次写都要访问慢速主存，严重拖慢了系统速度。为了缓解这个问题，采用写直达法的系统通常会增加一个**写缓冲器（Write Buffer）**，让 CPU 把数据扔给缓冲器后就继续执行，由缓冲器在后台慢慢写入主存。
- **写回法（Write-back）**：
    - **机制**：处理器**只更新 Cache 中的数据，绝不立刻写回内存**。硬件会为这个 Cache 块打上一个“脏位（Dirty Bit）”标签。只有当这个脏块因为容量满而被 Q3 的替换算法强制踢出 Cache 时，它才会被写回主存。
    - **优缺点**：优点是速度极快，大幅减少了访存次数和总线带宽消耗；缺点是控制逻辑非常复杂，并且带来了严重的缓存一致性问题（因为主存里的数据长期是旧的）。

### 3. 写失效（Write Miss）时的两种策略

当 CPU 想要写某个地址，却发现这个块根本不在 Cache 里时，有两种处理方式：

- **按写分配法（Write allocate）**：也称写时取（Fetch on Write）。先向主存发出请求，**把包含这个地址的整个数据块调入 Cache，然后再在 Cache 里完成写入**。
- **不按写分配法（No-write allocate）**：也称绕写法（Write around）。直接绕过 Cache，把你要修改的数据直接写进下一级主存里，**不把这个块调入 Cache**。

### ⚖️ Q4 的工程设计黄金搭档

虽然这四种方法在理论上可以任意组合，但在真实的现代计算机体系结构中，通常遵循以下固定搭配原则：

- **“写回法（Write-back）” 通常严格绑定 “按写分配法（Write allocate）”**。既然写回法期望未来的修改都在 Cache 内部以极快的速度完成，那么第一次没命中时，理应先把块搬进 Cache 再说。
- **“写直达法（Write-through）” 通常严格绑定 “不按写分配法（No-write allocate）”**。既然写直达法每次都要写透到主存，那如果没命中，直接写主存就行了，完全没有必要费时费力再把它调进 Cache 占用宝贵的空间。
