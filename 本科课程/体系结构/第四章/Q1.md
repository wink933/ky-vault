在 Cache 设计的四个基本问题（4Q）中，**Q1 指的是“映像规则（Placement）”**，即**当要把一个块从主存调入 Cache 时，它到底可以被放置在 Cache 的哪些位置**。

为了解决这个问题，计算机体系结构中主要设计了三种经典的映像方式：

### 1. 直接映像方式（Direct Mapped）

- **规则**：主存中的每一块只能存放在 Cache 中的**唯一固定位置**。
- **映射公式**：`Cache块地址 j = 主存块地址 i mod (Cache中的块数 M)`。
- **特点**：查找速度最快，硬件实现最简单，但冲突失效（Conflict Miss）的概率最高。

### 2. 全相联方式（Fully Associative）

- **规则**：主存中调入的块可以存放在 Cache 中的**任何位置**。
- **特点**：空间利用率极高，块冲突概率极小（只有 Cache 全满时才会冲突替换），但查找时需要同时比较所有块的 Tag，硬件实现极其复杂，代价很高。

### 3. 组相联映像（Set Associative）

这是直接映像和全相联的折中方案。

- **规则**：将 Cache 分为若干个“组（Set）”，每组包含 N 个块（称为 **N 路组相联**）。主存中的某一块只能被放置在**唯一的一个指定组**中，但可以放在**该组内的任意一个位置**。
- **映射逻辑**：可以总结为**“组间直接映像，组内全相联”**。
- **映射公式**：`Cache组号 K = 主存块地址 i mod (Cache的总组数 G)`。

### 💡 Q1 的工程设计权衡（Trade-off）

在实际应用中，相联度（N 的大小）的高低直接影响 Cache 的性能和成本：

- **相联度越高（N 越大）**：Cache 的空间利用率就越高，块冲突的概率就越小，从而**失效率就越低**。
- **相联度过高的代价**：实现查找和替换的机制会变得越来越复杂，硬件成本增大，且可能会**增加 Cache 的命中时间**。
- **现代计算机的选择**：综合考量速度与失效率，现代绝大多数计算机主要采用**直接映像、两路或四路组相联**。
