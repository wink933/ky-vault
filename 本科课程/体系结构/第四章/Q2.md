在 Cache 设计的四个基本问题（4Q）中，**Q2 指的是“查找方法（Identification）”**，即探讨**如何确认 CPU 所需的数据是否已经存放在 Cache 中，以及如何准确定位它**。

结合我们的课程讲义，Q2 的核心机制可以归纳为以下几个维度的硬件逻辑：

### 1. 物理地址的三段式划分

当处理器发出地址访问 Cache 时，该物理地址会被硬件严格切割为三个字段：**标记（Tag）**、**索引（Index）**和**块内偏移（Offset）**。

- **关联度对地址划分的影响**：增加 Cache 的组相联度会缩小索引（Index）字段的位宽，并相应地扩大标记（Tag）字段的位宽。
- **全相联的特例**：在**全相联映像**结构中，因为主存块可以放在 Cache 的任意位置而不需要分组定位，因此**完全没有块索引（Block Index）字段**。

### 2. 核心查找原则：并行查找（Parallel Search）

Cache 的速度对 CPU 性能至关重要，因此 Q2 的最高原则是：**所有可能的标记（Tag）必须进行并行查找**。

- **硬件实现路径**：这种并行的按内容检索通常通过相联存储器来实现，或者使用单体多字存储器并配合多个硬件比较器（Comparator）来完成。

### 3. 查找与比较的“黄金定则”

在具体执行查找验证时，硬件遵循一个极简的规则：**无论 Cache 采用的是直接映像还是组相联结构，在查找时只需比较标记（Tag）是否相等，索引（Index）以及块内偏移无需参加比较**。因为索引已经在上一步被用于物理寻址选出对应组了。

### ⚖️ Q2 的工程设计折中（Trade-off）

实现并行查找需要巨大的硬件资源支撑。讲义中明确指出：**相联度 N 越大（如 8 路或 16 路组相联），意味着需要在同一时间并行读出并比较的 Tag 越多，这会导致实现查找的硬件机制越复杂，代价也就越高**。这正是架构师在设计 Cache 时必须在“降低失效率”与“控制硬件成本及缩短命中时间”之间做出的经典权衡。
