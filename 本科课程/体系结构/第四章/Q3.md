在 Cache 设计的四个基本问题（4Q）中，**Q3 指的是“替换算法（Replacement）”**，即探讨**当 Cache（或所映射的特定组）已全部被占用，而新的主存块又需要调入时，究竟该强制腾出（替换）哪一个块**。

根据在 Q1 中学到的映像规则，如果 Cache 采用的是**直接映像**，因为每个主存块只能存放在唯一固定的位置，所以遇到冲突时别无选择，直接覆盖即可；但如果采用的是**组相联或全相联映像**，硬件就面临“多选一”的局面，必须依赖特定的替换算法来做决定。

体系结构中常考的三种经典替换算法如下：

**1. 随机法（Random）**

- **机制**：发生缺失时，硬件通过一个伪随机数生成器，从当前组中随机挑选一个 Cache 块进行替换。
- **优缺点**：最大优点是**极其简单、易于实现**；缺点是没有考虑 Cache 块的使用历史，无法反映程序的局部性，因此**失效率通常较高**。

**2. 先进先出法（FIFO, First In First Out）**

- **机制**：替换同一组中最早进入 Cache 的那个块。
- **优缺点**：优点同样是简单。缺点是它虽然利用了各块进入的先后顺序，但依然不够符合程序的局部性原理，因为“最早调入的块”很可能是那些在整个循环中都需要经常访问的核心全局变量，盲目将其替换会导致极高的失效代价。

**3. 最近最少使用法（LRU, Least Recently Used）**

- **机制**：替换在最近一段时间内，最少被 CPU 访问过的块。
- **优缺点**：优点是它**较好地利用了程序的时间局部性原理，在这三种算法中失效率最低**。缺点是硬件需要实时维护和更新同一组内所有块的使用顺序，**逻辑比较复杂，硬件实现较为困难**。

💡 **Q3 的工程设计与性能考点（Trade-off）：** 在性能分析时，讲义中的统计规律指出了一个极其重要的考点：**在 Cache 容量较小时，LRU 算法的优势非常明显，失效率显著低于随机法**。但是，**随着 Cache 容量的不断加大，随机法的失效率会逐渐降低，它与 LRU 之间的性能差距会越来越小**。

因此，在现代架构设计中，面对相联度极高的大容量底层缓存（如 L3 Cache），为了避免维护 LRU 链表带来的巨大硬件代价和延迟，架构师有时会折中采用随机法或近似 LRU（Pseudo-LRU）算法。
