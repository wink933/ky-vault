### 一、 简要回答题 (10 分)

#### 1）根据图 1、图 2 和访存信息，讨论现有的计算机系统缓存的块大小多少合适？（5 分）

根据存储层次的性能参数公式，平均访存时间 $\text{AMAT} = \text{Hit Time} + \text{Miss Rate} \times \text{Miss Penalty}$ 。

- **未命中开销 (Miss Penalty) 分析**：已知存储系统有 $80\text{ CC}$ 的固定开销，随后每 $2\text{ CC}$ 传输 $16\text{ 字节}$ 。随着块大小（Block Size）增大，传输延迟呈线性增加：
    
    - $16\text{ 字节}$ 时：$\text{Miss Penalty} = 80 + \frac{16}{16} \times 2 = 82\text{ CC}$。
        
    - $32\text{ 字节}$ 时：$\text{Miss Penalty} = 80 + \frac{32}{16} \times 2 = 84\text{ CC}$。
        
    - $64\text{ 字节}$ 时：$\text{Miss Penalty} = 80 + \frac{64}{16} \times 2 = 88\text{ CC}$。
        
    - $128\text{ 字节}$ 时：$\text{Miss Penalty} = 80 + \frac{128}{16} \times 2 = 96\text{ CC}$。
        
- **未命中率 (Miss Rate) 与局部性分析**：从图 1 的经典失效率曲线可以看出，当块大小从 $16\text{B}$ 增加到 $64\text{B}$ 时，由于空间局部性（Spatial Locality）的作用，各容量 Cache 的未命中率显著下降 ；但当块大小进一步盲目增大（如 $128\text{B}, 256\text{B}$）时，由于 Cache 行数变少导致冲突不命中率上升，且未命中开销（Miss Penalty）急剧增加，反而使 $\text{AMAT}$ 恶化 。
    
- **结论**：现有的计算机系统缓存块大小选择 **$64\text{ 字节}$**（或者是部分大容量缓存采用的 $128\text{ 字节}$）最合适，能够完美平衡空间局部性收益与总线传输开销。
    

### 二、 处理器参数问答题 (10 分)

#### 1） 解释你看到的参数（3 分）。

- **核心设计异构性**：Intel Core Ultra 9 285 采用混合大小核架构（8 个 P-core + 16 个 E-core，共 24 核 24 线程），主打高单核睿频（高达 5.6 GHz）以面向台式桌面级市场 ；AMD EPYC 9965（基于 Zen 5c 架构）采用 192 核 384 线程的纯多核高密度同构设计，主打服务器/工作站高并发吞吐市场 。
    
- **缓存与内存层次**：Intel 引入了超低延迟的 L0 级独立指令/数据缓存，支持双通道 DDR5 内存 ；AMD 拥有庞大的 384 MB 共享 L3 缓存，并支持高达 12 通道的高带宽 DDR5 内存 。
    
- **功耗设计 (TDP)**：Intel 基础 TDP 为 65 W（PL2 达 182 W） ；AMD 针对数据中心高吞吐负载设计，TDP 高达 500 W 。
    

#### 2） Intel Core Ultra 9 285 中 Cache L0-D 和 Cache L0-I 代表什么，为什么要分开两部分单独设计（2 分）？

- **代表含义**：`Cache L0-D` 代表 L0 级**数据缓存（Data Cache）**，`Cache L0-I` 代表 L0 级**指令缓存（Instruction Cache）** 。
    
- **分立设计原因（哈佛架构思想）**：
    
    - **避免结构冒险（Resource Conflict）**：在流水线中，取指阶段（IF）需要读取指令，访存阶段（MEM）需要读写数据 。若采用统一结构，两条指令可能在同一时钟周期因争用单个缓存端口而发生结构冲突导致流水线停顿 。
        
    - **提供双倍并行带宽**：允许处理器在单周期内同时完成指令读取与数据加载。
        
    - **匹配不同的访问特征**：指令具有极强的顺序读取和只读属性；数据则包含复杂的读写交互且访问更随机，分立设计可以针对其特性分别优化。
        

#### 3）二者的 L1 Cache 的容量大小分别是多少？典型的 L1 Cache 大小是如何确定的（2 分）？

- **容量大小**：Intel 的 P-core L1 Cache 为 192 KB（E-core L1 为 96 KB） ；AMD EPYC 9965 的 L1 Cache 为每核心 80 KB 。
    
- **如何确定**：
    
    - **命中时间与主频的硬限制**：L1 Cache 的访问延迟必须控制在 1~2 个极其微小的时钟周期内 。容量过大将延长查找电路的门延迟，直接拖慢整个 CPU 的最高主频 。
        
    - **虚拟地址转换（VIPT 映射）的物理限制**：为了实现虚拟索引物理标记（VIPT）的并行查表，L1 Cache 的单路容量（容量/组相联路数）通常受限于操作系统的物理页大小（一般为 4 KB），以避免页内偏移地址转换引起的别名问题。
        

#### 4）Intel Core Ultra 9 285 的 E-core 和 P-core 分别是什么，有何区别？为什么要做这样的大小核设计（3 分）？

- **概念与区别**：
    
    - **P-core (Performance Core，性能核)**：采用深流水线、复杂乱序执行和高时钟频率的大面积核心，专为单线程性能和重度单应（如游戏、前端交互）优化 。
        
    - **E-core (Efficient Core，能效核)**：采用精简、小面积、低功耗高能效的多核架构，专为多线程吞吐量及后台多任务（如系统渲染、后台服务）优化 。
        
- **设计原因**：
    
    - **最大化能效比（Performance per Watt）**：轻载或多媒体后台运行时只激活低功耗 E-core，极大程度降低核心功耗和发热。
        
    - **解决物理面积与多核并行的矛盾**：在有限的硅片面积（Die Size）内，堆叠多个精简的 E-core 能够比单纯做大核提供更强大的并发吞吐能力，同时保留少部分 P-core 保证了单线程峰值性能 。

        $$\text{AMAT}_2 = 1.2647 + \left( \frac{43.3 \text{ 次未命中}}{1360 \text{ 次总访存}} \right) \times 200 \approx 1.2647 + 6.3676 = 7.632 \text{ 时钟周期}$$
        

### 四、 简答题 (10 分)

#### 1) 包含式缓存（Inclusive Cache）和互斥式缓存（Exclusive Cache）结构谁更好（2 分）？

各有优劣，依赖不同的设计目标：

- **包含式缓存（多核更好）**：下层缓存包含上层所有内容。**优点**是一致性维护简单，多核窥探（Snoop）只需查询 LLC 即可，无需逐级向上扫描 ；**缺点**是存在空间数据冗余。
    
- **互斥式缓存（小容量更好）**：各级缓存内容完全互斥。**优点**是总有效缓存容量大（各级容量相加）；**缺点**是当缓存行在两级之间频繁置换和一致性检索时，硬件控制极其复杂。
    

#### 2) 假设有个针对X86的Win 10开发的英雄联盟游戏安装包，在苹果M3 mac pro上安装 ARM版 Win 10系统后，该英雄联盟游戏安装包能否正常执行？为什么（3 分）？

**结论：在不考虑反作弊内核驱动限制的前提下能执行，但若包含深度的内核反作弊组件则无法正常执行。**

- **技术原因**：ARM 版 Windows 10/11 内部集成有 **WoW64 动态二进制翻译（仿真）层**，能够在运行期间将 X86 架构的用户态指令转换为 ARM64 指令执行。
    
- **致命限制**：英雄联盟等竞技游戏普遍含有极高级别、运行在内核态（Ring 0）的防作弊系统（如微软仿真的边界限制）。仿真层通常无法成功翻译和执行 X86 内核级驱动，因而会导致游戏报错或直接被拒绝启动。
    

#### 3）阅读图 6 记分牌状态图回答：

##### a) 描述记分牌算法（3 分）。

记分牌算法是一种硬件动态调度技术，核心采用**集中式冒险检测**，支持**顺序发射、乱序执行、乱序完成** 。它将 ID 阶段拆分为：

1. **发射（Issue）**：译码并检测**结构冒险**和 **WAW 冒险**，若无冲突则允许发射更新状态，否则阻塞后续所有指令 。
    
2. **读操作数（Read Operands）**：动态监控并解决 **RAW 冒险**，一旦指令的所有源操作数就绪，即可读取操作数进入执行 。
    
3. **执行（Execute）与写回（Write Result）**：执行完毕后检测 **WAR 冒险**，若后续有未读取该目的寄存器的老指令存在，则暂停写回，直至假相关解除 。
    

##### b) 记分牌算法关于 WAW 的解决方案有何利弊，如何改进（2 分）？

- **利弊**：**利**在实现逻辑极其简单直接；**弊**在直接在发射阶段阻塞（Stall）整条流水线，即使两条指令之间只是重用了寄存器名（没有真数据依赖），也会导致后续所有无关指令全部停滞，严重压制了指令级并行度 。
    
- **改进**：引入寄存器重命名（Register Renaming）**技术。如 **Tomasulo 算法**，利用分布式的**保留站（Reservation Station）替代物理寄存器名，将名字相关直接转换为虚链接的动态数据流，从而允许指令不间断发射 。
    

### 五、 指令集问答题 (10 分)

#### 1）已知某 RISC 仅支持立即数为 12bit 的加法操作，现有 int A=B+1000000；问编译器要如何编译该语句（2 分）。

常数 $1000000$ 远超 12 比特有符号数的表示范围（$-2048 \sim 2047$）。编译器必须将其拆分为多条指令组合：

1. 首先使用大立即数加载指令（如 RISC-V 中的 `lui`，高位立即数加载）将高位段载入临时寄存器。
    
2. 使用低位拼接指令（如 `addi` 或 `ori`）将剩余低位并入该寄存器，在寄存器中完整构建出 $1000000$。
    
3. 最后使用寄存器-寄存器加法指令（`add`），将变量 B 所在寄存器与该临时寄存器相加。
    

#### 2）有 63 条指令，支持 64 个寄存器。三元操作数指令（Add R1, R2, R3）。问最小长度是多少，为什么（3 分）？

- **操作码（Opcode）**：63 条指令需要 $\lceil \log_2(63) \rceil = 6 \text{ bit}$。
    
- **操作数（Operands）**：64 个寄存器每个需要 $\log_2(64) = 6 \text{ bit}$。三元操作数共包含 3 个寄存器字段，需要 $3 \times 6 = 18 \text{ bit}$。
    
- **总最小长度**：$6 \text{ (Opcode)} + 18 \text{ (操作数)} = 24 \text{ bit}$。
    
- **原因**：由于每个字段必须分配足够的二进制位以便硬件无歧义地译码出 63 种操作和 3 个独立的寄存器索引，其空间之和物理上最低必须占用 24 位。
    

#### 3）编写汇编代码实现 $(A+C) \times B + (B \times C + B) / D$ (5 分)

（设结果最终存回内存地址 `T`，各架构按图 7 规范编写 ）

- **累加器架构（Accumulator）** ：
    
    代码段
    
    ```
    Load    C       ; AC = C
    Add     A       ; AC = A + C
    Mul     B       ; AC = (A + C) * B
    Store   T1      ; T1 = (A + C) * B
    Load    B       ; AC = B
    Mul     C       ; AC = B * C
    Add     B       ; AC = B * C + B
    Div     D       ; AC = (B * C + B) / D
    Add     T1      ; AC = (A + C) * B + (B * C + B) / D

    ```

    代码段
    
    ```
    Push    A
    Push    C
    Add             ; 栈顶 = A + C
    Push    B
    Mul             ; 栈顶 = (A + C) * B
    Push    B
    Push    C
    Mul             ; 栈顶 = B * C
    Push    B
    Add             ; 栈顶 = B * C + B
    Push    D
    Div             ; 栈顶 = (B * C + B) / D
    Add             ; 两项结果相加

    Load    R2, B   ; R2 = B

    Add     R2, B   ; R2 = B * C + B
    Div     R2, D   ; R2 = (B * C + B) / D
    Add     R1, R2  ; R1 = R1 + R2
    Store   R1, T   ; 写回 T
    ```
    
- **寄存器-寄存器架构（Load-Store）** ：
    
    代码段
    
    ```
    Load    R1, A   ; R1 = A
    Load    R2, B   ; R2 = B
    Load    R3, C   ; R3 = C
    Load    R4, D   ; R4 = D
    Add     R5, R1, R3  ; R5 = A + C
    Mul     R5, R5, R2  ; R5 = (A + C) * B
    Mul     R6, R2, R3  ; R6 = B * C
    Add     R6, R6, R2  ; R6 = B * C + B
    Div     R6, R6, R4  ; R6 = (B * C + B) / D
    Add     R7, R5, R6  ; R7 = 两部分之和
    Store   R7, T   ; 写回 T
    ```

### 📝 第一题：数据冒险分析与流水线时空图（2025年A卷 第7题，10分）

**题目再现**： 给定指令序列： `I1: load $r2, 8($r1)` `I2: sub $r4, $r2, $r1` `I3: and $r5, $r1, $r2` `I4: sub $r6, $r2, $r4` `I5: add $r7, $r2, $r3`

#### 1) 找出代码中所有的数据冒险（RAW）

在经典的 5 级流水线中，真实数据依赖（RAW，写后读）会导致后一条指令必须等待前一条指令写入结果。根据指令中寄存器的读写关系，所有的 RAW 冒险如下：

1. **I2 指令和 I1 指令在 `$r2` 上存在 RAW**（I1 写 `$r2`，I2 读 `$r2`）。
2. **I3 指令和 I1 指令在 `$r2` 上存在 RAW**（I1 写 `$r2`，I3 读 `$r2`）。
3. **I4 指令和 I1 指令在 `$r2` 上存在 RAW**（I1 写 `$r2`，I4 读 `$r2`）。
4. **I4 指令和 I2 指令在 `$r4` 上存在 RAW**（I2 写 `$r4`，I4 读 `$r4`）。
5. **I5 指令和 I1 指令在 `$r2` 上存在 RAW**（I1 写 `$r2`，I5 读 `$r2`）。

#### 2) 画出没有转发（No Forwarding）的流水线时空图

在没有硬件旁路转发的情况下，必须依靠硬件互锁（Interlock）让后续指令在 ID（译码）阶段停顿，**直到前一条指令在 WB 阶段的前半周期将数据写回寄存器，后续指令才能在 ID 阶段的后半周期读出**。

#### 3) 画出有转发（Forwarding）的流水线时空图

### 📝 第二题：控制冒险与分支预测填图题（2025年A卷 第6题第2小问，5分）

**题目条件分析**： 给定 7 条连续的汇编指令序列，包含条件分支 `beq $1, $2, X`。题目设定了极其关键的三条规则：

1. 条件跳转指令在 **EX 阶段**才知道最终的跳转位置。
2. 硬件分支预测机制**预测跳转不会选中（Untaken）**。
3. 实际执行时，**`$1` 的值不等于 `$2` 的值**。（即条件不成立，实际确实**没有发生跳转**）。

**破题核心**：因为预测是不跳转（Untaken），且实际由于 `$1 != $2` 确实没有跳转，所以**分支预测是完全正确的！流水线不需要发生冲刷（Flush/Kill），程序将完美地顺序执行下去**。我们只需要找出顺序执行路径中的数据冒险即可。

- `lw $10, 0($11)` 与 `sub $14, $10, $10`：存在针对 `$10` 的 **Load-Use 冒险**，必须产生 **1 周期停顿**。
- `X: add $4, $1, $2` 与 `lw $1, 0($4)`：存在针对 `$4` 的 RAW，有旁路转发，**0 停顿**。
- `lw $1, 0($4)` 与 `sub $1, $1, $1`：存在针对 `$1` 的 **Load-Use 冒险**，必须产生 **1 周期停顿**。
- `sub $1, $1, $1` 与 `add $1, $1, $1`：存在针对 `$1` 的 RAW，有旁路转发，**0 停顿**。

### 📝 第三题：概念辨析与判断题（2024年真题回忆版）

根据 2024 年考试中针对流水线与冒险机制的判断题，这里为你作极其清晰的学术辨析：

**1）“Tomasulo 不需要考虑真数据依赖（RAW）”**

- **判断**：**错误（False）**。
- **解释**：Tomasulo 算法虽然通过强大的**保留站（Reservation Stations）机制进行了寄存器重命名**，从而彻底消除了 WAR（读后写）和 WAW（写后写）这两种假数据依赖（名称依赖）；但对于 **RAW（写后读）这种真实数据依赖**，指令依然无法立刻执行。它们必须在保留站中保持 Busy 状态并持续监听，直到前序指令计算完毕并通过 **CDB（公共数据总线）广播**出结果后，才能获取源操作数并进入执行段（EX）。

**2）“分支预测可以完美解决控制冒险”**

- **判断**：**错误（False）**。
- **解释**：分支预测（如 BHT、BTB 技术）只能通过“提前猜测”来尽量隐藏控制冒险带来的流水线断流。但它绝对不是“完美”的。一旦**预测失败（Misprediction）**，处理器依然必须付出惨痛的代价：清空（Flush）流水线中沿着错误预测路径已经取入的所有指令，并回滚状态从正确的地址重新取指。这种预测失败带来的**分支惩罚（Branch Penalty）**在极深的现代流水线中依然是极其巨大的性能损耗。
