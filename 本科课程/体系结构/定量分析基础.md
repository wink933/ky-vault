计算机系统的定量分析基础主要围绕**性能的度量、性能的评估公式以及优化的核心定律**展开，这是整个体系结构课程的基石。

**一、 性能的两大核心维度** 在定量分析中，“性能”通常包含两个容易产生冲突的含义：

- **响应时间（Response Time / Execution Time）**：指完成单个任务所经历的全部时间，也被称为延迟（Latency）。
- **吞吐率（Throughput / Bandwidth）**：指单位时间内完成的任务总数。 提升硬件的并行性（如采用多处理器）通常可以提高吞吐率，而缩短单个任务的执行时间则可以同时提高响应时间和吞吐率。

**二、 CPU 性能通用公式** CPU 运行时间是度量计算机系统性能最实际、最可靠的方式。其最常用的综合公式为： **CPU 执行时间 = 指令总数 (IC) × 每条指令平均时钟周期数 (CPI) × 时钟周期时间**。

其中，不同类型的指令（如算术逻辑 ALU 指令、访存 Load/Store 指令、分支 Branch 指令）往往需要不同的执行周期。因此，程序的整体 **CPI** 可以通过各类指令的周期数 ($CPI_i$) 与该指令在程序中出现的频率 ($Freq_i$) 的乘积之和来计算：$CPI = \sum (CPI_i \times Freq_i)$。

**三、 影响 CPU 性能三大分量的五大层级因素** 计算机系统的各个设计层级会对上述公式中的三个分量（IC、CPI、时钟周期）产生直接或间接的影响：

1. **程序/算法（Program）**：直接决定不同算法执行的**指令总数**，其数据的局部性特征会间接影响缓存命中率，进而影响 **CPI**。
2. **编译器（Compiler）**：通过优化（如循环展开、内联）直接减少**指令总数**；通过指令调度避免流水线停顿，直接降低 **CPI**。
3. **指令集架构（ISA）**：直接影响**指令总数**（如 CISC 指令少，RISC 指令多）和 **CPI**（复杂指令 CPI 高）。指令集的复杂性还会间接影响**时钟频率**的提升上限。
4. **微架构/组织（Organization）**：通过乱序执行、分支预测等硬件技术直接决定 **CPI**；其流水线深度的设计会间接影响**时钟频率**。
5. **工艺技术（Technology）**：直接决定晶体管的物理尺寸和电压，从而直接决定处理器的**时钟频率**。

**四、 定量设计的核心：Amdahl 定律（加速比）** Amdahl 定律用于度量对系统某一部件进行改进后，整个系统能获得的加速比。 假设可改进部分在原先计算时间中所占的比例为 **$F$**，该特定部件的性能提升倍数（加速比）为 **$S$**，则系统的整体加速比公式为： **整体加速比 = 1 / ((1 - F) + F / S)**。

这一公式揭示了**性能提高的递减原则**：如果只针对整个任务的一小部分进行优化，那么无论这部分优化得有多极致（即 $S \to \infty$），系统整体的加速比上限都不会超过 **$1 / (1 - F)$**。因此，系统设计的核心影像是 **“加速大概率事件”（Make the Common Case Fast）**。

**五、 性能综合评价指标与 Benchmarks**

- **MIPS 和 MFLOPS 的局限性**：早期的 MIPS（每秒百万条指令）和 MFLOPS（每秒百万次浮点运算）由于严重依赖具体的指令集或程序操作比例，无法准确用于比较不同架构的机器，有时甚至会出现 MIPS 高但执行时间反而慢的矛盾。
- **SPEC 测试基准**：为了真实反映性能，工业界采用标准测试程序集（如 SPECint, SPECfp）进行评测。
- **几何平均（Geometric Mean）**：在对一组 Benchmark 应用程序的规格化执行时间（SPEC Ratio，即参考机器时间除以测试机器时间）进行综合评价时，必须采用**几何平均**而不是算术平均。几何平均的重要数学特性是：它与参考机器的选择完全无关（即两台机器几何平均的比率，等于这两台机器单一性能比率的几何平均）。
